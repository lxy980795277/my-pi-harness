# Web Renderer

浏览器与 Electron 共用的 React 工作台。页面负责布局和状态呈现，通过共享协议访问本机 daemon；不访问 Node、模型凭据、数据库或 Pi 实例。基础 UI 在 `src/components/ui/` 中按 shadcn 的组合方式维护，主题使用 Tailwind CSS 语义 token。

Web 源码与测试面使用 Bundler 解析，模块导入无后缀，样式和本地静态资产保留实际扩展。手写组件使用 `FC<Props>`、具名导出和独立的 `index.tsx` 目录；Hook 与状态规则见 [前端规范](../../docs/05_CONSTRAINTS/frontend.md)。HTTP/SSE 统一客户端位于 `src/services/`，领域 DTO 在 Feature Service 中校验；Query 拥有服务器快照，Zustand 只保存导航、会话选择和未提交草稿。

M1 提供本机配对、Provider/模型配置、专用凭据写入、连接测试、OAuth 交互；进入工作台要求有效的 GitHub 应用登录态，与模型认证分别管理。会话工作台包含保存的历史、流式文字/推理内容、停止、后续输入/引导、持久队列编辑删除与显式恢复、编辑重发和JSONL日志下载。全宽header左侧显示标题、右侧下载当前会话已提交日志，模型和推理选项由输入框拥有。运行状态页保留健康检查、服务元数据、`runtime.ready`、浅深主题和手动重连。

## 工作区与对话

M5任务界面提供独立任务看板、会话header固定任务入口和用户主动打开的任务详情。子转录按需分页读取，不逐条插入主聊天；待回答、计划审核和工具批准保留原任务来源。Query拥有任务事实，Zustand只保存选择与筛选；工作台共用一个摘要SSE，详情关闭不停止后台执行。角色、模型、推理强度和预算配置位于设置的子Agent页，完整协议见[任务API](../../docs/03_API/agents.md)，实际验收状态见[M5 Spec](../../docs/04_FEATURES/202610281702_feature_m5-subagents-board/spec.md)。

时间线按服务端消息顺序组合，将工具插在其afterMessageId指向的assistant后；同一消息内保留请求事件顺序，不用毫秒时间或工具ID重排。

工具默认以图标、中文名称和单行摘要显示，hover/键盘焦点将同槽图标切为展开箭头；展开后才显示轻量参数/结果面板，待审批内容与决策始终可见。每次用户输入的工具前后正文共享末尾操作栏，复制按序包含该次回答全部助手原文，不混入思考或工具结果；同一Run的不同输入分别收尾。回答底部按用户输入汇总真实模型用量、总耗时和时间，计量与缺失语义见[阅读指南](../../docs/07_USER_GUIDE/model-session.md#阅读与消息操作)。正文与输入共用896px内容列，输入正文最小48px；正文、工具详情与统计行变化参与虚拟列表动态测高。

请求失败原因在对应回答处以纯文本显示，保留已有部分正文，后续回答和刷新不改变其归属；没有助手消息时仍提供该次请求的错误位置。子任务转录沿用相同展示。运行错误不重复占据对话顶部横条，连接、读取和下载错误仍由各自操作入口说明；安全错误文案由[会话协议](../../docs/03_API/model-session.md#事件快照与断线)约定。

主页面以居中输入框开始对话，首次发送才创建会话。输入栏统一按上下文、工作区、执行批准方式、模型和发送排列；上下文菜单提供文本、图片、PDF及Office/开放文档上传，MCP入口选择已发现的工具，Skill入口选择本次使用的冻结指令与资源，设置可创建、安装和管理Skills及插件，见[Skills指南](../../docs/07_USER_GUIDE/Skills与插件.md)；上传字节仅在专用操作内保留，Store只保存草稿元数据。模型默认继承全局设置，本次选择只影响当前对话。输入栏不再提供执行/Plan模式；计划内容、审核和任务仍由工作状态拥有。推理强度位于统一模型菜单顶部，随当前模型能力提供选项。已有对话继续使用相同输入栏，运行中提交默认排队，保留停止与队列管理；引导仍由宿主API支持。

新对话与已有对话共用键盘处理：Enter发送，Shift+Enter换行，Ctrl/Cmd+Enter仍可发送；IME候选确认不提交。快捷键触发同一发送按钮，保留其禁用限制。

全部会话位于最左侧工作区树，每个目录下显示对话标题和创建时间；旧会话以及不可用目录的历史仍在“未分配工作区”可读。工作区可登记、编辑名称/图标和移除，已有会话的目录固定。Electron通过有限桥点击选择或拖入目录，路径只读；浏览器继续使用和编辑已有工作区，新增目录后续补齐。目录有效性和允许范围由daemon判断；没有工作区不会自动获得当前目录访问权限。移除登记不删除磁盘文件，有保留会话时由服务拒绝。

工作区行仅展开/收起，不改变当前会话、页面或新对话目标；右侧悬浮更多与加号，主按钮背景占满整行。更多弹层提供重命名、删除，加号明确返回新对话并预选该工作区，发送前不创建空Session。未分配工作区不提供编辑或删除登记。目录、会话和行内操作的hover即时响应，不使用过渡动画；操作在键盘聚焦或弹层打开时保持可见。

工作区图标使用protocol的18个固定ID，统一映射到共享Lucide组件，侧栏与composer选项共用；默认folder保留展开状态及hover箭头。添加弹窗使用名称组合输入、shadcn Popover图标面板和目录选择区；组合边框只响应名称输入聚焦，图标按钮保留独立的键盘焦点提示。选择/拖放、取消及晚到响应由独立Hook持有。

首次发送先完成会话创建，再以固定 requestId 提交消息，成功后才切换选中会话。未确认输入的文本、发送意图与请求 ID 保留在非持久化 Store，页面或会话切换不会丢失；结果未知时锁住该输入，重试复用原请求，不因收到运行事件而变成新的排队输入。首次创建也保留独立 generation 与会话关联，只有明确点击“新对话”才开启另一轮；创建结果未知时刷新左侧历史并要求用户检查，不能自动重试创建。工具调用与消息在同一时间线按服务端消息和工具锚点顺序呈现，显示参数、结果和文件差异；待批准调用提供仅针对本次操作的允许和拒绝，状态以提交后的快照为准。完整能力和执行限制见 [M2 Spec](../../docs/04_FEATURES/202610150930_feature_workspace-execution/spec.md)。

## 本地 MCP

设置的MCP分区以远程添加为主入口，表单与JSON两个Tab共享配置，连接方式仅Streamable HTTP/SSE，支持Header编辑及真实握手测试；MCP ID为配置别名，内部身份使用稳定UUID。本地stdio配置和批量交换位于“高级配置”，保留独立秘密表单、启动授权、发现/诊断及停用撤销。配置和缓存目录由Query拥有，打开设置或选择器只执行只读请求；启动授权预览不执行程序，发现与测试必须明确点击。秘密在局部Hook中提交前清空，不进入Query、mutation variables或Zustand。具体字段与宿主执行范围见[M4.1设计](../../docs/04_FEATURES/202610201932_feature_m4-capabilities/local-mcp-contracts.md)。

输入选择按新对话代际或sessionId保存在composer，提交attempt冻结Server revision和定义指纹；首次发送、结果未确认重试、队列编辑与历史重发贯通同一公开选择协议。运行中的集合从Run快照读取并锁定，目录或工作区变化保留失效项，要求用户明确移除重选。工具详情显示冻结来源和派发事实；unknown是已结束的警示状态，停止spinner并提示操作可能已生效，不提供工具自动重试。

## 执行权限

输入框右下角的发送和停止共用固定位置：空闲时显示发送，运行中显示停止，结束后恢复发送；停止请求中禁止重复点击。Enter沿用提交行为，运行中按Enter可排队后续输入。

输入栏权限菜单仅提供“请求批准”“帮我批准”“完全访问权限”，新对话默认选择“完全访问权限”，客户端重置后恢复该默认值。每项具有独立图标、说明和选中标记；完整访问使用警示色。触发器随当前模式更新，旧read-only会话仍准确显示“只读”，打开菜单不会改变其权限，也不在新选择中继续提供只读选项。会话运行时不可切换策略，服务在Run接受时冻结实际权限。

工具卡区分AI复核中与等待人工批准；reviewing不显示人工操作按钮，服务进入awaiting_approval后才允许作出本次决定。已记录的公开审批来源、决定和理由可在历史工具卡中查看，私有复核输入不进入Renderer。AI复核复用会话配置但使用独立请求；完整访问下命令不受OS沙箱限制，工作区文件工具、Plan与取消策略继续由宿主执行。

## 上下文与会话工作状态

输入栏的加号支持每条消息最多8个文本、图片、PDF或支持的Office/开放文档，文件内容由受授权的daemon冻结与提取；文件引用保留宿主API及历史预览，界面不再提供添加入口；新会话、结果未知的重试、排队输入及历史分支保留attachmentIds。历史与草稿共用按需预览，base64只在上传操作与打开的内容Query内存在，关闭预览后不保留内容缓存；退出授权清空草稿。编辑消息和队列只修改正文，宿主保留原附件。消息可仅含附件，首次发送以首个文件名生成标题；粘贴的图片与文件选择共用上传、取消和重复触发所有者，普通文本保持原生粘贴。

输入框下方常驻“上下文占比 | 总对话次数”，次数按当前分支已接受的用户消息统计，工具步骤和未消费队列不计；未知占比显示“—”。点击上下文文字打开统一Dialog：上下文页显示最近请求冻结的AGENTS、输入预算、分类估算及可用的供应商输入计量；分类仍为估算。工作区当前根规则作为显式预览，与已冻结运行规则分别展示。自动或手动压缩产生上下文检查点，按结构化语义查看、比较和选择版本；选择旧版本明确确认有效历史尾部的变化。

待回答提问和计划审核卡片位于对话滚动区域，按内容自然撑高；消息历史继续虚拟化，待答表单保持挂载，分页选择和输入不会因上下滚动丢失。输入框与底部统计保持固定，内容变化参与整段对话的贴底和上滑阅读。

计划审核卡直接显示在会话中，批准后原Run继续执行，修改意见交回同一Run重新规划；正常工具审批继续有效。计划页展示步骤进度并维护Todos，任务支持受阻、取消、关联阶段和执行依据，人工完成会记录确认说明。多题问答采用分页，稳定题目ID和选项ID保存单选、多选及允许的自由输入，所有题目有效后一次提交，记录保留历史。

会话快照页比较当前状态或两个手动快照的消息前缀、规则、摘要、计划与任务，恢复新增分支；其操作独立于上下文检查点。重置任务仅清理Plan/Todos，重新开始上下文保留Plan/Todos并重设有效上下文起点。上述修改要求运行停止并确认，保留历史，不回滚磁盘文件、Shell或外部请求。

工作状态由分支隔离的Query保存，服务返回和SSE失效通知共用该缓存，活跃Run有界轮询恢复待答状态，读取明确携带预期branchId并核对返回分支；工作命令同时携带expectedBranchId与观察到的revision，其他客户端切换分支后旧页面不能写入新分支。旧revision响应不能覆盖较新的工作状态。计划审核和任务编辑携带观察到的revision，冲突由服务明确拒绝；组件和Zustand不复制工作事实。

## 模型设置

侧栏底部用户信息卡片点击后向上打开菜单，选择设置后显示 Dialog，退出登录需二次确认。模型内容按需加载，加载状态留在弹窗内；滚动区右侧和上下保留外框间距。页面导航不再包含设置项，通用设置复用工作台同一主题状态，关闭后恢复入口焦点并保留会话和输入草稿。模型页显示 六个固定内置 Provider 与自定义服务；内置只支持启停、认证和只读模型目录。自定义配置包含名称、三种 Pi 协议、Base URL 与 API Key 要求，可先保存空模型列表，再在独立模型 Dialog 添加 ID、上下文、输出限制与推理能力；编辑器固定草稿开始时的 Provider revision，不能用中途刷新后的 revision 覆盖他人修改；只有自身成功保存的响应推进重试基准。保存整个模型草稿时携带该 revision，未编辑的 headers/compat 保留。每个模型有独立连接测试结果。

默认模型和思考等级保存到本机 profile。新会话直接采用有效默认值，已存在会话继续保留原 Provider/model/thinking，旧账户通过精确 ID 兼容读取。默认失效时要求重新选择，不自动换用其他服务。配置保存、认证完成与连接成功分别展示；关闭 API Key 要求不会删除已存凭据，启用时仍可继续使用。

API Key 表单只显示未保存的输入；已有凭据只显示脱敏状态，需明确确认移除后重新认证。Provider OAuth 由其配置 Dialog 拥有，支持浏览器/桌面授权页、设备码、普通/秘密/手动码/select challenge；普通 text challenge 允许明确提交空值。成功刷新公开配置并关闭，取消或关闭终止所属流程。应用身份由独立登录页与用户菜单管理，不使用 Provider OAuth 面板，操作见[登录指南](../../docs/07_USER_GUIDE/application-login.md)。

## 数据与生命周期

浏览器以同源 HttpOnly cookie 授权，写请求使用当前授权的 CSRF token；配对码、API Key、OAuth prompt 回复只留在专用表单和提交请求中，不进入 Store、Query、LocalStorage 或 URL。收到 HTTP 401 时立即收回私有页面访问并检查授权；显式退出先卸载私有订阅，再清除请求缓存和草稿。

`features/sessions/queries/projection.ts` 是 HTTP、命令响应和 SSE 的共用合并入口。它按单会话`(snapshotSeq,liveRevision)`保留较新的公开快照，较旧refetch和重复更新不能覆盖实时正文或分支；SSE连接先建立含当前内存片段的权威快照，patch同时校验持久和实时基线，文本追加只传变化；分支变化或增量超界重新建立快照。具体序号及重连规则由[会话协议](../../docs/03_API/model-session.md#事件快照与断线)拥有。页面按32ms批次呈现，缺口重连校准。切换会话时关闭订阅并取消视图持有的请求，断线通过EventSource重连后的完整基线恢复，断线本身不会停止后台运行。

时间线使用TanStack Virtual，按稳定业务key呈现当前视区及有限overscan内的消息、工具和等待行，使用库默认动态测高，虚拟库管理高度与位置。跟随开启时按scrollHeight贴底，条目提交及内容/视口ResizeObserver触发同步；上滑暂停，回到底部或点击回到最新恢复。消息组件保留memo，Markdown继续复用Streamdown稳定内容块；SSE增量合批不受列表布局方式影响。历史首尾通过滚动访问；虚拟化限制挂载DOM，完整公开快照仍由Query持有，历史分页按实际需要后续评估。

用户消息保持纯文本，助手与思考正文通过Streamdown呈现Markdown，官方CJK插件处理中文引号/标点相邻的强调及裸链接边界。固定排版长度使用整数px，正文14/28px、代码正文与表格12/24px；公开components覆盖保留安全链接、图片引用和自定义代码/表格。Tailwind显式扫描Streamdown构建产物中的utility，根space-y-0将块间距交给本地CSS，松散列表中的段落保持block。rehype默认插件仅移除raw，保留sanitize/harden及skipHtml；代码高亮使用有界Shiki token与语义样式，复制保留原文。附件仍使用受保护预览，桌面外链由独立受限桥打开，不复用认证流程。滚动、排版与安全职责见[系统架构设计](../../docs/09_TECHNICAL/系统架构设计.md#54-原文事实与markdown展示)。

纯投影竞态、默认选择、授权链接与 challenge 语义测试在 `test/`；浏览器与桌面的真实跨进程验收由根目录 M1 测试和 [M1 Spec](../../docs/04_FEATURES/202610131100_feature_model-session/spec.md) 记录，真实供应商认证与受控测试服务分别标识。

## 开发

从仓库根目录启动 daemon 和 Web；具体入口见 [运行指南](../../docs/07_USER_GUIDE/overview.md)。单独启动界面：

```sh
pnpm --filter @my-pi-harness/web dev
```

Vite 固定监听 `127.0.0.1:5174`。页面始终请求同源 `/api`；开发代理默认转发到 `http://127.0.0.1:4311`，可通过 `DAEMON_ORIGIN` 调整代理目标。健康响应与 SSE 内容在进入组件前按 `@my-pi-harness/protocol` 校验。

首次进入共用[应用初始化](../../docs/04_FEATURES/202610221610_feature_application-initialization/spec.md)：同一个空间光环加载组件覆盖登录校验、服务协议检查及工作区/会话列表/Provider配置/默认设置的并行读取，齐备后一次挂载工作台。必要查询共享15秒新鲜度，业务写入仍显式刷新；合法空数据不阻塞，后台刷新保留已有页面与草稿，首次失败可重试。设置目录、MCP和Skills按需加载，不阻塞启动。

健康缓存按协议版本隔离；授权失效或注销时保留诊断内容但取消旧检查并标为失效，下次授权需重新确认服务协议。失败后的重连不使用旧成功结果放行。不兼容时重启整套开发服务并重新连接，单独热更新页面不能替换已经运行的daemon。会话同步与等待状态见[系统架构](../../docs/09_TECHNICAL/系统架构设计.md#五前端状态与sse同步)。

## 构建与发布

```sh
pnpm --filter @my-pi-harness/web typecheck
pnpm --filter @my-pi-harness/web lint
pnpm --filter @my-pi-harness/web build
```

构建输出为 `dist/` 静态文件。发布版由 daemon 托管这些文件与 `/api`，Electron 加载 daemon 的实际监听地址；浏览器也访问同一服务。Vite 是开发工具，不是发布服务。桌面资源装配由 `apps/desktop` 负责。

浏览器源码和 Vite 配置分别使用 `tsconfig.json` 与 `tsconfig.node.json`；浏览器程序没有 Node ambient 类型。源码检查与 Vite 打包通过路径映射读取 protocol 源码，不依赖旧 `dist`；测试使用独立 `tsconfig.test.json`，不会通过 NodeNext 编译面追入 Renderer。

TSX 仅布局和绑定同步具名事件。状态转换、选项构建、请求与 Query 编排由 `.ts` Hook/函数拥有；不用三目、void 运算符和 Promise 链。`hooks/use-async-event.ts` 是唯一同步异步桥，处理异常、重复触发、取消与卸载；秘密不进入 mutation variables。业务使用 shadcn 控件，基础层才接触原生交互标签与 Radix。

生产 HTML 的 CSP nonce 由 daemon 每次响应生成，开发使用 Vite 的 nonce。入口在渲染前初始化 `get-nonce`，Radix 的 Select/ScrollArea 与弹窗滚动锁共享该值；缺少 nonce 明确失败，不放宽 `style-src`。
