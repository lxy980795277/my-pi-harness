# 禁止事项

本页列出跨模块的交付红线。对应细则由其他约束拥有，不能凭此页代替阅读变更职责的规范。

## 流程与证据

| 禁止行为                                   | 应采用的做法                                     |
| ------------------------------------------ | ------------------------------------------------ |
| 无Spec直接展开新功能，或把未确认范围当需求 | 更新Spec、UseCase、Tasks；实际范围变化先对齐     |
| 对已确认且授权范围反复索要许可             | 沿七步流程连续实施，只对阻塞歧义和新授权事项对齐 |
| 提前创建verify通过、未运行宣称检查成功     | 完成实际验证后记录命令、环境、结果和缺口         |
| 未授权commit/push/分支改写，或覆盖用户改动 | 按实际指令与八步提交流程执行                     |
| 绕过失败hook、测试或安全审批               | 修复根因并提供新证据                             |
| 把参考仓库当运行或源码依赖                 | 独立实现，沿用确认范式与公开依赖                 |

用户当前指令优先，源项目流程不额外产生本仓库审批要求。检查点用于对齐结论，不能成为重复停工或自动提交的理由。

## 代码与类型

- 禁止用any、双重断言、ts-ignore或非空断言替代不确定输入的解析；例外必须局部解释，不能全局关闭规则。
- 禁止在静态类型已保证的服务字段上堆无意义typeof、可选链和空值替换；真正外部输入仍需运行时校验。
- 禁止空catch、统一假成功、吞错返回空集合、结果未知自动重试和无人处理的后台Promise。
- 禁止跨workspace相对导入私有源码、复制公开DTO/schema、或用指向旧dist的alias掩盖源码检查。
- 禁止保留注释掉的实现、backup/unused/deprecated业务副本及无真实职责空包；有明确发布兼容要求的内容单独说明期限与所有者。
- 业务源文件超过500行评估职责拆分，超过1000行先拆分再交付；组件超过200行检查职责，不机械切片。1000行上限由source-conventions检查，200/500行的职责判断由review承担；生成源码只按脚本明确登记的路径豁免，不能整片业务目录标为生成代码。lockfile和vendor不按业务文件阈值拆分。

## 本机安全与数据

- 禁止Renderer访问Node、凭据、数据库或daemon实现；禁止通用IPC、任意启动程序、路径和动态代码桥。
- 禁止关闭contextIsolation、sandbox或webSecurity解决功能问题；禁止任意导航、默认允许权限和未知URL的shell.openExternal。
- 禁止将回环监听或CORS当认证；开放本地副作用前完成来源、授权、策略和真实拒绝验证。
- 禁止sandbox失败静默退回宿主、越过Workspace策略，或遗留取消/超时后的进程树。
- 禁止秘密硬编码、真实.env进入仓库、凭据输出日志/DTO/URL/trace及读取任务无关秘密。
- 禁止编辑已发布迁移、静默清空损坏数据库、事实与索引双权威、SQLite事件和JSONL实时双写。
- 禁止未经授权删除持久用户数据或对外API；已有任务明确授权的变更按Spec完成迁移与兼容，不额外制造重复审批。

## 依赖与发布

不依赖用户机器预装运行时启动已打包应用，不把开发覆盖项带入生产。发布资源、版本、签名和退出证据按对应规范核验；脚本存在不代表已打包、已公证或Windows已验证。

不为单机应用复制Next App Router、Nest装饰器、MySQL手工DDL、Redis多实例政策或历史业务规范。通用规则的采用与调整见 [范式映射](../09_TECHNICAL/development-paradigm.md)。
