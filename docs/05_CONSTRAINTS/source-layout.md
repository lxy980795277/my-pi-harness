# 源码声明组织

适用于apps和packages中手写的TypeScript/TSX源码。文件按以下顺序组织，缺少的区域直接省略，不为分区新增空文件或注释标题：

1. 文件说明和import，保留现有模块导入/样式导入规则。
2. 模块级interface、type等纯类型定义，集中连续声明。
3. 模块级常量、schema和静态数据初始化，按运行时依赖顺序集中声明；必要的模块状态初始化紧随其后。
4. 函数、类、Hook、组件及其他实现，最后执行启动或注册操作。

这是本项目的统一可读性约定。Google TypeScript指南规定[imports位于实现之前](https://google.github.io/styleguide/tsguide.html#source-file-structure)，没有规定本项目上述更细的类型/常量次序；不能将本约定称为业界唯一顺序。

## 类型区

- 类型定义放import之后、首个值声明之前，不穿插在常量、函数或类之间；泛型参数、函数签名内的类型表达式仍随所属声明。
- 由schema推导的类型也集中在类型区，继续使用Static、ReturnType或typeof推导，不复制字段来避免前向引用。[typeof类型查询](https://www.typescriptlang.org/docs/handbook/2/typeof-types.html)不执行被引用的值；运行时schema之间仍遵守初始化顺序。
- declare global和模块扩充保持原有声明作用域，不把其中的interface移成模块私有类型。依赖函数局部泛型的类型留在所属作用域，不能通过提升改变作用域或泛型绑定。
- 具名type-only导出和公开re-export是模块出口，不为分区机械拆开聚合API；业务模块不借重导出绕过类型定义次序。

## 常量与实现区

- 常量、schema、配置表、固定正则和模块数据初始化集中在类型区之后；数据内部的函数属性或回调不改变整个数据声明的归属。
- const只表示绑定不可重新赋值。const声明的箭头函数、函数表达式、组件和Hook仍属于实现区；函数、Hook、闭包内的局部const不是模块常量，不提升作用域。
- let/var模块状态与静态数据初始化分别组织，不把可变状态伪装成不可变常量；同一组常量/schema不与纯类型定义交错。
- 不把enum当作纯类型提升；它可能有运行时初始化。类的static readonly仍归所属类，不为了文件布局把它改成全局状态。
- 移动声明必须保留初始化依赖和可观察副作用。常量依赖前面的箭头辅助函数时，应改成清晰的独立构造器导入或其他安全组织；不能将它直接移到尚未初始化的绑定之前。
- 启动检查、CSP nonce初始化、OAuth票据擦除、渲染和进程启动保留明确执行顺序。需要整理时将完整启动序列放入具名入口，不将其中局部变量分拆提升。
- 不改Worker脚本字符串、SQL字符串、生成文件或第三方资产中的声明次序；它们按原拥有者的格式和生成流程管理。

## 检查

源码gate通过TypeScript AST检查apps/packages的模块级类型和值声明顺序，忽略函数体、类内部及声明扩充内部作用域；常量不是按名称是否大写判断。gate只识别直接函数/类初始化器，不推断memo、lazy等工厂返回值，也不证明启动或注册副作用的执行顺序；这两项由代码审查核对。类型、schema及运行时依赖另由类型检查、行为测试和必要的干净构建验证，不能靠文本排序代替。
