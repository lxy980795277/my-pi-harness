# 代码治理

适用于apps、packages、工具脚本及测试。按实际改动或约2至4周开展一次扫描；先确认职责和消费者，再修复。可读性优先于字符数，不用语法出现次数代替问题判断。

## 命名与类型

- types目录按领域命名，如workspace.ts、session.ts、work.ts；不加冗余-view后缀。类型名称仍可用View表达公开投影等真实区别，其他目录有明确视图职责时可以保留view。
- 业务状态、动作等枚举值抽为有语义的具名TypeScript联合类型，放实际所有者的types模块；Hook/useState、参数和复杂属性引用它，不重复长字面量。已有protocol/schema定义时派生复用，不复制第二份枚举或为此强制引入运行时enum。
- 不为单个简单字段机械新建类型文件；抽取应减少重复或让调用点含义清楚，不能变成无职责转发层。

## 弃用与可读性

- 根据当前安装依赖的类型声明/文档识别deprecated，使用适合当前事件或调用的替代API；不能仅改名、换成同样弃用的别名、断言或禁用规则。类型感知ESLint拒绝弃用使用，升级依赖时复查。
- 多级??、查找加可选链、循环内隐式默认及多来源错误优先级，优先拆成具名变量、if和提前返回。简单单一默认、稳定selector常量及??=幂等缓存可以保留，不机械全禁。
- 展开空值逻辑时保留null/undefined及0、false、空字符串的区别，不把??改成||；错误展示仍按原优先级，权限、重试、超时和取消语义不变。不新建通用fallback函数把业务选择藏起来。

## 死代码与依赖

- 未引用文件、导出、依赖和重复状态先用rg核对源码、程序入口、动态注册、CSS、schema、测试、构建及发布资源；一次静态未命中不足以证明可以删除。当前不宣称已配置Knip等扫描。
- 确认同一职责后合并重复实现/可写事实源，移除注释副本和失效导出；公开exports、生成资源和有明确规划的资产按实际消费者判断，不机械裁剪。
- 依赖声明在实际消费workspace；生产运行所需放dependencies，测试/构建所需放devDependencies。工具误报只加具体路径/包的有理由例外，不全目录忽略，不把所有未声明依赖补进devDependencies。

## 实施与证据

修复前建立或更新Spec，保留无关工作区改动；重命名同步所有消费者和文档引用。按风险运行静态/类型、纯逻辑和必要真实交互回归，机械硬规则必须同时有实际通过和拒绝fixture；语义性判断由review承担。裁剪与数据影响见[裁剪规范](../08_COLLABORATION/pruning.md)，报告格式见[治理入口](overview.md)，只报告实际执行结果。
