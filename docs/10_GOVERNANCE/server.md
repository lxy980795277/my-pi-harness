# daemon治理

先读 [后端](../05_CONSTRAINTS/backend.md)、[存储](../05_CONSTRAINTS/storage.md)、[安全](../05_CONSTRAINTS/security.md) 和当前API。按领域审查，判断架构拥有者与实际运行行为，不复制Nest/Prisma多实例检查项。

| 维度       | 核对事项                                                        |
| ---------- | --------------------------------------------------------------- |
| 分层       | route只处理输入输出，服务不持有HTTP对象，repository不回流UI状态 |
| 输入       | schema校验、大小、默认值、未知字段和类型转换政策有真实拒绝证据  |
| 输出       | 按状态schema选择字段，无Entity、路径、凭据或内部堆栈泄露        |
| 配置       | 副作用前校验，非法或缺失资源失败，不静默替换目标                |
| 生命周期   | 启动失败回收、stop幂等、取消传播、SSE关闭、进程实际退出         |
| 状态       | 临时Map有所有者，持久事实入SQLite，未知结果不假成功             |
| 错误与日志 | 领域错误可区分、状态真实、关联与脱敏、stdout启动记录独占        |
| 存储       | 事务、seq唯一、迁移冻结、备份、JSONL导入与索引恢复              |
| 扩展能力   | 模型/工具/MCP权限、超时输出和隔离由所属模块承担                 |
| 测试       | 逻辑单测、真实边界、源码与构建产物分别验证                      |

M0尚未建立存储与Agent功能时记录“不适用”，不能将未实现能力列为已检查通过。发现bug提供可观察触发条件，区分当前缺陷与后续设计建议；输出格式见 [治理入口](overview.md)。
