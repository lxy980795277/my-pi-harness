# Renderer治理

先读 [前端约束](../05_CONSTRAINTS/frontend.md)、[设计](../02_DESIGN/overview.md)、[协议](../03_API/overview.md) 和通用类型规则。按实际feature审查，不默认忽略生成组件以外的整个目录。

| 维度     | 核对事项                                                   |
| -------- | ---------------------------------------------------------- |
| 职责     | 页面、组件、Hook、客户端与状态所有者清楚，无重复服务事实   |
| React    | 具名业务组件、Hook规则、完整依赖、异步取消和卸载清理       |
| Zustand  | 选择器、稳定结果、无组件getState或跨store隐式写入          |
| 数据     | 共用DTO/schema，HTTP/SSE经过实际客户端，校验及实例身份一致 |
| 状态     | loading/error/empty、断线、重连、取消与未知结果区别明确    |
| 呈现     | 统一UI入口与token、长文本、滚动和窗口适配、长列表性能      |
| 可访问性 | 名称、键盘、焦点、对比与非颜色状态、减少动效               |
| 桌面安全 | 无Node或内部依赖，有限桥接，不将任意外部内容当可信HTML     |
| 证据     | 静态规则、真实浏览器操作和视觉检查分别明确                 |

React/Zustand细则由前端规范拥有，不在本页复制另一份写法。生成shadcn组件的官方惯例不能作为手写业务组件的例外理由；规则工具不能代替页面操作。输出按 [治理入口](overview.md) 记录位置、证据与严重度。
