# 定期治理

治理是专项检查，不替代日常Spec和验收。按实际变化或定期需要执行，先给出证据与范围，再实施已经授权的修复；不借治理扩张功能或删除有明确规划的资产。

## 检查入口

| 文件                     | 范围                                  |
| ------------------------ | ------------------------------------- |
| [web.md](web.md)         | React Renderer、状态与可访问性        |
| [server.md](server.md)   | Fastify、应用服务、存储与生命周期     |
| [desktop.md](desktop.md) | Electron、独立Node、权限和平台发布    |
| [code.md](code.md)       | 命名、类型、弃用、可读性与死代码/依赖 |

## 检查维度

| 维度         | 重点                                                              |
| ------------ | ----------------------------------------------------------------- |
| 依赖与模块   | 跨app私有导入、浏览器不安全依赖、循环依赖、未使用依赖、无职责空包 |
| Renderer     | 状态所有者、订阅清理、流式渲染、三态、共享协议、组件重复          |
| daemon与桌面 | 来源校验、资源归属、进程回收、输出限制、配置与错误信息            |
| Agent与工具  | 模型可见内容可重建、审批与执行区分、重复副作用、取消与未知结果    |
| 存储         | 事实与索引、日志批提交、投影重建、损坏处理、恢复证据              |
| 文档         | 死链、重复事实、过期状态、假验证、历史决策误作当前规范            |
| 发布         | 产品版本一致、生产依赖和原生资源、平台检查与签名说明              |

未使用扫描需要核对构建、测试、CSS、schema、动态注册和发布资源入口，不因静态工具未识别就直接删除。依赖只添加到实际使用者；不把所有未列出依赖补进devDependencies。

## 输出

每项说明位置、实际风险、证据、建议和检查范围；区分违反现有约束、实际缺陷和可选改进。修复后更新相关Spec/Issues或权威文档，真实无问题时报告检查范围，不编造治理收益。

```text
[高/中/低] 路径:行号
问题：实际触发条件与观察到的结果
证据：源码、复现命令或对应运行记录
建议：具体所有者和修复方法
验证：覆盖此问题的检查及未验证项
```

高为实际安全、数据损坏或生命周期缺陷；中为违反已确认规则或可靠性不足；低为可选维护改进。不能把个人偏好列为高风险，不能将未来未承诺功能称为当前bug。汇总扫描范围、各级数量与需要优先处理的位置。
