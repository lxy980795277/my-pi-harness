# 死代码与依赖治理

按实际变化或约2至4周开展专项扫描。先使用rg核对文件、导入和配置；未来采用Knip等工具时再定义真实命令与排除项，当前不声明已有未配置扫描入口。

| 扫描结果      | 处理                                                            |
| ------------- | --------------------------------------------------------------- |
| 未引用文件    | 查程序入口、插件注册、schema、测试、构建与发布资源后判断        |
| 未使用依赖    | 核对CSS/PostCSS、配置、二进制资源和workspace消费再移除          |
| 未声明依赖    | 加入实际使用workspace的dependencies或devDependencies            |
| 未使用导出    | 检查公开exports与消费者；业务私有导出可收窄，生成组件不机械删除 |
| 重复导出/状态 | 确认是否同一职责或合法不同入口，优先消除重复事实源              |
| 例外与忽略    | 限定具体路径/包并说明实际用途，不全目录忽略掩盖问题             |

生产daemon运行需要的依赖必须在dependencies，不能全部补到devDependencies。静态工具识别不到Tailwind CSS、配置导入和打包资源时建立局部例外；不搬用参考项目的旧Tiptap、backup和Next目录ignore。

删除步骤与数据/公开API影响见 [裁剪规范](../08_COLLABORATION/pruning.md)。报告确认的使用者和检查范围，不凭一次扫描的总数宣称收益。
