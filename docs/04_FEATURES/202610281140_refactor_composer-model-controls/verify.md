# 输入栏模式清理与统一模型菜单验证

日期：2026-10-28，北京时间。macOS arm64、Node24.20.0、pnpm10.34.6、产品0.11.0。AC1–AC5及UC1–UC5在以下源码、真实构建和Chromium范围内通过；未提交或推送。

## 最终行为

新旧会话输入栏、工作面板及检查点展示不再提供执行/Plan模式。创建会话workMode、WorkState.mode、WorkPatch.mode、客户端冻结草稿和MCP模式参数、模型上下文模式字段及Plan只读门禁均删除；旧参数通过真实HTTP返回400且没有写入状态。InputRequest.mode的send/steer/follow-up仍属于队列语义，MCP表单/JSON的mode仍属于编辑界面语义。

结构化计划、Todo、人工提问和计划审核继续保留。反馈、批准及取消更新计划状态并继续原有等待流程，不切换工作模式；工具仍经过所选审批策略、精确只读授权、工作区与参数检查。M3浏览器场景完整走过计划反馈、再次审核、批准、同Run继续、快照恢复与两类重置。

模型菜单最上方固定一个推理强度子菜单，下方按服务商选择模型；外部触发器同时展示当前模型和推理档位，没有独立思考下拉框。档位来自当前模型能力，关闭-only模型可以进入子菜单但只有关闭选项；切换模型沿用既有选择/保存逻辑，初始化关闭，不把上一模型的档位直接传给新模型。失效历史选择保留为禁用项，不自动选其他模型。

菜单使用新增的Radix Dropdown Menu 2.1.25及本地UI封装，键盘、焦点、子菜单碰撞与关闭由原语拥有；仅有菜单开合的局部状态，模型事实继续由Query/草稿所有者维护。没有开放新的CSP权限，静态品牌资源复用既有来源。

## 界面与交互证据

已查看output/playwright/composer-controls-20261028中的composer-model-menu-light.png、dark.png和narrow.png。浅/深色下顶部推理行、当前档位和选中标记均可见，服务商行位于分隔线下面；640×800窄视口时子菜单翻转到左侧，菜单横向保持在视口内。该证据仅覆盖菜单避让，不扩展为整个应用的手机布局验收。
