# 输入栏模式清理与统一模型菜单

## Spec

### Roadmap Alignment

本轮调整既有M1模型选择、M3工作状态及M4收尾交互，沿用[roadmap](../../00_OVERVIEW/roadmap.md)，不进入M5。执行/Plan模式退出当前产品范围，计划内容、Todos、人工提问和计划审核仍独立保留。

### Intent

移除输入栏执行/Plan模式选择及全链路模式状态、接口参数、上下文和工具限制；将推理强度移入模型菜单顶部的统一子菜单，下面按服务商选择模型，输入栏只显示一个模型入口。

### Constraints

- 删除WorkState.mode、工作编辑mode及新会话workMode，不隐藏控件后保留无用参数、默认值或固定执行模式。输入队列send/steer/follow-up及MCP表单/JSON等其他mode不属于本次删除范围。
- 移除只规划模式对工具的额外限制；现有审批策略、MCP精确只读授权、工作区和工具参数校验继续生效，计划审核不替代工具审批。
- 保留结构化计划、Todo、人工提问、同Run计划审核和分支检查点的其余事实。持久日志读取以[后续专项](../202610281245_refactor_session-journal-reading/spec.md)为准，不清理用户数据库、会话、凭据或工作区。
- 模型菜单使用现有基础控件体系及维护中的菜单原语处理嵌套、键盘、焦点和碰撞避让；不手写完整菜单交互或开放新的CSP权限。
- 推理强度只有主菜单顶部一个入口，当前模型支持的档位决定内容；外部触发器显示所选模型和当前强度，新旧会话共用组件。模型不支持推理时只显示关闭。
- Query保留服务器事实，Zustand保留草稿；菜单局部状态不复制模型配置。模型切换沿用现有已校验选择和持久化路径，不发送不支持的强度。
- 公开协议按破坏字段删除升级；版本发布与commit仅在用户明确要求时执行。

### Acceptance Criteria

- AC1：新旧会话、工作面板及检查点中无执行/Plan模式入口、文案或客户端模式状态；工作状态和新会话接口不再接受或返回相关参数。
- AC2：不存在只规划模式的运行时/上下文/存储分支；计划、待办、提问、审核与其他审批策略继续通过有效回归。
- AC3：对话模型按钮打开菜单，顶部推理强度子菜单、服务商模型子菜单顺序固定，支持键盘、焦点、勾选和取消，界面不再有独立思考下拉框。
- AC4：模型/推理选择在新旧会话正确保存，按当前模型能力过滤档位；失效的历史选择保持明确不可用，不自动换用另一模型。
- AC5：定向源码、类型、静态和真实构建浏览器检查通过，记录实际平台、截图观察和未验证边界。

## UseCase

- UC1：进入新对话，选择服务商模型，再通过同一模型菜单顶部切换推理强度并发送；请求中没有workMode，实际使用选中模型和强度。
- UC2：打开既有会话并切换模型/推理，刷新保留服务端选择；运行中不能修改冻结配置。只支持关闭的模型没有无效推理档位。
- UC3：手动或Agent编辑计划、待办并完成反馈/批准，继续同Run处理；没有模式切换，工具仍按所选审批策略执行。
- UC4：旧workMode/mode工作参数被HTTP校验拒绝，未修改会话或工作状态；分支、检查点和重置保留其余内容语义。
- UC5：通过键盘进入推理和服务商子菜单，选择后回焦；菜单在视口边缘可避让，无独立横向溢出或CSP错误。

## Issues

删除工作字段引起的旧日志读取问题由[会话日志去版本与持久读取整理](../202610281245_refactor_session-journal-reading/spec.md)解决，不再以批次版本拒绝附加字段。模型菜单基于[Radix Dropdown Menu](https://www.radix-ui.com/primitives/docs/components/dropdown-menu)的子菜单和单选原语实现，复用已有主题与CSP nonce初始化，未自管键盘或放宽CSP。整合时TypeScript发现可选disabled不能显式传undefined，调用处按已声明选项缺省为false；最终真实构建通过。

## 移除focus-visible样式（2026-10-30）
