# Pi 1.4运行时升级

## Spec

状态：工程实现、本机自动化及DeepSeek Flash关闭推理档位的真实对话补测完成，按用户要求整理为0.15.0本地提交；其他供应商/推理档位、真实插件账号、Windows及正式安装/签名未验证，详见[验证记录](verify.md)。

### Roadmap Alignment

属于M0依赖治理及M1–M5维护，承接已完成的Agent执行职责拆分。M6仍为规划，本迭代不恢复已暂缓的工具目录/默认加载重构，不引入Pi coding-agent、durable、codemode或新的消息/Session体系。

### Intent

将正式依赖的Pi agent-core和ai从1.1.0统一升级到已发布1.4.0，采用其Provider协议、参数解析和消息转换修复，并处理本应用的配置、私有消息校验和请求身份。发布版以npm精确版本为准，不混入本地Pi仓库的Unreleased实现。

### Constraints

- 保留主/子Run、审批、请求调度、队列、插件/MCP、工作区策略及完整消息持久粒度；不复制参考仓库业务实现或提示词。
- core、ai及其依赖一致解析，移除旧core→ai强制1.1.0覆写；Node继续使用项目声明的24版本。
- 私有codec按本应用格式校验消息，SDK版本只记录实际来源，不作为同一codec格式的读取分支；补充1.4字段校验，不加入按旧SDK版本转换或降级逻辑，不清除用户配置、凭据、会话或工作区文件。
- 原生Provider目录和API由新版Pi拥有；不自动替换失效型号或推理档位，自定义Provider的显式配置保持用户拥有。
- 畸形JSON在任何工具审批/副作用前拒绝，并将有界解析原因交给模型；不得移除原始参数严格校验或允许Pi静默转换数字字符串/null。
- 主/子Run、摘要、审批和连接探测共用应用请求身份；身份配置不读取供应商凭据或新增遥测上传。
- 静态、受控HTTP/SSE、源码集成、构建产物、实际供应商与平台证据分开记录。普通测试不调用用户模型账号或Keychain。

### Acceptance Criteria

- AC1：两个Pi包精确解析为1.4.0，不存在core与ai的混合版本或旧override，源码类型和受影响检查通过。
- AC2：三种自定义协议、原生六厂商、keyless、认证隔离、取消和lease释放保持可用；Kimi使用新的Completions端点，被移除模型和不支持档位明确拒绝，不静默换模型。
- AC3：codec保存实际SDK来源，保留并校验argumentsError、签名及完整消息；日志回放不按SDK版本分支，公开协议和SQLite结构无无关变化。
- AC4：畸形工具JSON不执行，错误调用与结果成对落盘，模型收到可修复的有界错误并能继续；已有严格参数拒绝不退化。
- AC5：应用身份一致经过正常、keyless、主子Run、摘要和审批请求；不发送虚构产品URL，不自动启用telemetry。
- AC6：M1–M5现有能力回归通过；实际部署产物可从源码树外启动/退出并解析lazy Provider。真实账号、完整桌面交互和Windows未执行部分明确标记，不用源码测试替代。

## UseCase

- UC1：已有Profile加载新版六厂商目录；新建和继续会话采用真实API、上下文及推理能力，旧显式失效选择返回可理解错误。
- UC2：通过真实Pi适配器连接本地动态端口的Completions/Responses/Anthropic SSE；认证、keyless、自定义headers及停止保持一致。
- UC3：模型发出畸形最终工具JSON；系统先拒绝执行，保存原始错误和失败结果，再将错误反馈给下一轮模型；合法参数不受影响。
- UC4：同一会话切换模型；出站请求不包含另一模型的私有思考，原始持久消息保持完整，工具调用结果仍配对。
- UC5：主子任务、独立审批及自动摘要调用经过同一身份策略；取消和失败后请求槽位及模型lease释放。
- UC6：从临时目录启动已部署daemon，检查Pi版本/公共子路径、就绪和关闭；不读取用户真实Profile或修改开发端口。

## Issues

- 前期隔离探测确认：本地Pi HEAD已超出1.4发布态，不能把工具参数增量JSON解析优化计入本迭代。
- 前期隔离探测确认：现有prepareArguments可能先以通用schema错误拒绝空参数，遮盖Pi argumentsError中的完整JSON错误。本次需保留严格校验并补齐详细反馈，不以放行参数解决。
- 正式写入实际SDK版本后发现storage工具意图投影同样固定校验1.1.0，导致工具事实被拒绝并冻结会话。前期隔离检查仍写旧标记，因此未暴露该点；本次已同步修复runtime与storage两个读取所有者，新增任意非空SDK来源按同一codec投影的回归，不建立旧版本转换。
- 浏览器回归发现四个既有场景使用8192窗口，却假设不会自动压缩；实际输入超过80%阈值后插入正常摘要，导致请求下标/数量和手动摘要版本数断言失败。仅为快捷键、计划/快照、手动摘要及插件工具发现场景显式配置32768窗口，保留原请求与版本链断言；产品压缩策略未修改。
- 工具增量缓存仍受本应用leading system重建方式影响，本迭代不宣称获得全部缓存收益；摘要固定输出上限继续由本应用策略拥有。
