# 会话消息持久粒度整理

状态：2026-10-29工程实现及macOS自动化验证通过，旧会话已按授权清理，独立配置保留；实际结果见[验证记录](verify.md)。尚未提交或推送。

## Spec

### Roadmap Alignment

属于既有M1会话事实、M3上下文和M5子任务链路维护，不扩张M6/M7。用户明确授权以pi-harness的消息持久粒度为参照，流式片段仅用于实时展示，完成消息和必要执行事实落盘；旧开发数据不兼容，可删除本项目旧会话并清理对应数据库。保留当前M5及界面未提交工作，不自动提交或推送。

### Intent

消除每个文本/思考片段单独写JSONL、校验和、fsync与SQLite投影的开销，同时保持实时生成、断线重连、任务详情、停止和正常失败后的完整消息可读。此前样本44629行/20.56MB中，44447行/18.33MB为流式增量，实际新增内容约155KB；精简目标是持久记录数量随消息和执行事实增长，不随token/chunk数量增长。

### Constraints

- 独立实现既有范式，不复制参考项目业务代码；当前完整消息、思考、供应商元数据、工具参数/终态、权限与请求上下文仍保留。
- 保留用户完整输入、assistant空开始占位、完整message.completed以及Run、队列、分支、工作状态和Task事实。message.delta移出持久事件集合，不写JSONL或SQLite，误入持久append明确拒绝。
- 实时片段通过独立publishMessageDelta入口更新宿主内存覆盖层，校验原Session/Run/消息归属、活跃状态和长度。不会创建第二份可持久修改的消息或模型上下文；模型历史仍只读持久完整事实。
- 当前tool.updated全部承载审批、派发屏障或终态，继续落盘；没有实际工具临时进度生产者，不预建tool.progress空接口。MCP may_have_started必须在调用外部服务前持久成功，unknown恢复不变。
- snapshotSeq仅计算连续持久事件。SessionSnapshot及AgentTaskDetail增加非持久liveRevision；当前持久seq内每次实时更新递增，成功持久提交后归零，但其他活动消息覆盖层保留。客户端按(snapshotSeq,liveRevision)判断新旧，patch双水位精确对齐，SSE id为seq:revision。
- 重连发送当前完整快照，不回放瞬态片段；启动恢复必须持久终结全部根/子在途执行，使snapshotSeq超过崩溃前持久水位。不增加进程epoch或历史兼容分支。
- 正常完成、取消和失败一次持久化已观测的完整正文及思考；SDK错误消息为空时不能抹掉已显示内容。真正崩溃前尚未完成、未落盘的片段允许丢失，恢复仅标记中断，不伪造内容或自动调用模型。
- 公开协议随新快照消费者同步升级；不新增无需要的SQLite迁移。JSONL继续完整批次、checksum、严格连续seq、fsync和失败冻结；下载仍是原始已提交日志，不包含内存片段。
- 清理前确认属于本项目并正常停止所属运行，清除旧会话日志/附件及数据库会话投影，保留独立Provider、工作区、应用授权与插件凭据。不操作pi-harness或其他项目、用户工作区源文件。

### Acceptance Criteria

- AC-01：同一受控输出拆成不同chunk数量，持久消息数和JSONL行数不随chunk增长；JSONL与SQLite事件表没有message.delta，readEvents仅返回持久事实。
- AC-02：生成中主对话和子Task详情可读当前完整partial，增量不写SQLite；普通持久事件穿插时不丢其他活动partial。相同持久seq的新liveRevision不会被当作旧数据丢弃。
- AC-03：SSE双水位patch、HTTP迟到、重连首包及真正重启恢复保持正确；纯增量不触发工作状态查询，子流不驱动主聊天重建。
- AC-04：完成、取消和错误后完整正文及思考持久并可重放；崩溃后未完成Run/Task中断，已持久工具副作用和unknown语义不变，不自动重跑。
- AC-05：完整消息、模型上下文及工具结果保持可还原；下载与磁盘字节一致，审批/队列/分支及M5通信不因瞬态路径改变。
- AC-06：授权的数据清理范围可核验，旧会话不再被新启动读取；独立配置和凭据保留。定向源码、静态、构建产物及浏览器实际验证，更新技术/API说明与结果，不冒充真实供应商/平台验收。

## UseCase

- UC-01：流式输出包含正文与思考，期间读取HTTP/SSE及任务详情；实时内容增长，日志只记录开始和终态事实，结束后刷新保持完整消息。
- UC-02：流式期间更新计划、产生工具结果或另一个子任务结束；持久seq前进且liveRevision归零，其他partial继续可见，旧响应不能覆盖新内容。
- UC-03：生成中断开页面再连接；获取当前内存全量快照。终止daemon后重启则只保留持久完整消息，在途运行中断，不恢复丢失片段或重复工具。
- UC-04：SDK取消/错误返回空final，或最后持久提交失败；已显示内容在正常取消/失败时保存，持久化不确定时按原策略冻结并停止实际运行。
- UC-05：MCP执行前派发审计已落盘，异常重启继续判unknown；日志下载不包含未持久片段。

## Issues

当前日志将流式片段与持久执行事实共用同一append事务，每条增量附带完整事件包、checksum和fsync。仅在JSONL写入时过滤不能解决SQLite/快照依赖，也会破坏连续seq；需要独立实时发布及明确快照水位。

产物及下载回归的旧partial持久断言已同步：正常取消/完成保存完整消息，真正崩溃仅中断，下载只反映已提交事实；模型请求数、无自动重跑和下载字节检查保留。
