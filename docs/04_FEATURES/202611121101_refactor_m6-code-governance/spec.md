# M6 实现代码治理

## Spec

状态：2026-11-12按用户授权开始，审查、修复及本机验证已完成。工作区保留既有M6及直接保存/自动学习改动，本轮不自动提交、清库或推送。

### Roadmap Alignment

属于M0工程治理与已实现M6的维护，复核[长期记忆与跨会话搜索](../202610301722_feature_m6-memory-search/spec.md)的模块划分、共享规则和生命周期；不进入M7，不扩大平台、真实供应商或外部账号验收范围。

### Intent

模块职责清晰、依赖边界明确、容易扩展。清理真实重复、重构后失效内容与无人负责的异步工作；不以文件数、行数或抽象层数为目标，不通过机械改写对象成员或新增转发层制造治理收益。

### Constraints

- 逐项执行[治理入口](../../10_GOVERNANCE/overview.md)及code/server/web/desktop相关规则；先说明消费者、触发条件和实际风险，再修复。
- 保留现有直接记忆、根子范围、CAS、幂等、遗忘及实际请求可重建语义；保留原工具审批、虚拟列表和只读来源引用。
- Query拥有服务器事实，Zustand只拥有筛选、草稿和展示状态；memory拥有领域规则，storage拥有事务/索引，runtime拥有实际Run，daemon拥有身份解析与本地模型资源。
- 不删除合法动态入口、发布资源、历史证据或仍被实际profile使用的迁移；不读取真实凭据或清理真实数据库/会话。
- 局部修复使用最小充分检查。已有检索质量、规模性能及平台证据只在实现和环境未变化的范围复用；实际改变算法、查询范围/排序/索引或模型调度时重验相关门槛。

### Acceptance Criteria

- AC-01：每项修复有明确所有者、实际问题与消费者证据，不引入第二事实源或泛化框架。
- AC-02：删除确认无消费者的代码/字段/依赖，更新所有真实调用方；结构已经合理的部分如实保留。
- AC-03：取消、关闭、异步返回及持久化异常由原拥有者收束，不假成功、不放宽权限或隐藏失败。
- AC-04：保持用户可见功能及协议语义；必要行为修复有可复现回归，静态/类型/格式与受影响测试通过。
- AC-05：验证结束后记录扫描范围、发现和保留项、实际命令及未验证项，更新权威文档与roadmap，不重复复制规则。

## UseCase

- UC-01：普通对话直接保存/学习，关闭后停止自动学习，纠正、遗忘及新请求采用继续正常。
- UC-02：根/子请求、队列、引用和动态工具保持原范围，取消和重启不复活失效授权或正文。
- UC-03：管理、搜索、只读来源、虚拟定位在切换/关闭/注销后不接受迟到结果，临时状态不会复制服务器事实。
- UC-04：本地资源只由唯一Worker拥有者派发，查询/准备/索引关闭可等待；检索与发布资源保持实际消费者关系。
