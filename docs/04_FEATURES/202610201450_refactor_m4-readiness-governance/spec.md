# M4前代码治理

## Spec

状态：基线0.6.1的治理与验证已完成，确认高0项、中4项、低4项，均已修复、清理或修正文档。27个浏览器场景、daemon产物恢复及macOS arm64应用目录smoke通过；纳入0.6.2本地提交，未推送或对外发布。本专项不实现M4能力，后续从M4.1详细设计恢复。

### Roadmap Alignment

本专项属于M0工程治理及M1–M3存量维护，覆盖当前会话渲染迭代后的Web、daemon、runtime、storage、execution、desktop、脚本和文档。M4.1–M4.9沿用已确认模块与任务，治理完成后从M4.1详细设计恢复，不将规划视为已实现。Windows Shell、浏览器新增目录及既有真实账号/平台边界保留原归属。

### Intent

按docs/10_GOVERNANCE检查命名、领域类型、弃用API、空值可读性、真实死代码/依赖、状态和生命周期，以及当前文档与实现的一致性。只修复有源码或复现证据的问题，不以改动数量代替治理效果。

### Constraints

- 先确认消费者和拥有者，再裁剪或重构；保留动态入口、发布资源及明确规划的资产。不删除用户数据、日志或工作区文件，不机械禁用所有空值表达式。
- 按实际风险区分约束违规、行为缺陷和可选维护项；发现问题记录位置、触发条件、证据及修复范围，无法确认的猜测不作为已发现缺陷。
- Renderer保留当前UI、Markdown/虚拟列表与消息原文职责；daemon、runtime、storage和execution保留授权、审批、取消及提交顺序，不借治理扩张M4功能。
- 静态扫描覆盖工程入口，人工审查按关键领域路径进行，不宣称逐行证明所有源码无缺陷。已有同内容检查可复用，新修复补最小充分行为证据；真实服务、桌面产物及平台验收分别记录。
- 提交遵循八步流程，准确同步产品版本、验证记录和发布说明；提交钩子不绕过，不提交凭据、运行数据或诊断产物。

### Acceptance Criteria

- AC-01：完成Web、服务/运行时/存储、桌面/脚本及通用代码规则审查，记录覆盖范围与高/中/低问题数量，有证据时修复并回归。
- AC-02：领域命名/联合、弃用API、多级空值及死代码/依赖的扫描结果经消费者核对；没有问题的维度如实记录，不为满足数量制造改动。
- AC-03：新修复的检查通过，既有M1–M3关键交互与存储/恢复职责不回退；未执行的浏览器、账号和平台操作明确保留。
- AC-04：当前架构、API、使用说明和M4下一步没有过期事实或假完成状态；治理结论、版本、Release Note及本地提交可追溯。

## UseCase

- UC-01：维护者按治理入口扫描和检查关键调用链，对确认的问题确定真实所有者，修复后执行相关回归；未确认或范围外项不当作修复成果。
- UC-02：用户审查治理记录及本地提交，了解实际修复、通过证据和剩余边界，再从M4.1继续开发。

## Issues

- [中，已修复并通过产物验证] G-01：桌面smoke的preload白名单遗漏已公开的openExternal，当前产物固定公开5项却仍断言4项，导致新包smoke失败。修复验证入口并重新验证真实macOS产物，不放宽任意桥能力。
- [低，已清理] G-02：Web的fetchProvider服务包装只有声明，没有源码、测试、脚本或动态入口消费者。移除死包装；保留仍由公开协议和宿主拥有的GET路由。
- [低，已修复并通过验证] G-03：退出时公共健康缓存判定仍使用旧health前缀，真实查询已改为runtime/health/协议版本；同步实际key与回归fixture，避免清理公共健康数据。

- [低，已修复并通过验证] G-04：桌面打包已有显式Client ID时仍读取根.env，与显式配置优先的职责不符；改为缺省时才读取文件，保持校验和fallback。
- [中，已修复并通过浏览器验证] G-05：QueuePanel以输入ID和revision作为key，另一页面更新时重挂载并丢弃本页正在编辑的草稿。旧产物真实浏览器已复现。改用稳定输入ID并在开始编辑时冻结text/revision，使后续更新保留草稿且保存产生409；未将初步推测的静默覆盖当作旧代码已确认行为。
- [中，已修复并通过验证] G-06：注销或授权撤销后，旧的在途auth-status响应可重新写入authenticated状态。真实QueryClient与deferred读取已复现；修复需同时保护Query、CSRF、显式接收及注销过渡，而非只忽略末尾receive。
- [中，已修正文档] G-07：模型会话指南仍将归档历史完整性归因于SQLite事件，落后于JSONL事实源设计；按实际归档和日志实现修正，保留历史验证记录。

- [低，已修复] G-08：附件freeze内部已有唯一取消信号所有者，可选signal与新controller fallback没有实际调用需求；收紧私有参数并直接透传，保留公开接口。

其他维度未确认需要修改的高/中问题；实际范围、回归与平台边界见[治理验证](verify.md)。
