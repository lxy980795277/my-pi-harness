# 配置装配与条件表达式治理

## Spec

状态：局部方案按用户review收敛后，已扩展完成七个package的扫描及必要整改。包级行为、全workspace类型和静态检查通过，覆盖与保留结论见[验证记录](verify.md)。用户后续授权按[0.17.1](../../06_RELEASES/0.17.1.md)本地提交，不推送。

### Roadmap Alignment

属于M0代码可读性及既有M1–M5维护，承接0.17.0后的治理审查；M6保持仅规划，不扩大功能或验收范围。

### Intent

覆盖agent-runtime、execution、integrations、protocol、storage以及eslint-config/tsconfig配置包。保留配置对象的整体性，按实际业务职责提取复杂计算、较长行为和真正重复的策略，不以修改数量为目标。原有模型策略计算和任务正文读取继续保留。条件展开、字段数或对象大小本身不作为整改理由，不通过零散赋值把一个完整配置拆成多处。

### Constraints

- 保留exactOptionalPropertyTypes和原字段缺失语义，不将可选属性统一改为显式undefined，不增加断言、Partial占位或通用conditionalProps/builder。
- 保留truthiness、null/undefined区别、覆盖顺序及有副作用的求值时机；不为减少表达式长度拆散完整配置。
- 上下文模型适配继续每次prepareRequest计算，反映委派后的输出上限；原SDK可选transformContext仍延迟读取最新投影，没有work时不注册。
- 任务正文保持原语义：字符串直接使用，结构化消息只取首个text；不改变附件、消息或上下文处理。
- 保留已收敛的主子Run及daemon集中配置，扫描范围只扩展到packages，不自动改apps或重新拆散配置；通信、授权、网络策略、持久化校验及资源生命周期只整理表达，不改变行为。
- 不变更协议23、SQLite9、消息/JSONL、界面或数据，不启动真实模型/用户服务；实现阶段不自动提交或升版，用户后续要求提交时按项目流程同步产品版本与发布记录，不推送。

### Acceptance Criteria

- AC-01：ToolRunContext、Agent、主子Run及daemon配置继续整体表达，可选字段保留原条件展开，不保留对象后零散补字段的机械改写。
- AC-02：模型投影策略和任务正文读取由同文件具名函数表达实际职责；模型策略仍每请求解析，原条件和正文语义保持。
- AC-03：撤回部分没有遗留无消费者的类型导出、导入、配置变量或新文件，没有通用包装层。
- AC-04：治理规范以业务复杂度、职责及整体阅读效果判断，明确允许配置条件展开，不以字段数量决定是否改if。
- AC-05：相关源码行为、类型、静态和文档检查通过；动态输出上限回归保持有效，调整后再更新verify。
- AC-06：七个package均有扫描结论，区分应保留的简单写法和真正需要整理的业务表达；必要修复留在实际拥有者，不制造通用包装、类型副本或无效改动。

## UseCase

- UC-01：阅读Agent配置时能在一个对象内看到相关参数，模型策略计算可通过具名函数单独理解。
- UC-02：根Run在首次委派前后请求模型，上下文预算与实际输出策略继续一致；没有上下文服务时保留SDK默认处理。
- UC-03：阅读结构化用户输入的任务正文提取，不需要追踪filter/slice/map/join链，取首段text的行为保持。
- UC-04：review本轮diff，主子Run及daemon机械改写已撤回，无类型或声明残留，规范与实际实现一致。
- UC-05：逐package查看扫描覆盖和选定修改，单纯DTO/schema、短条件字段或完整配置保持整体，复杂策略和重复行为能直接找到所属函数。
