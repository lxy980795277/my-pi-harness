# M3 上下文与交互

## Spec

状态：2026-10-16本轮完整设计、实现与macOS本机自动化验证完成，待用户统一体验验收。当前应用0.3.0、wire8，实际证据与未验证项见[verify](verify.md)。本轮已清理旧开发数据，不做旧格式兼容；未提交、未推送，也未进入M4。

### Roadmap Alignment

沿用原M3.1–M3.8编号。会话JSONL权威存储作为M3前置重构；当前会话历史检索明确细化到M3.7，用于压缩后的原文恢复。跨会话搜索、FTS/embedding和长期记忆仍归M6；MCP/Skill归M4，子Agent归M5，文件撤销重做和完整导入导出归M7。M2的Windows Shell、浏览器新增目录及真实供应商验收保留原归属。

### Intent

让单个长期任务在多轮工具调用和上下文压缩后继续执行，让人工提问与计划审核真正暂停并继续原Run，并能从完整会话日志恢复历史、摘要版本、计划与任务状态。提供附件上传、预览和常用文档提取，保留已有工作区与对话体验。

### Constraints

- 本仓库独立实现；仅分析标杆功能，不复制业务代码或内部提示词。保持Electron、Web、daemon、runtime、storage分工，协议先定再同步全部消费者。
- 所有迭代仍处开发期，不要求兼容旧API、数据库、Session格式或codec；允许合并初始schema和移除旧适配器。用户授权直接删除本项目既有开发数据，不保留备份或迁移链；不删除.workspace及工作区源文件、不读取或删除其他项目数据。
- JSONL为会话执行事实的唯一权威，路径继续使用仓库根.my-pi-harness下按profile隔离的目录；SQLite拥有配置、工作区和可重建会话投影，系统凭据继续使用OS凭据库。
- 日志每行是带版本、稳定batchId、Session归属、seq范围及完整记录的批次。宿主记录包含模型codec、工具结果和请求上下文等恢复资料；HTTP/SSE只投影公开事件，禁止返回宿主私有字段和凭据。会话创建、编辑、归档、分支与工作状态均可由日志重建。
- 同步存储接口可保留：在短SQLite事务内验证并暂存投影，外层提交前先将同Session完整批写JSONL并fsync，再提交SQLite，返回后才发布SSE。非法批不写日志；任一写入/fsync或提交失败冻结后续写入，已提交日志不得触发工具重执行。跨Session恢复分别提交。
- 启动持有profile独占权后校验日志和重建会话投影。允许修复崩溃残留的不完整末行；完整坏行、顺序冲突、未知版本、缺失既有日志明确失败。SQLite不反向覆盖日志，日志根变化不再从数据库生成新主日志。
- 附件保存为独立不可变宿主文件，包含内容与校验摘要；先持久化附件后记录引用，缺失/校验失败明确报错。SQLite附件索引可重建；消息和SSE只包含元数据/ID，base64不进入通用前端Store。
- AGENTS延续工作区根及显式引用祖先规则，按由浅到深优先级冻结文本和hash，下一Run重新加载。不得越界、读取敏感目标或因上下文预算默默删除规则。
- 每次模型请求前执行统一流水线：有效历史投影、附件与过长工具结果处理、估算及可用Usage校准、自动压缩、完整工具配对和最终预算检查。分类数值仍是估算；真实Usage只校准总量，输出预留明确。
- 自动压缩支持同Run内连续工具任务。摘要包含目标、约束、决策、已完成、待完成、阻塞、下一步；保留当前任务、已批准计划和近期完整工具组，记录父版本、覆盖锚点、来源数、前后token及model/fallback策略。失败可用有界本地摘要，取消不提交半成品，最终仍超限时阻止模型请求。
- Question以稳定请求ID拥有多题，每题有ID、标题、问题、带描述选项、单/多选和自由回答开关。回答核对题目、选项、重复项、自由回答权限、Session/Run/分支及状态；取消结束当前等待，停止/重启终结等待，不自动重发副作用。
- Plan包含稳定ID、结构化步骤、正文和审核状态。update_plan提交后等待用户批准、反馈或取消；批准在同Run内切执行并继续，反馈交回模型修改。计划批准不替代具体工具审批，Plan期间继续禁止文件修改、Shell和Web POST。
- Todo支持pending/in_progress/completed/blocked/cancelled，关联计划步骤。新增完成依据可引用本Run实际成功工具ID，或填写明确文本结论；已保存且未修改的完成依据可沿当前可见历史跨Run/恢复分支保留，不得接受伪造工具证据，不强迫纯分析任务调用工具。运行时限制重复ID、失效步骤和多个in_progress。
- 自动摘要版本称“上下文检查点”，选择版本不创建消息分支，保留旧历史并明确新的有效尾部。现有消息前缀+WorkState保存功能称“会话快照”，恢复创建新分支。两种功能的协议和UI独立，不回滚磁盘或外部请求。
- reset-tasks只清Plan/Todos；reset-context重新设置有效历史起点并清规则/用量/摘要/问题/队列，保留Plan/Todos、mode、可读历史和会话快照。模型可清任务状态，不能隐式清空整个会话上下文。新顶层Run与批准原计划继续同Run明确区分。
- 当前会话历史检索有查询、结果数量和片段长度上限，仅返回当前Session历史；模型可恢复旧上下文检查点和清任务状态，不能越权访问其他Session或触发文件回滚。
- 附件支持文本、图片、PDF及常见Office/开放文档文本提取，不提供OCR。支持仅附件发送和图片粘贴；上传/解析时校验类型、大小、数量、解压输出及取消。菜单保持上传文件、禁用MCP、禁用Skill，不恢复已移除的工作区文件引用入口。
- UI保持紧凑、shadcn与Hook分工，无TSX复杂逻辑、三目、void启动或Promise链；保持Select无回焦边框、即时hover、右侧菜单和现有布局。
- 用户命令核对expectedBranchId/revision，拒绝旧客户端写到新分支；活跃Run仅开放匹配的提问和计划审核。测试使用临时数据和合成模型，不读取真实凭据或产生供应商费用。

### Data and API Design

- WorkSnapshot包含state、手动会话快照checkpoints和摘要版本compactions；state.compaction表示当前生效摘要。
- Compaction保留渲染正文，并有structured七字段、parentId、strategy、beforeTokens、afterTokens、sourceMessages、runId和覆盖消息锚点。
- Question包含questions数组与answers数组；每条答案为questionId、optionIds和text。Plan独立保存review状态，不把计划批准混入普通问答。
- POST /work/plans/:planId/review：expectedBranchId、revision、decision(approve/feedback/cancel)、feedback。
- POST /work/compactions/:compactionId/select：expectedBranchId和revision；POST /work/reset-tasks与/work/reset-context分别管理任务和上下文。
- 既有/work/checkpoints创建与恢复保留手动快照语义；questions/:questionId/answer接收answers数组，取消保持独立接口。共享协议版本提升，所有消费者同时更新，不保留旧入口适配。
- 存储WorkStore新增listCompactions(sessionId,branchId?)，来源为持久work.updated摘要版本；Runtime通过现有端口访问，不依赖SQL或磁盘实现。

### Acceptance Criteria

- AC-00 / 存储：移除旧开发数据后可启动；删除会话派生表后由JSONL恢复会话、消息、Run、队列、分支、上下文与附件引用。配置独立保留，宿主私有数据不进入HTTP/SSE。批校验失败不落日志，末行中断可恢复，完整损坏明确拒绝。
- AC-01 / M3.1：AGENTS作用域、优先级、冻结与下一Run重载保持有效，越界/敏感目标/超限拒绝。
- AC-02 / M3.2：文本/图片/PDF及文档上传、预览、仅附件发送、粘贴图片、队列和重启恢复可用；非法与超限输入在上传时拒绝，取消释放解析资源。
- AC-03 / M3.3：每次请求前显示预算、来源、分类、输出预留与裁剪；真实Usage可用时校准总量，最新输入与完整工具组得到保护，超限不发请求。
- AC-04 / M3.4：同Run多次工具循环可自动压缩且生成父子摘要版本，任务/批准计划/修正事实继续可用；失败fallback与取消、预算拒绝均有行为证据。
- AC-05 / M3.5：多题单选/多选/自由答完整提交后原Run继续；错误选项、重复/遗漏回答、错Session/已结束请求拒绝；停止和重启结束等待。
- AC-06 / M3.6：计划审核批准后原Run继续执行，反馈后模型修订，取消/停止结束等待；Plan只读和工具审批不被绕过。Todo步骤与完成证据校验、进度和持久化有效。
- AC-07 / M3.7：自动摘要历史可比较/选择，模型有界检索本会话原文、恢复摘要和清任务状态；手动会话快照继续创建新分支。任务重置与上下文重置效果不同，无磁盘回滚承诺。
- AC-08 / M3.8：源码、真实SQLite/JSONL、HTTP/SSE、浏览器、构建daemon与macOS桌面产物按实际运行记录；M1/M2关键流程回归；没有旧格式兼容验收。

## UseCase

- UC-01 创建干净profile、配置模型/工作区并完成对话；重启后历史、附件和工作状态恢复。删除会话投影再启动，日志重建会话但不自动调用模型/工具。
- UC-02 故意截断日志末行、损坏完整记录、丢失附件、模拟索引提交失败；只恢复已提交批，明确错误，不覆盖完整坏记录或重复副作用。
- UC-03 挂载规则和附件，单个Run连续执行足够多工具触发两次压缩；观察摘要链和当前任务继续，工具调用/结果配对完整，修正事实和待办不丢失。
- UC-04 模型提出含单选、多选和自由答的多题请求；用户分页填写并提交，原Run继续。非法答案拒绝；取消、停止、刷新和重启各有明确状态。
- UC-05 Plan模式产生结构化计划，保持Run等待；用户反馈后模型修订，再批准并继续原Run。文件/Shell继续走所选审批，不从计划批准推导工具授权。
- UC-06 比较两个自动摘要版本并选择旧版本，之后只使用其摘要和新的有效尾部；工具可检索同会话原文。创建手动会话快照再恢复，保留原分支与磁盘现状。
- UC-07 分别重置任务和上下文，检查摘要/历史/队列的差异；并发客户端用旧分支或revision操作时拒绝，不清错状态。
- UC-08 上传Office文档、只发送图片、粘贴图片并排队发送，刷新/重启后预览不依赖原文件；不支持格式和超限上传有具体错误，菜单无冗余限制文案。

## Issues

历史第一轮的压缩锚点重复应用、引用源文件删除、准备阶段取消、跨分支revision冲突已修复，继续保留回归用例。本轮新问题与解决记录在实际发生后补充，不将计划中的检查写成已验证。

### 本轮修复

- 同Run压缩后只剩两个assistant/tool完整组时，原选择器不再压缩，下一结果会超预算；允许压缩一个完整组并保留另一个，持续20次真实工具循环回归。
- 连续fallback摘要逐项有界但合计可能超持久化上限；结构化JSON与渲染正文统一执行全局预算，取消和存储失败仍不转fallback。
- 恢复分支后Todo继承原工具ID，但原校验要求工具属于新分支/当前Run；校验改为当前可见历史，未改的依据保留，新增依据继续核验。
- 历史检索只读公开消息会漏附件正文与父分支继承工具；有界读取当前可见消息绑定的冻结文本，避免全局附件扫描。
- Run刚结束立即打开工作面板时，SSE合并刷新可能尚未更新revision；打开时刷新当前分支工作Query，读取中禁用修改，保留服务冲突校验。
