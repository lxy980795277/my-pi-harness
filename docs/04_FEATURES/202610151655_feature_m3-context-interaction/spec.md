# M3 上下文与交互

## Spec

状态：M3.1–M3.8已有第一轮实现与macOS本机自动化验证，待用户统一体验及最新桌面包验收；实际证据和未验证项见[verify](verify.md)。当前按用户授权随0.3.0本地提交既有改动，下述模块验收顺序待确认，确认前不追加开发，不推送或进入M4。参考标杆的功能和交互，独立实现，不复制其业务代码或内部提示词。

### Roadmap Alignment

属于[roadmap](../../00_OVERVIEW/roadmap.md)原M3：AGENTS、附件与引用、预算/裁剪/压缩、人工提问、Plan/Todos、checkpoint对比恢复及工作状态重置。M2的Windows Shell、浏览器新增目录、真实供应商/账号验收仍留原处；M4插件、M5子Agent/看板、M6长期记忆、M7文件撤销重做不提前实现。

### Intent

使用户能提供项目规则和文件上下文、持续进行长对话、回答Agent问题并检查计划进度，在保留历史的前提下比较和恢复会话工作状态。

### Constraints

- 沿用Electron/main/preload、Web、daemon、Pi runtime、storage职责，UI采用现有shadcn与TSX/Hook分工；共享协议先定义，再并行实现消费者。
- SQLite只追加0005及后继迁移；原始事件、迁移1–4、私有codec1/2不重写。M3新增工作状态按分支保存，修改先持久化再发布；wire升级并同步消费者。
- 运行使用冻结规则与附件内容，模型请求上下文保留可重构记录。工作区根AGENTS及显式文件引用路径上的AGENTS按由浅到深顺序加载，有来源、hash和大小限制；下一Run重载，不能越界读取。
- 附件支持UTF-8文本、图片及PDF文本提取，无OCR；HTTP上传与工作区文件引用均校验类型、大小、数量及真实路径。内容保存于宿主，不将base64放通用前端Store或SSE；历史只公开元数据/ID，通过受授权接口预览。
- 添加上下文菜单依次展示“上传文件”“MCP”“Skill”，使用紧凑内边距；MCP/Skill为禁用占位，其能力仍属M4。按用户后续调整移除文件引用入口与表单，宿主引用API和历史引用预览保留；不常驻展示大小和数量限制，上传时校验并显示具体错误。
- 上下文预算是估算，预留模型输出；裁剪保持完整用户轮次与工具调用/结果配对，不能丢失最新输入或悄悄删项目规则。手动/自动模型摘要持久保存覆盖锚点，失败或取消保留旧状态和原历史。
- 人工提问、Plan/Todos是会话工具，无工作区也可用；文件/Shell工具继续要求工作区。提问有稳定ID、所属Run、单次回答、取消与重启interrupted状态，不自动沿用旧待答请求。
- Plan模式只允许读取与会话规划工具，不进行文件修改、Shell和Web POST；计划确认不会跳过正常执行审批。Todos为单Agent会话状态，不等于M5任务看板。
- checkpoint保存分支消息前缀及上下文/摘要/Plan/Todos；比较显示差异，恢复通过新增分支保留原历史。恢复/重置要求Run已停止，不自动重放队列或副作用；不回滚磁盘、Shell或外部请求。重置保留会话历史并清理所选工作状态与未消费队列。
- 工作状态读取明确预期分支；编辑、压缩、恢复、重置及检查点创建核对expectedBranchId，版本化修改同时核对revision。其他客户端切换分支后，旧命令返回冲突，即使两个分支版本相同也不能写入新分支。
- 测试使用独立临时profile、工作区与合成模型，不能读取用户凭据或产生真实供应商费用。浏览器、Electron、真实供应商与Windows证据分别报告。

### Acceptance Criteria

- AC-01 / M3.1：可查看生效AGENTS来源和内容；按优先级用于模型请求，修改下一Run生效；越界/敏感目标和超限拒绝。
- AC-02 / M3.2：输入栏添加、预览、移除文本/图片/PDF；文件片段引用保留宿主API与历史预览，按用户调整不再提供添加入口。发送/排队/刷新/重启/历史分支保留，模型能力不匹配和非法上传明确失败；菜单MCP/Skill仅禁用占位。
- AC-03 / M3.3：显示估算用量/窗口/输出预留/裁剪情况；请求不超预算，工具对完整，最新输入超限时明确提示。
- AC-04 / M3.4：手动和自动摘要可见且可重放；保留近期消息，失败/取消不丢历史，分支不引用未来摘要。
- AC-05 / M3.5：模型可提问，用户可选项或自由回答，停止与重启结束等待，重复/错会话回答拒绝；普通无工作区对话可用。
- AC-06 / M3.6：计划和Todos可创建/编辑/完成且持久化；Plan与执行切换明确，Plan不能进行本地修改或命令，确认不替代审批。
- AC-07 / M3.7：创建检查点、对比、恢复与工作状态重置有实际效果；历史保留、分支隔离、队列不误执行、无文件回滚承诺。
- AC-08 / M3.8：旧数据库迁移、停止/刷新/重启及M1/M2关键流程回归通过；静态、构建、浏览器和本机桌面验证如实记录。

## UseCase

- UC-01 为工作区准备AGENTS，附带文件提问，查看生效规则；改规则后下一Run读取新版本，旧Run内容保持原样。
- UC-02 在浏览器或桌面上传图片/文本/PDF；菜单仅有上传与禁用的MCP/Skill占位。移除草稿附件不删除历史附件，刷新后可预览已发送材料及已有文件引用。
- UC-03 长对话达到阈值自动压缩，也可停止后手动压缩；失败后仍可阅读全部历史，超大最新输入被拒绝而不发送残缺内容。
- UC-04 无工作区的Agent提出选项问题，用户回答后继续；取消、停止或重启后待答问题显示结束，不隐式重发请求。
- UC-05 切Plan模式，让Agent制定计划和Todos，用户调整/确认后执行；尝试写文件或Shell被明确拒绝。
- UC-06 停止后建立检查点，继续对话并修改计划，再对比和恢复检查点；原分支可读，文件保持现状。重置清空当前上下文和计划但保留历史。
- UC-07 两个客户端查看同一会话，其中一个切换分支，另一个提交旧计划编辑、压缩、恢复、重置或检查点创建；服务拒绝旧分支请求并保留当前分支状态。

## Issues

- 已解决：自动压缩重复应用历史锚点会丢失摘要前缀；锚点只应用一次，连续自动压缩及重置后再压缩都有回归。
- 已解决：冻结引用的源文件删除后，规则发现仍依赖源文件存在；引用正文保持冻结，仅检查仍存在的祖先目录和规则，不跟随替换链接。
- 已解决：停止发生在压缩排队、凭据解析或Run接受前时可能错过取消；所有者在入队前登记，停止/关闭贯通解析、准备及摘要信号，取消不接受新Run或覆盖旧摘要。
- 已解决：不同分支相同revision时，旧窗口命令可能写入新分支；工作接口同时核对预期分支与版本，读取与缓存也核对分支。
- 已解决：全量测试默认高并发时，真实ESLint编译面冷启动超过10秒；隔离运行36项通过，根Vitest限制4个worker后全量639项通过，未放宽断言和超时。
