# 工具目录与按需加载设计

本页对应[Spec](spec.md)。2026-11-03按用户确认设计完成实现与本机验证，实际证据和未验证范围见[verify](verify.md)。

## 1. 设计取舍

工具是否有独立职责、是否应由模型调用、是否应在每次请求声明，是三个分别判断的问题。保留必要能力，通过删除重复入口和渐进声明减少选择负担；不为了接近其他项目的工具数量，把不同事务合并为通用action接口。

采用少量默认工具、统一候选、模型主动发现、下一请求生效和变化入日志的方式。动态可见集合按Run管理，沿用本项目的执行/授权拥有者；不照搬其他产品的Session生命周期或插件运行时。

Skill保留标准Markdown文件包和摘要目录，宿主负责内容快照、插件绑定及资源读取。Skill不是可执行工具，读取其正文不扩大执行权限；需要搜索Skill时应保持独立语义，本轮因已有完整摘要而移除搜索入口，不并入`tool_search`。

## 2. 工具清单

### 移除的6个模型入口

| 工具                         | 处理                                      | 理由                                                                 |
| ---------------------------- | ----------------------------------------- | -------------------------------------------------------------------- |
| `load_tools`                 | 删除模型入口，内部仍有按名字暂存/激活方法 | `tool_search`自动加载，精确工具名也可作为query，不再要求模型二次加载 |
| `skill_search`               | 删除                                      | 已提供全部启用摘要，当前子串搜索未提供必要新能力                     |
| `request_skill_tools`        | 删除专用审批、grant状态和事件链           | 发现/加载与真实执行审批已有拥有者，Skill不需要额外权限状态           |
| `revoke_skill_tools`         | 连同对应撤销/停止分支删除                 | 移除上一项的配套流程，真实插件/MCP撤销与停止保持                     |
| `restore_context_checkpoint` | 仅撤去模型入口                            | 选择/放弃上下文由用户命令和API拥有，原内部能力保留                   |
| `reset_working_state`        | 仅撤去模型入口                            | 避免模型自主清空工作状态，用户重置能力保留                           |

删除范围覆盖定义、执行分支、特殊审批、事件/schema/投影消费者、UI映射、角色名单、提示、插件资源及对应旧测试。通用工具历史仍按真实事实展示，不新增旧名字可调用别名；不借清理删除插件授权、凭据、MCP信任或真实角色限制。

### 保留的28个模型工具

| 职责       | 数量 | 工具                                                                                                           | 默认策略                              |
| ---------- | ---- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 基础执行   | 7    | `read_file`、`list_files`、`search_files`、`write_file`、`edit_file`、`shell`、`web_fetch`                     | 当前能力可用时默认                    |
| 人工交互   | 1    | `ask_user`                                                                                                     | 默认                                  |
| 工具发现   | 1    | `tool_search`                                                                                                  | 默认，独立于MCP开关                   |
| 委派闭环   | 2    | `spawn_agent`、`wait_agents`                                                                                   | 启用委派且当前任务可使用时默认        |
| Skill正文  | 1    | `load_skill`                                                                                                   | 存在可用Skill摘要时默认               |
| Office     | 7    | `office_inspect`、`office_docx`、`office_pdf`、`office_xlsx`、`office_pptx`、`pdf_read_pages`、`office_render` | 按需，可由有效Skill依赖预选           |
| 计划与清单 | 3    | `update_plan`、`update_plan_steps`、`update_todos`                                                             | 按需；当前工作状态所需入口直接提供    |
| 历史与结果 | 2    | `search_session_history`、`read_tool_result`                                                                   | 按需；已裁剪结果的reader直接提供      |
| Skill资源  | 1    | `read_skill_resource`                                                                                          | 按需；已激活Skill有资源引用时直接提供 |
| Agent控制  | 3    | `get_agent_status`、`send_agent_message`、`stop_agent`                                                         | 按需；子任务初始直接提供父通信入口    |

普通有工作区根Run在无额外状态/选择时为11项，有Skill摘要时为12项，其余16项为按需定义。无工作区时去掉6个文件/Shell工具，对应5或6项；Office也不能作为可加载候选。关闭Agent、角色/深度限制、WorkRuntime不可用及平台能力限制继续决定实际可用集合，不声明当前根本无法执行的工具。

显式MCP选择、有效Skill依赖、已有Plan/Todos和子任务继承可能增加初始声明；数量是观察结果，不是硬性指标。创建和等待一起默认，避免为了收集刚委派的任务再搜索；正文loader随目录提供，避免先搜已知loader再读Skill。

spawn与wait分别按能力判断：深度限制关闭继续spawn，不连带关闭等待和收集已有后代；不使用一个共用开关把整组入口一并移除。

Office保留结构化执行、依赖检测、文件策略及产物处理，不替换为任意Shell脚本。三个Plan/Todo接口分别拥有提审暂停、已批准步骤更新和完成证据，不能合成丢失这些约束的泛用操作。`get_agent_status`读取最新状态，`wait_agents`等待所捕获的后代执行；timeout为0也不视为同一接口。

## 3. 发现与加载

宿主统一收集具备真实执行入口的原生和MCP候选。原生定义继续由execution、work、agents和capabilities各自拥有；目录通过引用组合，不复制schema。每项记录原生执行族、真实session/workspace来源及default/on-demand策略。MCP使用既有冻结绑定，不伪装为原生工具。

工作区、角色、开关和有效授权过滤先于检索及结果计数。没有工作区、不能写的子角色或已撤销的外部能力，不作为可发现候选返回；隐藏声明不等于允许搜索获取。

`tool_search({query, limit?})`保留现有入口，检索本Run的候选及相关已加载项，返回每项名称、简短用途和“已可用/下一请求可用”。精确名称优先；已加载命中不重复激活，不重复写加载事件。命中新增工具后直接暂存，没有后续`load_tools`步骤。

沿用现有词法与可选本地语义检索，不新增检索依赖或默认收费推理。MCP无服务、关闭或目录失败时，内置候选依然可搜；远程目录诊断单独说明，零命中不能被描述成OAuth断连或权限证明。

上下文只保留原生能力组的一句话说明和相关名字、MCP服务摘要，以及Skill名称/简介/ID。参数schema只随激活声明，不将全部schema搬进文字目录。Skill目录与Tool索引保持各自类型，不建立通用能力搜索框架。

## 4. 生命周期

```text
Run接受：冻结获准候选与默认集合
    ↓
模型调用tool_search：暂存命中
    ↓
下一请求准备：合并必要依赖 → 提交run.tools_loaded
    ↓
使用同一工具集合组装执行入口、schema和上下文预算
    ↓
本Run继续：保留已加载项，新增仍按相同步骤提交
    ↓
完成/失败/取消：释放本Run资源；新Run重新选择
```

一次模型请求不是一个Run。运行中转向/队列输入若仍属于当前Run，继续使用本Run集合。上下文压缩不会清除运行集合；历史正文中出现某工具名也不会自动恢复可调用权限。

同一assistant消息中的工具调用使用同一声明快照。即便搜索先执行完，该批其他调用也不能立即调用刚发现的工具；下一次模型请求才获得完整参数声明和执行入口。

新顶层Run根据当前环境、显式选择及有效Skill重新构建，不复制上一Run所有动态工具。连接/目录缓存可以复用，但不是激活状态或授权租约。恢复历史只恢复事实，不自动执行旧调用；失效绑定按原撤销/停止机制处理。

## 5. Skill接口收敛

建议模型调用简化为`load_skill({id})`。模型不负责复述64位内容hash；宿主在Run接受时记录Skill候选元数据，包含ID、名称/简介、预期内容hash和来源/绑定依据，并据此生成摘要。该记录不是预加载全部正文。

候选元数据使用明确结构进入既有接受快照，不能解析systemPrompt文本反查绑定，也不能误用只包含已激活正文的现有`skills`字段。内部SkillSelection、FrozenSkill、资源hash与真实授权字段继续保留；加载策略和模型摘要不再重复携带无用校验细节。

调用loader时，从本Run候选解析预期内容，对比当前启用状态、skillEpoch、pluginEpoch及pluginGeneration等绑定身份，再冻结正文与资源。首次加载前文件变化、目录替换或授权失效明确返回原因；插件同内容重装也不能只凭相同hash接受新绑定。已激活正文继续使用原快照，源文件后续编辑不自动替换它，授权撤销仍按原规则生效。同Run显式新增选择沿原输入接受链绑定；不能替换已激活Skill的正文版本。

候选目录仅保留元数据，不为所有候选创建正文快照或持有活动租约；实际激活后才retain对应绑定，按Run释放。

运行中显式输入先保存完整队列绑定，消费时将queue.consumed与用户消息同批提交后再stage Skill，下一请求推进加载；未消费输入被删除或编辑移除时没有待发布正文。目录服务存在但当前没有Skill时仍保留资源reader候选，后续显式新增Skill可以读取资源。

正文和资源索引按原机制记录并进入后续上下文，继承/压缩继续遵守现有有效绑定规则。`read_skill_resource({skillId,path})`保留相对路径、快照索引、hash/大小和类型检查，不扩大workspace read_file范围。已激活Skill的附加资源索引非空时直接激活reader，不解析Markdown猜测哪些链接算引用，避免模型为已知资源入口再搜索。

Skill声明的工具依赖只是加载提示；只在本Run已经获准的候选内解析，不能由文件内容新增授权。现有Office依赖可继续预选，任意MCP/写操作仍走工具发现及真实执行审批。删除专用grant/revoke后，不用其他名字恢复一套同类状态。

## 6. 已知依赖直接可达

只根据宿主已经确认的状态补齐入口，不分析用户文字猜测任务类型，不为所有工具建立通用依赖图。

| 已确认状态                       | 请求前确保可用                               | 拥有者                                 |
| -------------------------------- | -------------------------------------------- | -------------------------------------- |
| 当前已有待修订/有效Plan          | `update_plan`及符合状态的`update_plan_steps` | WorkRuntime提供状态，选择/请求准备落实 |
| 当前有Todos                      | `update_todos`                               | WorkRuntime                            |
| 已激活Skill的附加资源索引非空    | `read_skill_resource`                        | Skill加载/上下文拥有者                 |
| 当前请求包含可恢复的裁剪结果引用 | `read_tool_result`                           | 上下文请求准备                         |
| 子任务需要向父任务通信           | `send_agent_message`                         | 子Run初始选择                          |

长结果投影使用持久宿主工具记录ID，而非provider调用ID，直接给出reader参数和offset。只有确实保存了原文字段时才提供恢复引用；执行器本身未保留的输出不能承诺恢复。旧历史中未知位置继续通过按需`search_session_history`定位。

纯投影返回裁剪内容、来源引用和所需工具信息，不写日志或改capabilities。请求拥有者先完成必要工具激活和持久屏障，再按最终schema计算预算并发送；不能沿用“先advance、后发现裁剪”的顺序，让reader晚一请求出现。压缩后的再次投影复用相同规则，当前Run已激活项不撤回，不增加无界重试循环。

## 7. 主子任务

根Run和子Run复用相同候选及默认策略。子Run保留从父当前集合中继承可继承项的现有语义，但可见集合和未加载候选都先按角色筛选；补齐子任务所需默认入口后，不再无条件加入全部Agent控制工具。

子任务独立激活自己的工具，不反向修改父/兄弟。只读角色不能通过搜索获取写工具，MCP仍要求已有read-only授权依据。深度或开关不允许继续委派时，不提供无效spawn入口；等待/收集已有后代的能力独立判断。

续作是新Run：依据当时仍有效的父绑定、角色和显式输入重新选择，不复用旧Run的capabilities、可执行闭包或已释放租约。现有消息、任务ID、执行ID及通信事实继续由M5拥有。

## 8. 代码职责

| 模块                                    | 最终职责                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------- |
| execution/work/agents各自定义模块       | 工具schema和领域执行规则，唯一来源                                         |
| `tools/catalog.ts`                      | 组合原生定义、执行族及default/on-demand策略，提供唯一元数据查询            |
| `tools/selection.ts`                    | 根/子Run初始集合及候选选择，应用工作区、角色与已知状态规则                 |
| `tools/toolset.ts`                      | 冻结当前声明、来源和指纹，按名查找；不负责搜索或审批                       |
| `capabilities/run.ts`                   | 本Run候选、暂存、当前集合推进与释放，不拥有工具副作用                      |
| `capabilities/search.ts`                | 复用检索/排序，输入获准目录，不自行扩展授权                                |
| Skill service及`capabilities/skills.ts` | 候选绑定、正文/资源激活、插件有效性和租约；与工具激活职责分开              |
| `tools/runtime.ts`、`families.ts`       | 原始参数、审批、领域派发和结果记录；路由消费同一目录，不再保留独立漂移名单 |
| context projection/request准备          | 纯内容投影、已知依赖需求、最终声明预算和请求输入                           |
| storage/protocol                        | 接受候选和加载事实的校验/回放，允许获准session/workspace/mcp来源的准确增量 |

仅在出现独立职责时拆文件，不创建空包装或注册器/路由器/目录各维护一份映射。`ToolRuntime.selectToolset`的选择职责迁至统一选择模块，执行器保留执行。Skill流程从run.ts移出时保留一个明确拥有者，不复制冻结和授权校验。

## 9. 数据与清理

沿用`run.accepted/run.tools_loaded`及实际请求快照表达已接受候选和模型实际采用集合；扩展原生候选为带真实source/fingerprint的记录，同步存储投影对新增session来源的校验。主子使用同一记录机制，不另加工具激活日志或修改消息粒度。

加载策略是宿主元数据，不进入供应商schema，也不为其新增公开事件字段。Skill候选hash和插件依据属于内部接受数据；模型只见选择所需信息。内部快照增补由原codec拥有，不添加旧名字兼容路由或第二套候选状态。

nativeCandidates只保存尚未声明的原生候选，初始声明由tools/toolSources记录一次；运行时目录合并两者以支持重复搜索。活跃Skill的模型投影只提供正文、ID、来源及资源路径/类型，完整hash和授权身份保留在私有事实中。

清理需要逐条追踪消费者，尤其是Skill grant/revoke事件、特殊审批与停止分支、角色白名单、系统说明、插件资源中旧工具名、UI映射和测试。用户检查点/重置端口及真实MCP授权继续保留；技术文档在实现完成后按实际职责同步，本草案不提前改写当前状态专题。

## 10. 实施顺序与评审重点

实施分为目录/候选及接受数据、入口与Skill流程收敛、请求准备及主子接入、回归与清理四段；不是只删除数组项。主要风险是来源投影、正文绑定和隐藏入口后任务链路是否仍可达，详细任务和可观察门槛见[Spec](spec.md)。

本轮不新增依赖、不改Pi loop、不重做消息、不进入M6。收益按普通问答、文件、Office/Skill和委派等场景实际请求的声明大小、token估算及额外发现往返记录，不把28/12当作质量证明。

建议Review重点：6项模型入口是否移除；默认spawn+wait及条件Skill loader；Run范围而非Session永久累积；Skill接口只传ID但保留宿主内容绑定；已知结果/资源/工作状态直接提供读取或更新入口。
