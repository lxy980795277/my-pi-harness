# 工具目录、按需加载与Skill接口治理

## Spec

状态：2026-11-03用户确认设计后完成实现、本机源码回归、构建与隔离浏览器验证，见[验证记录](verify.md)。工具治理提交后，用户授权直接删除阻塞启动的两份旧能力快照会话并重建索引，已完成实际profile恢复及daemon健康检查，详见验证记录的后续清理。完整机制见[详细设计](design.md)。

### Roadmap Alignment

属于M0工程治理及M3上下文工具、M4发现/Skill/Office、M5委派工具的既有能力维护，承接Pi 1.4升级后的工具治理讨论。M1–M5既有验收状态保持；M6记忆与搜索继续仅规划，不引入跨会话搜索、长期记忆或通用检索平台。

### Intent

减少重复模型入口和普通请求中不需要的工具声明，同时保持任务闭环、角色限制及执行审计。把工具定义、加载策略、单Run可见集合、执行审批和Skill正文管理分别交给明确拥有者，不以某个固定工具数量或文件行数为目标。

已将34个内置模型工具收敛为28个：移除6个模型入口；普通有工作区且启用委派的根Run初始提供11个，有可用Skill摘要时为12个。显式选择、已有工作状态、角色和资源依赖会影响实际集合，不将12视为上限或Token降幅。

### Constraints

- 用户已授权按本设计实现、验证与本地提交；不推送、不启动收费模型、不操作真实账号。工具治理阶段保留开发数据；后续用户明确授权直接删除阻塞启动的旧会话及清理索引，独立配置与授权保持。任务按实际进度更新，验证结束后创建verify。
- 保留Pi agent-core/ai、现有消息类型、Session/分支、完整消息落盘粒度及执行事件主链，不引入coding-agent会话体系、codemode/PTC或新插件框架。
- 工具注册、模型声明与执行授权分别管理。搜索或Skill加载不能赋予文件、网络、Shell、MCP或角色权限；人工/AI/完全访问继续由统一执行策略拥有。
- 原生工具保留真实session/workspace来源；MCP保留冻结定义、服务器与授权绑定。候选先按工作区、角色和能力可用性过滤，再参与检索。
- 工具加载变化必须先持久化，再用于请求声明、上下文预算及执行；同一assistant工具批次使用原声明快照，新增工具从下一模型请求生效。
- 动态工具在当前Run内只追加，Run结束后释放；新Run重新选择。插件撤销等授权失效仍按原执行/停止规则处理，不因集合只追加而继续执行。
- Skill继续采用文件包和渐进正文加载。模型接口只保留loader和受限资源读取，内容hash、来源及插件绑定由宿主解析、保留和校验，不将指令读取等同于授权。
- `restore_context_checkpoint/reset_working_state`仅撤去模型入口，保留既有用户命令、API、上下文与工作状态能力；其他保留工具不以通用action参数机械合并。
- 不保留被替代的名字别名、双轨候选表、专用Skill grant集合或废弃执行分支；同步清理受影响协议、投影、提示、界面、资源和测试。数据字段按实际语义变更，不借本轮重写消息或另加一套日志。

### Acceptance Criteria

- AC-01：内置模型定义为设计中的28项，删除的6项无可执行模型入口、无无效注册和新产生的废弃grant事件；用户检查点/重置API仍可用。
- AC-02：启用委派的普通有工作区根Run在无额外状态/选择时为11项，有可用Skill时为12项；Office、Plan、历史及非必备Agent控制默认不声明。无工作区不会通过搜索获得文件/Shell/Office能力。
- AC-03：`tool_search`覆盖获准的内置与MCP候选，MCP停用或失败不阻塞内置发现；精确名称优先，重复查询明确返回已可用，且不重复激活或写加载事件。
- AC-04：搜索新增工具在下一请求声明，本Run后续请求可继续使用；同批未知调用仍拒绝，不能依赖工具执行顺序绕过声明。
- AC-05：每次实际请求的schema、执行集合、来源/指纹、加载事实及预算一致；加载持久化失败时不发出使用新集合的请求。
- AC-06：新顶层Run不自动继承旧Run所有动态工具；压缩不丢当前Run集合；失败/取消/重启不重复派发历史副作用，相关租约按拥有者释放。
- AC-07：主任务可直接spawn并wait；深度限制不连带关闭收集已有后代的wait，子任务初始可向父通信。父已激活项和候选均先按子角色过滤，子加载不污染父/兄弟，续作不复用旧Run闭包或租约。
- AC-08：`load_skill({id})`使用接受时记录的候选hash/来源/授权代次加载，首次加载前正文变化或绑定失效明确拒绝，同内容插件重装也不得静默换绑定；显式输入仍走原接受链，同Run不能替换已激活正文。
- AC-09：Skill摘要不再携带要求模型复述的hash；完整正文和资源按需加载。资源reader只读已接受资源，原路径/hash/大小及绑定检查保留；工作区外Skill资源不扩大普通文件权限。
- AC-10：裁剪提示携带真实宿主工具记录ID，当前请求已提供reader，可直接分页；不能用provider调用ID、其他分支/任务的结果或执行输出中未保存的文字伪造可恢复内容。
- AC-11：当前Plan/Todos及Skill资源引用所要求的工具在同一请求可达，激活后再计入声明预算；纯上下文投影不写事件、不修改运行状态。
- AC-12：工具定义与路由策略有唯一来源；同一工具的schema、默认策略、子角色和候选来源没有多套漂移名单。权限、MCP unknown/取消、Plan审核及Todo证据规则回归保持。
- AC-13：记录代表场景实际声明数量、序列化大小、token估算和发现往返；不得用工具数量代替Token收益，普通读取不因隐藏已知loader/wait而增加搜索往返。
- AC-14：排队输入中的显式Skill在消息实际消费后才暂存激活；消费前编辑移除或删除输入不加载正文、不保留租约，也不导致会话持久化失败。

## UseCase

1. UC-01（AC-01–03、13）：有/无工作区的新会话普通问答，核对实际schema；输入准确工具名及同名重复搜索，区分已可用、新增和不可用，零MCP时仍可加载内置工具。
2. UC-02（AC-03–06）：搜索Office或远程工具，下一请求执行并连续使用；同批先search再调用未声明工具、加载事件写失败、授权撤销、取消和重启分别验证拒绝与释放。
3. UC-03（AC-08、09、11）：从Skill摘要加载正文及图片/文本资源；加载前修改文件、停用插件、同Run换正文、读取未登记/越界资源，均不能静默替代或越权。
4. UC-04（AC-05、10、11）：长结果进入裁剪，模型按宿主记录ID直接分页，无需搜索已知结果；中断结果、失败结果、无保留正文及错误分支/任务分别验证提示与范围。
5. UC-05（AC-07、12）：spawn、wait、父子通信、嵌套、停止及续作；只读子任务搜索写工具失败，子加载不改变父/兄弟，不能由factory补回全部控制工具。
6. UC-06（AC-01、11、12）：按需提交和修改Plan/Todos，审核后步骤更新可达；用户检查点选择和工作状态重置保持可用，模型不再提供这两个入口。

## Issues

- 现有延迟原生候选仅workspace来源，不能直接隐藏session工具后仍用旧`advance()`；否则新增来源被错误记录或投影拒绝。
- 当前Skill摘要已全部注入，`skill_search`仅名称/简介子串查询；专用grant集合不参与实际执行授权，重复审批与停止流程应整体移除。
- 当前裁剪要求先搜索宿主记录ID；隐藏history/reader而不修改提示和请求准备，会形成恢复断路。
- 当前子启动会补齐全部Agent工具；仅调整根默认数组无法真正收敛主子工具声明。
- 用户已确认设计；任务和AC仍按实际实现及验证更新，不能将设计确认解释为工程已完成。
- 独立审查发现受理队列即stage Skill会在删除/编辑未消费输入后残留待激活正文。改由RunInputDelivery在消费事实与用户消息同批提交后stage；存储只接受已消费队列的新增绑定，真实交错回归通过。
- 仅统计本地结构元数据：3份会话中2份含旧workspaceCandidates接受记录和加载事件。新校验不兼容该旧快照；本轮未删除、改写或重建原开发会话，新临时profile通过不代表旧数据恢复通过。
- 用户确认工具分类的后续优化留待下一迭代：业务类别、执行入口、工作区依赖与访问权限的命名和归属另行设计，本轮保留现有family/source分类。
- 后续实际启动在projectCapabilityLoad校验旧接受快照时触发INVALID_RECORD。用户允许直接删除旧数据后，持profile互斥锁删除两份阻塞JSONL并按外键顺序清空17张可重建投影表；正常回放保留的一份会话，21张独立配置表摘要一致。实际daemon临时端口启动及健康检查通过，未新增兼容分支。
