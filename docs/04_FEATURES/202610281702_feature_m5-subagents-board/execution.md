# M5 执行与数据设计

本轮设计已落地；当前机制由[子Agent技术设计](../../09_TECHNICAL/子Agent与任务看板设计.md)拥有，实际schema与接口见[任务协议](../../03_API/agents.md)。本页保留实施决策及阶段边界，范围和验收以[Spec](spec.md)为准，任务见[实施清单](tasks.md)。

## 已确认的实现决策

| 议题       | 结论                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 会话与任务 | 一个可见Session、一份JSONL；稳定Task与每次Pi执行的Run分开，不建隐藏Session或第二套循环                     |
| 关系与分支 | Task引用原委派工具，子Run引用Task；祖先、根和深度派生，按最外层委派消息锚点判断分支可见性                  |
| 独立上下文 | 只传任务与明确资料，复用作用域WorkRuntime；主、子及兄弟的消息、摘要、交互和队列不串用                      |
| 角色配置   | 新Task读取当前角色并冻结；根树预算不热换，新限制只可在父范围内收窄                                         |
| 并发与预算 | 名额约束真实模型请求，等待不占槽；根共享余额只在请求前预留，子额度作为上限而非二次扣款                     |
| 写入       | 同树唯一拥有者，全部在途写操作结算后沿父子转交；收束时归还仍有效祖先，不承诺外部事务或回滚                 |
| 等待与续作 | 等待冻结当时Run；续作创建新Run，必须由仍接受命令的直接父拥有，不能把旧结论用于失败的新执行                 |
| 通信来源   | 原消息先排队，消费与实际输入同批；agentMessageId关联持久来源，SDK正文明确为Agent资料，主聊天不冒充用户提问 |
| 结算与恢复 | 父终态前结算后代，资源join等待全部结果再传播失败；重启保留事实并中断，不自动重跑                           |
| 界面       | 固定会话入口、独立看板、按需详情；Query拥有事实，Zustand只保存展示及未提交草稿                             |
| 刷新       | 全局摘要SSE只通知结构/状态，忽略逐token变化；唯一活跃详情以500ms补文字，主聊天不随子delta重建              |

## 实施阶段

M5.1先完成单层只读闭环和最小页面入口，阶段内不开放无法操作的子人工等待。M5.2补齐并行、嵌套、通信、角色和预算；M5.3具备准确来源的提问/审核/审批入口后开放子人工交互，再完成恢复与故障收束。M5.4完善执行树和看板，M5.5覆盖全链路、回归与证据。

子Agent默认只有明确转交的资料。只读角色剔除Shell和未知写工具，动态加载与实际调用继续检查同一权限范围；新角色或嵌套不能扩大父工作区、审批策略及MCP/Skill授权。

父模型应先收集子结果再汇总。如果提前输出最终答案，运行时结算已有后代并保留未汇总结果，不自动额外调用主模型。收束拒绝新通信/续作，未消费消息明确结算，不留下永远无法继续的等待。

协议19加入任务和通信来源，SQLite schema9加入相关配置/投影；公开事件envelope和无版本的JSONL批次保持原职责。不为旧开发格式建立版本分支，本轮也不清理用户会话或配置。

## 后续范围

M5保留执行来源供M6决定记忆权限与学习材料，探索性输出不自动变为长期记忆。记忆存储、抽取和跨会话召回尚未实现，不预建空接口。M7继续拥有完整Trace、费用估算、文件撤销和包含附件/配置的完整导入导出。
