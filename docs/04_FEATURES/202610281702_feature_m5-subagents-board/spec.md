# M5 子 Agent 与任务看板

## Spec

状态：2026-10-28建立规划，2026-10-29完成M5.1–M5.5工程实现及macOS自动化验证，结果见[验证记录](verify.md)。真实Pi、临时存储、API及Chromium链路已验证；待用户体验验收，真实供应商、Electron和Windows实机验收尚未执行，不以工程检查代替。

2026-10-29补充审批继承修复：用户主对话为完全访问，调查子任务的网页GET仍等待人工批准。现实现将只读角色直接写成session.approvalMode=read-only，混淆能力限制和审批方式。本轮分离两个维度，子执行继承父执行的审批策略，只读角色的写限制继续由宿主执行，不以授予写权限来消除批准弹窗；范围仍属M5.2/M5.3维护。

### Roadmap Alignment

覆盖[roadmap](../../00_OVERVIEW/roadmap.md)的既有M5：角色与预算、执行树、嵌套委派、等待、通信、停止、独立上下文，以及任务看板的进度、待处理和人工确认。用户确认先做M5执行核心，再做M6；M5内部先验证真实委派链路，再完善并发协作和看板。

M1–M4的会话、模型、审批、工作区、上下文、MCP、Skills和插件能力继续复用。既有Windows Shell暂缓、Office视觉、真实服务账号和平台验收不迁入本里程碑。长期记忆和跨会话搜索属于M6，完整主子Trace、费用估算、文件撤销及完整导入导出属于M7；Computer Use继续排除。

### Intent

用户提出一个可拆分任务后，主Agent能委派具有独立上下文的子Agent执行，读取结果、补充要求或停止子树，并据真实结果汇总答复。用户能在会话执行树和任务看板看到任务归属、进度及人工等待，刷新页面后保持一致，停止或重启后不遗留无主执行。

### 已接受决定与设计结论

- 先实现单层只读委派的完整链路，再增加并行、嵌套、通信、预算和看板；阶段性闭环不等于整个M5完成。
- 使用一个可见Session、一份JSONL和一棵任务树。AgentTask表示稳定的委派任务，Run仍表示一次实际Pi执行，不创建隐藏Session或第二套Agent循环。
- 主、子上下文独立；只有明确传递的任务资料、通信和结果进入对方上下文，不默认复制整段历史。
- 父执行结束前必须结算所属子树。停止覆盖排队、启动准备、模型、工具及人工等待，重启只恢复事实，不自动执行。
- 任务事实来自daemon及日志投影。看板、执行树和聊天引用同一任务，不再维护另一份可修改的执行状态。
- M6只提前约定用户/工作区归属、任务可见范围、写入权限与来源保留，不预建未使用的记忆接口。

详细机制、拟新增协议和数据流见[执行与数据设计](execution.md)，模块归属、实施顺序及检查门槛见[实施任务](tasks.md)。

### Constraints

- 保留现有模块依赖：agent-runtime拥有任务编排和Pi执行，storage拥有持久化，daemon拥有HTTP/SSE与应用装配，Web负责呈现。没有独立外部Agent进程或通用分布式调度平台。
- 任务关系只保存必要事实：Task记录sourceToolCallId，复用委派工具记录推导父Run及消息锚点；子Run记录taskId。根、深度、父任务、当前Run及汇总状态由投影推导，不写成多份权威字段。
- 子任务只能使用父执行允许范围内的工作区、工具、MCP和Skills，不能借角色、通信、tool_search或嵌套委派扩大权限；用户配置的模型选择在接受前解析并冻结。
- 模型调用、工具审批、问题、计划审核和上下文压缩复用现有机制并增加准确任务作用域；主输入队列、分支、重置与检查点不能被子任务改变。
- 同一根任务树只允许一个写入拥有者；写角色显式取得并在结束时归还，其他任务在此期间只读。任意Shell和外部系统不承诺事务、文件隔离或自动回滚。
- JSONL先提交再发布；任务消息、通信消费和实际执行关联必须可重放。重启扫描全部未结算子Run，不能只处理session.activeRunId。
- token预算是请求前预留与实际Usage结算后的执行限制，不承诺供应商精确扣费硬上限。并发、任务总数、深度、轮数和时限由宿主执行约束。
- UI保持轻量工具行、既有过程折叠及虚拟滚动。子Agent输出不逐条插入主聊天，人工确认不能被折叠区域或关闭详情隐藏。
- 角色及执行限制由已校验配置拥有；不通过复制提示词、只限制前端选项或在模型输出中声明规则代替宿主执行。
- 审批策略继承已接受父Run的冻结选择，ask、auto、full-access分别沿用人工、独立AI复核及自动批准；角色access独立限制可用工具和实际参数。只读角色的网页GET可按父策略执行，但POST、文件写、Shell和未获只读授权的外部工具仍不得派发。嵌套、动态加载、Skill授权和显式续作不能恢复被上级排除的能力；request_skill_tools等明确要求人工确认的独立授权不被full-access跳过。
- 不为M5引入旧数据版本分支或兼容转发；需要调整协议和SQLite时同步消费者及文档。实际数据清理需要单独授权，本次规划不清理数据。

### Acceptance Criteria

- AC-01：主Agent可创建只读子任务，工具返回稳定任务ID；子Agent实际调用模型，主Agent收到有界结果后汇总，重复请求不重复启动。
- AC-02：子任务只收到声明的任务资料与获准能力。主、子及不同子任务的消息、摘要、Todos、问题、模型请求与输入队列不串用；主聊天不包含完整子转录。
- AC-03：同根任务树可并行和嵌套委派、查询、等待、通信及显式续作；祖先/循环等待、跨树命令、过期拥有者与超限操作被拒绝，满并发下等待不占住子任务名额。
- AC-04：角色/model配置可验证和冻结，子任务权限不超过父范围。写入拥有者由宿主约束，未经转交的并发文件修改、Shell及外部写工具不会派发。
- AC-05：任务数、深度、并发请求、轮数、耗时及token预算在实际执行入口生效；父子消耗归集无重复，超限有明确原因，终态和取消仍能完成持久记录。
- AC-06：通信先持久化再消费，消费与目标输入同批提交；运行中补充不覆盖当前输入，续作创建新Run，失败或重启不把旧消息重复执行。
- AC-07：停止子任务只影响其子树，停止根任务覆盖全部后代；重复停止幂等并等待资源真正结算，父执行终态之后没有活动后代。
- AC-08：子任务的提问、计划审核和工具审批显示准确来源，可在统一待处理入口完成；提交只继续原等待，关闭详情、过程折叠或刷新不丢表单，旧回答拒绝。
- AC-09：仅由JSONL重建投影可恢复任务关系、通信、历史和已完成结果。daemon重启中断全部在途执行及等待，不自动调用模型或工具；持久化失败停止所属树，unknown不能被父任务当成功或自动重试。
- AC-10：执行树、看板和详情显示真实状态及来源，区分排队、执行、等待子任务、人工等待与终态；有明确任务分母才显示完成数，不推测token百分比。详情按需分页，主聊天滚动位置和表单状态稳定。
- AC-11：Web与Electron使用同一业务API；浅/深主题、窄屏、键盘、SSE重连、目标切换和迟到响应正确。普通测试不使用真实账户或用户profile，真实供应商和平台分别登记证据。
- AC-12：完全访问主Run委派调查子任务执行网页GET时，无额外人工批准；ask和auto子执行分别保留原审批/复核方式，写角色也沿用父策略。只读角色的POST、文件写、Shell及越权外部调用在真实派发前拒绝，人工批准或角色切换不能绕过；嵌套、动态加载和原Task续作保持相同约束。实际Run接受审计保存继承的审批方式，角色限制仍由既有Task事实拥有，不新增重复持久状态。

## UseCase

### UC-01 单层委派与汇总（AC-01、02）

前置：主会话可调用受控模型，已启用只读角色。操作：主Agent委派资料核对任务，子Agent读取允许范围内的文件并返回结论，主Agent等待后汇总。预期：各自上下文独立，任务和结果可在界面与日志定位。异常：重复委派命令返回既有任务；模型准备失败保留失败原因，不伪造完成。

### UC-02 并行与嵌套（AC-03、05）

前置：允许多任务和有限深度。操作：主任务并行委派两个任务，其中一个再委派后代并等待。预期：执行不超过并发限制，等待释放执行名额，父子正确回收。异常：任务总量/深度超限、祖先等待和跨树ID明确拒绝。

### UC-03 通信与续作（AC-03、06）

前置：根执行和直接父Run仍接受子命令，有执行中及已完成子任务。操作：给执行中的子任务补充资料；对已完成任务显式请求续作。预期：前者持久排队并在安全边界消费，后者使用同任务上下文创建新Run。异常：直接父Run已结束/收束、目标已关闭、重复消息或旧客户端命令不会复活旧Run。

### UC-04 角色、模型及权限（AC-02、04）

前置：配置只读和执行角色、不同模型，以及有限MCP/Skill范围。操作：分别委派并在等待期间修改设置或撤销权限。预期：已接受任务使用冻结选择，下一任务才读取新配置；撤销及时生效。异常：子任务请求更大工作区、禁用工具或未获准MCP被拒绝，不静默回退到更高权限模型/角色。

### UC-05 写入协调（AC-04）

前置：一个子任务已取得同树写入拥有权。操作：另一个子任务和主Agent尝试修改文件、执行Shell或调用外部写工具，随后原写任务结束。预期：前述写入不派发，拥有者结束后才可显式转交；只读任务仍可工作。异常：未知工具按可能写入处理，文件被树外程序修改时不声称隔离或回滚。

### UC-06 预算耗尽（AC-05）

前置：设置低轮数、耗时和token预算。操作：多个子任务同时请求额度，包含缺少Usage的受控响应。预期：宿主原子预留，不能重复分配同一额度；超限停止新模型请求，保留实际Usage及缺失说明。异常：不能因计量不完整报出精确费用或跳过终态记录。

### UC-07 子问题与审批（AC-08）

前置：两个子任务分别等待用户回答和工具批准。操作：关闭详情或折叠过程，从待处理入口回答/批准。预期：来源准确，原Run继续，其他任务不误收答案。异常：重复提交、错任务、错分支及已取消的等待被拒绝，批准计划不授予工具权限。

### UC-08 停止与父执行结束（AC-07、09）

前置：子树分别处于排队、模型准备、工具运行和人工等待。操作：先停止一个子树，再停止根执行；另测父模型提前输出最终回答。预期：停止作用域正确并等待真正结算；父任务先结算后代才写终态。异常：重复停止不重复结束，unknown停止所属树且不自动重试。

### UC-09 断线、重启与重建（AC-06、09）

前置：保存已完成子任务、待消费通信和活动子任务。操作：断开SSE并重连，重启临时daemon，再由JSONL重建投影。预期：顺序与归属一致，已完成结果保留，在途任务中断，未消费通信不自动启动模型。异常：损坏关系和缺失必要事实明确失败，不用SQLite反向补日志。

### UC-10 看板、详情与阅读（AC-10、11）

前置：存在并行子流及多条人工等待。操作：在主聊天阅读旧消息，打开任务树，切换详情及看板筛选，在窄屏关闭再打开。预期：子流不推动主滚动、不自动改变聊天宽度，表单保持，旧响应不覆盖新任务；来源和终态一致。异常：断线只改变连接提示，不把执行标成成功或失败。

### UC-11 审批继承与只读能力（AC-04、08、12）

前置：主对话分别选择full-access、ask、auto，配置只读调查及写入角色。操作：委派子任务获取受控网页GET，再尝试POST、只读授权外部工具、动态Skill工具、嵌套委派和原Task续作。预期：允许的读取遵循父审批方式，只读角色不额外降为人工模式；禁止的副作用在批准或派发之前拒绝，失效授权仍拒绝。修改全局角色不改变既有Task的冻结角色，重启中断历史等待，不重发副作用。

## Issues

规划期识别的Session唯一活跃执行、分支WorkState及恢复路径已统一增加Task作用域。根会话仍保持一个活跃根Run，子执行拥有独立上下文和结算责任；实际行为、修复和验收边界见[验证记录](verify.md)。

审批继承及动态能力回归同时复现工具指纹漂移：从已冻结records重建RunToolset时，旧fingerprint被错误计入新的哈希，后续load_skill提交被存储拒绝。构造器统一只选择definition/source/external后冻结和计算，advance复用该归一入口，删除调用方重复清理及占位指纹；既有持久记录不重算或改写。
