# 回答过程自动折叠

## Spec

### Roadmap Alignment

本轮属于既有对话渲染交互与M4收尾，沿用[roadmap](../../00_OVERVIEW/roadmap.md)现有能力，不进入M5。仅改变Renderer呈现，不改模型、协议、持久化或执行授权。

### Intent

回答生成中正常展示思考、工具及中间说明。完整回答结束后将过程合成默认收起的“已处理＋耗时＋箭头”，正式回答及原回答操作/统计留在外面，点击可展开完整过程；内部工具保留现有单项折叠。

### Constraints

- 参考已确认的交互与工程范式，独立实现，不复制参考项目业务代码。
- 按用户输入轮次划分过程，不能只按runId，因为同Run可处理多个排队输入；消息完成不等于整轮回答完成。
- 最后一步思考进入过程，正式正文独立展示；无过程时不新增空折叠行，无正式答案时不把toolUse前言冒充最终回答。
- 活动、待批准、提问、计划审核及停止/异常的部分结果不得被成功折叠逻辑隐藏。成功完成的历史轮次可折叠，同Run后续输入保持活动展示。
- 保留TanStack Virtual、稳定key、directDomUpdates与动态测高。收起时过程内容真正不渲染，不保留原平铺行的虚拟占位；尊重减少动效，不引入高度动画。
- 展开选择由timeline Store按session/input拥有，跨虚拟卸载保留，注销清理沿用现有reset。Query/日志不保存展示选择。
- 保留用户对message-timeline行容器移除pb-0.5的现有改动及上一轮未提交OAuth修复，不回退、暂存或提交无关修改。

### Acceptance Criteria

- AC1：有过程的成功回答结束后显示一条默认收起的已处理摘要，思考、中间正文及工具在内，正式正文和原整答操作/统计在外。
- AC2：点击、键盘可展开/收起过程，内部工具仍可独立查看，展开选择跨虚拟卸载及切换会话保留，不跨输入串用。
- AC3：活动Run、待审批、同Run排队后续输入、纯文本回答、停止/失败/未知结果及分支继承保持正确可见性，不隐藏待处理交互或丢失正文。
- AC4：展开/收起由虚拟库动态测高，底部跟随及用户上滚阅读保持，长列表首尾可访问，不引入人工虚拟高度或额外滚动条。
- AC5：纯分组与展示状态回归、类型/静态、真实构建浏览器场景通过，验证记录说明实际观察及未覆盖边界。

## UseCase

- UC1：发送含多个工具轮和最后思考的任务，运行时可观察过程；结束后只见摘要、最终正文及回答操作，展开可恢复全部过程并查看单工具。
- UC2：展开历史过程，滚出虚拟视区或切到另一会话再回来，保留该输入的展开选择；其他输入仍默认收起。
- UC3：工具等待批准或用户停止/异常退出时，仍能看到相关操作、状态和部分内容；纯文本回答不产生空摘要。
- UC4：同Run先完成一个输入再处理队列输入，已完成轮与活动轮互不混合；分支继承不误用另一分支Run结束状态。
- UC5：在长列表、底部跟随和上滚阅读下切换过程开合，虚拟行高度更新且无残留空占位；重新展开不重复模型或工具请求。

## Issues

真实浏览器验证发现，展开时继续贴底会移动摘要，普通阅读时切换start锚定会丢失条目数量变化后的定位，结束时才拆出最后思考会改变正文行内部高度。现在分别通过显式开合暂停跟随、普通阅读保留库的稳定key定位，以及从生成期间就拆分思考/正文解决；未使用固定高度或人工补偿虚拟尺寸。断言和实际覆盖见verify，不据端点采样声称所有浏览器呈现帧无抖动。
