### Roadmap Alignment

复核沿用M3.1–M3.8与存储前置重构的既有范围，明确功能实现、自动化证据和用户体验验收的区别。Windows Shell、浏览器新增工作区继续归M2且已由用户暂缓；真实账号、其他平台与发布验收不冒充已完成。技术沉淀覆盖M1–M3，属于工程维护，不新增里程碑。

### Intent

确认进入M4前M3是否存在功能遗漏，让开发者通过少量关键设计文档理解系统如何运行、状态由谁拥有、失败如何恢复及哪些能力仍未实现。

- AC-01：逐M3子模块审查实现、测试和验收证据，给出完成结论及真实保留项，修正过期状态，不将M2/M4范围混入M3。
- AC-02：四篇旧文档删除，09定位与根README/AGENTS、总览、关联链接同步，无死链或失效维护要求。
- AC-03：五篇核心设计有实际问题、架构/数据流、状态来源、关键机制、失败处理、取舍和实现锚点；正文与源码一致，无未实现功能冒充完成。
- AC-04：检查文档彼此及01/03/05的职责，无依赖清单、历史流水或同一事实多份维护；核心机制可按场景独立阅读。
- AC-05：实际文档与格式检查通过，验证记录区分本轮复核与此前执行的测试；不自动提交或开始M4。

## UseCase

- UC-01 从roadmap确认M3各部分已实现哪些行为、证据在哪里、哪些体验和平台还需验证。
- UC-02 新开发者从09总览进入系统图，再沿Agent、上下文、存储或执行文档定位源码，能解释一次请求从输入到持久化/流式更新的路径。
- UC-03 调查断线、重启、摘要失败、工具取消或审批等待，能找到对应状态所有者、恢复方式与限制，不将断线当作取消或检查点当作磁盘回滚。
- UC-04 后续M4设计根据已有扩展位置衔接能力，不依赖被删的历史选型/版本页，不把文档中的未来范围当作实现。
