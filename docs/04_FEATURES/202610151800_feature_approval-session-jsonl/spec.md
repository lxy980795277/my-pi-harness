# 审批模式与会话JSONL镜像

## Spec

状态：初轮及Select焦点、JSONL隐藏目录调整、开发/正式统一仓库日志根均已实现并完成macOS本机验证，证据见[verify](verify.md)。属于既有M2工具权限与M3会话持久化的后续优化；M4 MCP/Skill能力仍未实现，本次只保留已有占位，不启动完整M4。按照[roadmap](../../00_OVERVIEW/roadmap.md)维护范围，不自动commit或push。

### Roadmap Alignment

M2新增请求批准/帮我批准/完全访问三种可选策略；旧read-only记录保持原限制。M3新增每会话JSONL持续镜像，提前完成M7日志输出的一部分，不声明JSONL导入、完整独立备份或M7已完成。用户要求“同时保存JSONL”取代旧后端约束中仅显式导出的限制；SQLite仍是唯一恢复事实来源。

### Intent

权限菜单与参考图一致，图标、标题、说明、勾选与警示色清晰；菜单选择具有对应的真实执行行为。每个会话自动保存可阅读、顺序稳定的JSONL日志，包含已有历史与后续事件。

### Constraints

- 前端新对话默认full-access，客户端重置后恢复该默认值；用户手动选择仍沿用当前偏好。菜单依次为“请求批准”“帮我批准”“完全访问权限”；已有会话沿用保存的权限，旧read-only继续由服务识别，界面能准确展示其当前状态。
- ask沿用逐次审批；auto由独立模型请求复核需要批准的调用，复用当前会话模型配置但没有执行工具、审批权限或可修改的共享对话状态。只接受明确结构化allow/deny/ask；失败/未知结果转人工，不失败放行。取消、超时与模型lease必须结算。
- full-access跳过人工/AI审批，并在受支持macOS命令执行中明确取消OS沙箱；用户直接选择此模式构成后续Run的授权。仍保留工具参数、已注册工作区、Plan模式、所属进程组回收、超时与输出上限；脱离进程组的恶意后代不在现有保证内，不声称完整进程树回收；不通过该模式隐式实现Windows Shell。文件工具继续以工作区为根，Shell拥有宿主用户权限；不进行系统提权。
- 会话策略在Run接受时冻结。Plan模式仍禁止变更与命令，不能被full-access绕过。临时模型结果、错误、第三方内容不改变权限。
- AI复核记录请求、决定、理由和执行者来源；私有复核输入不暴露给HTTP/SSE，工具卡能区分AI/用户/完整访问批准。MCP尚未实现，不显示已具备MCP执行能力的结果。
- wire提升7，兼容读取旧ask/read-only事件；只追加必要迁移，不改既有迁移1–5。新审批审计字段可选，历史记录不重写。
- JSONL默认按隐藏数据目录组织：开发和正式运行统一使用仓库根目录的`.my-pi-harness`，自定义SQLite profile不改变默认日志根，任意启动cwd也不改变仓库归属；不同SQLite profile的镜像分别隔离，测试通过显式日志根保持临时目录隔离。独立安装包已脱离源码仓库，须以现有`MY_PI_HARNESS_SESSION_LOG_ROOT`指定仓库中的日志目录，缺失时明确报错。仅调整JSONL，SQLite、系统凭据引用和桌面授权保持原位置；新位置从SQLite补齐历史，旧日志不删除。包含已提交公开HarnessEvent，按seq递增，稳定ID与会话归属保持一致；privateData/模型私有codec与附件字节不进入JSONL。
- SQLite先提交事务，之后顺序追加JSONL；没有跨文件与数据库的原子承诺。文件失败显式报告、数据库事实不撤销，调用不得被误当未执行而重复；下次启动按SQLite补齐缺失日志/崩溃末行。JSONL不作为竞争恢复来源，不提供本轮导入能力。
- 旧会话包括归档历史在启动时补齐。拒绝路径穿越、符号/硬链接或目录替换造成的越界写入，日志私有文件权限；回滚事务不产生日志，重复请求不重复行，关闭不遗留写入任务。
- 前端使用现有shadcn及语义颜色，图标尺寸统一，TSX只布局与绑定。共享SelectTrigger不使用聚焦边框/光圈，以背景提供焦点反馈，保留Radix关闭后回焦和键盘操作；输入容器的聚焦边框仅由文本输入触发，不由底部选择器触发。
- 隐藏JSONL目录在开发仓库中由Git忽略，并从文件工具、工作区引用及默认沙箱Shell中排除；完整访问Shell仍按用户明确选择拥有宿主权限。日志根必须是末级名称固定为`.my-pi-harness`的绝对目录，以统一路径保护；其下按canonical profile路径的完整SHA-256隔离镜像，避免不同profile竞争同一会话文件。

### Acceptance Criteria

- AC-01：三个菜单项有独立图标、说明与选中勾号，完全访问使用警示色，新会话与已有会话一致；旧只读状态显示准确且不提升权限。
- AC-02：auto工具复核允许/拒绝/转人工有实际效果，失败/无效响应转人工，停止取消复核，独立请求不污染主会话上下文并记录审计。
- AC-03：full-access无需审批，命令实际可访问沙箱外的受控测试文件；ask/auto仍隔离且无自动回退，Plan与取消/超时/回收不回归，Windows限制保持。
- AC-04：新建、流式消息、工具、队列、分支、工作状态和归档事件同步写入各自JSONL；已有历史补齐、事务失败不产生日志、重复/重启不重复、崩溃末行可修复、非法文件拒绝。
- AC-05：静态、相关源码行为、真实构建daemon重启与浏览器菜单/审批链路验证通过；明确JSONL不是含私有codec和附件内容的独立可恢复备份。
- AC-06：鼠标选择关闭后焦点仍返回触发器，但选择器及输入外框不出现额外聚焦边框；键盘选择和可见背景反馈仍可用。
- AC-07：开发/正式源码及构建产物均解析到仓库根，安装包要求显式日志根，测试显式隔离；新旧历史补齐、不同profile隔离及隐藏目录的工具保护有实际验证；不迁移数据库或自动删除旧日志。

## UseCase

- UC-01 新对话打开权限菜单，选择三种策略并发送；同一Run使用接受时策略，界面名称与说明一致。旧只读会话依然阻止变更。
- UC-02 auto模式请求修改/命令，独立AI确认与用户意图一致后执行；拒绝不执行，需要用户决定或模型失败时展示现有审批卡，停止不遗留等待。
- UC-03 明确选择完整访问，运行受控命令读取工作区外测试文件；在ask/auto中同命令继续受沙箱限制。取消仍回收所属进程，Plan中均禁止命令。
- UC-04 创建会话、对话与分支后检查JSONL；重启或删除镜像后按SQLite补齐；损坏末行、模拟写失败/事务回滚和重复请求均不改变已提交事实或重复执行工具。

## Issues

独立复核没有工具但仍可能收到供应商返回的toolCall；Pi默认循环会据此继续请求。现明确只允许一轮复核，非正常文本终态转人工，回归检查不接受第二轮allow。模型失败不吞存储审计失败，已提交数据库后的JSONL错误通过独立503明确提示，避免误当未执行而重试。

启动已创建镜像后，恢复阶段失败也必须关闭镜像目录fd、数据库及profile锁；已统一调用store.close，并用fsync故障与损坏投影验证fd关闭和可重新打开profile。
