# M7 执行可观测、数据恢复与产品验收

## Spec

状态：2026-11-14基于191192d、产品0.21.0、公开协议29、SQLite16完成方案规划，用户已授权按M7.1至M7.5顺序开发、逐节验证。M7功能实现、治理、本机工程检查及真实任务执行已收口，内容质量和平台发布条件未全部通过，实际证据见[验证记录](verify.md)。当前实现和缺口的依据、模块分工见[设计](design.md)，开发顺序与阶段门槛见[任务](tasks.md)。

### Roadmap Alignment

对应[路线图](../../00_OVERVIEW/roadmap.md)的M7完整对齐验收。交付主子任务Trace、最终请求查看、统一用量及费用估算、文件撤销重做、完整会话归档与恢复，以及M1–M6当前实现的真实任务和发布候选验收。

M7沿用现有Pi1.4、tools、plugins、sandbox、memory与storage分工。Windows Shell继续归属用户暂缓的M2.3，Computer Use属于后续专项。原M4真实账号与办公质量、M5平台、M6真实学习行为等缺口在M7验收矩阵中逐项核对，结果仍标明原能力归属。

### Intent

用户能知道一次回答经历了哪些主子请求、工具和等待，看到最终提交给模型的内容及准确的失败位置；能区分已记录用量、未知部分和费用估算；能安全撤销原生文件工具的修改，并把一次会话连同其必要资源迁移到新环境继续使用。开发和发布结论由当前候选版本的实际证据支撑。

| ----------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |

| M7.3 文件变更历史 | 查看原生文件工具的变更，逐项或按回答撤销、重做，冲突时保留当前文件                   | 原始字节可恢复，操作可追溯，取消、崩溃和并发均有明确结果                   |

轨迹入口放在对话header，与现有任务、日志入口协调；阅读轨迹不挤占对话正文，也不修改当前执行分支。轨迹页提供主子树导航、时间线与详情，宽屏并排，窄屏逐级返回。默认显示摘要，正文和图片按需加载。已有回答下方的用量与时间保持简洁，详细拆分进入用量视图。

文件变更入口从轨迹中的文件工具和会话变更列表进入。撤销操作显示准确路径、来源和可操作状态；按回答撤销以逆序逐项执行，展示成功、冲突及未执行项。完整归档与原始JSONL下载在同一日志入口区分说明。

### Constraints

- JSONL继续保存已提交事实，SQLite保存可重建的请求、Trace和文件操作投影。复用既有最终输入、Pi消息codec、工具正文与不可变blob，不新增第二套消息存储，也不把流式token逐片落盘。
- 区分输入幂等ID与每次模型调用的modelRequestId。统一观察主模型、子任务、审批复核和压缩请求；派发前重投影不算联网请求，SDK内部未暴露的重试不猜测。
- 最终输入指宿主交给Pi stream的system、messages和工具声明。供应商协议转换及网络送达属于另一层观察，界面准确标明可观测范围。
- 请求统计来自唯一请求事实。主子并发分别提供墙钟和累计耗时；费用属于带来源的估算。缺价格、缺Usage或中断未知不填零，也不据此增加token预算或固定循环次数限制。
- 请求详情只向当前有权读取该会话的用户投影，认证header、Key、OAuth凭据和宿主私有codec不能直接返回Renderer。模型可见的历史正文可能含用户资料，按私有会话内容处理。
- 原生文件创建与编辑经统一写入用例保存前后像。工具定义仍归tools，真实路径与原子文件原语归sandbox，持久数据归storage，审批与Run归属沿现有agent-runtime。
- 可撤销范围为write_file、edit_file产生的受管文本创建和修改，含撤销创建时的受控删除。Shell、MCP、办公脚本及远端副作用显示来源和不可撤销说明。分支与checkpoint恢复只恢复上下文，文件历史保持独立操作语义。
- 应用内同一真实路径的写入、撤销和重做串行，执行前复核工作区身份、文件类型及当前内容。多文件操作逐项记账，不能承诺文件系统与日志跨介质原子提交；外部程序竞态的保证范围见设计。
- 完整归档限定单Session全部分支、子Run和可达资源，另附可重绑的非秘密依赖说明。长期记忆库、登录会话、插件Token、Keychain及工作区权限不随会话归档自动迁移。历史请求实际采用的记忆快照仍属于历史记录。
- 导入经过有界解析、完整校验与预览，不覆盖已有Session；导入的队列、旧批准及文件操作记录只供历史阅读。继续执行重新检查当前配置、权限和有效工具，绝不重放旧副作用。
- 功能实现伴随公开协议、持久codec与SQLite的必要更新，历史缺失信息显示未知；当前数据保留。规划阶段不修改协议版本、数据库或用户目录。
- 按现有领域建立模块，不新增泛用Trace平台、通用事务框架或独立评测产品。自动化回归、真实服务、内容质量、桌面安装与平台证据分别记录。

### Acceptance Criteria

| 编号  | 可观察结果                                                                                                                                                      |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01 | 同一输入经过排队、工具轮、子任务、审批复核和压缩后，每次实际stream调用有唯一身份和归属；未派发草稿不增加请求数                                                  |
| AC-02 | 请求详情还原实际最终输入、工具声明和采用资料，与派发时捕获一致；正文复用已有事实，SQLite及日志不再复制完整请求                                                  |
| AC-03 | 成功、供应商错误、用户停止、进程中断和持久化失败各有准确状态；已准备、已交接及是否送达不混为一谈                                                                |
| AC-04 | Trace按会话、分支、Run、子树、类型和状态过滤，先做权限过滤再分页；大日志及大正文不会全量进入Renderer，刷新、定位和重启后关联保持                                |
| AC-05 | 请求、回答、自身任务、包含后代的任务及Session汇总可逐叶核对，共享分支和嵌套子树不重复统计；审批与压缩可单独查看                                                 |
| AC-06 | Token保留供应商口径与缺失状态，费用保留估算来源、费率与币种；自定义零价、缺Usage及部分失败显示未知或部分完整，不冒充免费或真实账单                              |
| AC-07 | 并发任务的墙钟耗时与累计请求耗时分别显示，排队、首响应、模型和工具等待有清晰定义；缺失计时不由刷新时间补齐                                                      |
| AC-08 | 文本创建、编辑、撤销和重做保留准确原始字节、存在性及受支持mode；重复提交同一操作不产生第二次磁盘副作用                                                          |
| AC-09 | 外部修改、工作区替换、链接目标变化及过期操作链拒绝覆盖；主子任务和跨Session写同一路径有统一顺序，多文件部分结果明确                                             |
| AC-10 | 文件操作在准备、发布及终态记录之间中断后，恢复能区分未执行、已应用、冲突和未知，不自动再次写盘；分支和checkpoint切换不会隐式改文件                              |
| AC-11 | 完整归档恢复全部分支、子Run、附件、产物、文件前后像及最终输入引用，内容hash和关联一致；原始JSONL仍可单独下载                                                    |
| AC-12 | 导入前能看到资源、依赖、格式及冲突检查结果；坏checksum、缺blob、未知格式、恶意条目和ID冲突真实拒绝，已有会话及文件保持完整                                      |
| AC-13 | 导入取消、断线、重复请求及进程崩溃均有最终可查询结果，无可见半成品；历史可阅读，继续会话须使用当前绑定和权限，不自动请求模型、执行工具或写长期记忆              |
| AC-14 | 八组真实任务覆盖M1–M6，内容和Office产物使用独立判据，长会话及副作用故障时刻有回归；首轮失败、重试和未验项保留                                                   |
| AC-15 | 最新候选在macOS arm64及Windows x64的当前支持范围，从实际安装路径验证启动、共享数据、网络/插件、记忆、升级和退出；安装器、签名、公证及外部账号有分别可追溯的证据 |

## UseCase

### UC-01 找到一次失败的真实位置（AC-01–04、07）

在有嵌套子任务、工具和审批的会话打开轨迹，选择失败请求，看到它属于哪个任务、最终提交内容、已发生阶段和错误。读取旧请求时活动Run继续执行；停止、断网或重启后分别显示取消、失败或中断，未知送达与Usage保持未知。

### UC-02 核对一次回答的成本与耗时（AC-05–07）

查看回答主请求与子树汇总，再展开审批、压缩和失败请求。逐请求数值能解释总量，切换分支不重复计入共享历史。并行任务展示墙钟与累计耗时，自定义模型缺价格时显示价格未知，历史估算不随新目录价格改变。

### UC-03 恢复一次文件修改（AC-08–10）

让Agent创建文件并编辑现有文件，在变更列表查看diff，撤销后重做并核对字节。期间手动修改其中一个文件，批量撤销显示该项冲突并保留当前内容。分支切换不改磁盘，进程在写入后中断也不会自动重放操作。

### UC-04 把会话移到新环境（AC-11–13）

导出包含历史分支、子任务、附件和产物的完整归档，在独立profile预检导入。历史与资源可读，执行依赖在继续前重新绑定。坏归档被拒绝，重试有同一回执；旧队列、批准、记忆写入和文件撤销链不会自动生效。

### UC-05 验证真实产品与安装包（AC-14–15）

在固定候选上执行八组任务及横向故障矩阵，独立核对结果；分别安装macOS与Windows候选，重启、升级和退出后检查数据与所属进程。真实服务或签名身份缺失时记录Not verified及解除条件，不用替身结果代替真实账号或安装证据。
