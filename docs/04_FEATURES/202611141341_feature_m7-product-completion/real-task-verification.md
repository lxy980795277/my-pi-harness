## A4–A5：联网与真实授权读取

A4从官方资料核对Node文件API。审计独立读取官方tag文档，确认`flush`默认`false`；设置`flush=true`时，全部数据写完后调用`filehandle.sync()`，底层使用`fsync`，不表示改用同步阻塞API。相关选项加入于v20.10.0和v21.0.0；原文副本为`output/m7.5/audit/node-fs-v24.22.0.md`。持久工具事实为2次`web_search`、2次`web_fetch`和7次`read_tool_result`，不把8次模型请求写成8次结果续读。

A5调用已授权MCP的`get_me`，再经Skill网关执行3次GET。返回的仓库身份和最近3条提交与本地git独立核对一致；没有远端写操作。真实账号身份、OAuth Token与完整返回正文不纳入本文或白名单证据。本轮使用的是已有授权，拒绝零派发、未知结果不自动重试和故障恢复的证据来自[阶段验证](verify.md)中的隔离回归。

## A6：委派、排队与停止

首轮计算任务错用worker写入角色，因独占写入权冲突产生多次拒绝和串行执行，并未达成预期并行。随后显式追加两个researcher任务，创建时间相差35ms，两任务真实运行区间重叠。停止其中一个后，其Run及任务均为`cancelled`；另一个经过用户问答继续并完成，结果5050。创建时间接近本身不能证明模型同时推理，判定同时参考任务与Run区间、交互和终态。

六个任务包含一层嵌套关系；排队输入有实际`queue.added`与`queue.consumed`事实。独立核对的排队、嵌套和汇总数值分别包含1060、44100、570.70。完成的子任务保留结果，单停没有把另一个任务一并终止。整树停止及其他破坏性故障不在此真实任务中重复执行，其覆盖范围沿用隔离回归，不宣称在真实账号数据上全部实跑。

## A7：真实记忆事实

四个会话实际调用`save_memory`1次、`update_memory`1次、`learn_memory`1次、`delete_memory`2次、`search_memories`10次。保存回执创建测试记忆revision1，后续会话的准备上下文记录采用该ID和revision；更新后出现revision2采用记录，证明不是仅在同一个对话中复述旧消息。自动学习工具另创建一条记忆。

遗忘操作分别留下`forgotten`回执，revision为3和2；采集时当前记忆条目已不存在。另建新会话执行4次检索，结果均为0，准备上下文没有采用条目，也没有新的学习或写入。测试标记“松果731”仅用于确认测试范围，本文不记录偏好正文。历史采用事实保留作为审计记录，不等于已删除记忆仍能进入新上下文。
