# 会话日志数据精简

## Spec

### Roadmap Alignment

属于M0工程范式及M1–M4已实现会话链路维护，是M5前的数据治理，不启动M5或改为参考项目的数据架构。用户已授权按最优结果重构，不要求旧开发日志或API兼容，并在实现验证后要求直接删除旧会话、清理数据库及本地提交；提交版本为0.10.0，不推送。

### Intent

删除无业务消费者或可推导的批次字段，将模型回放材料保存为结构化JSON，消除工具正文与请求历史的重复存储。保留现有会话、事件、冻结权限、队列、分支、审批和恢复行为，模型实际输入仍可从日志精确还原。

### Constraints

- version继续逐行保存，不改为文件头；新磁盘批次使用版本3，仅接受新格式，不添加旧格式兼容或转换分支。用户后续已明确授权删除本项目旧会话及数据库会话数据；仅操作已确认profile的日志/附件与会话投影，保留独立配置、凭据及其他项目。
- 外层仅保留version、records、checksum；删除batchId、previousBatchId、sessionId、firstSeq，逐事件检查归属和连续seq。
- 保留同事务事件单行提交、SHA-256内容校验、fsync、末尾撕裂修复、投影失败冻结和逐工具恢复。
- privateData和消息codec在运行时与SQLite投影中使用对象；队列绑定、上下文messages等内部字段使用原生数组/对象，不嵌套JSON字符串。
- 磁盘编解码由storage拥有。工具终态展示文本与同批canonical结果相同时只保存一份正文；请求快照对相同历史消息使用前快照引用，首条system消息与systemPrompt不重复保存。还原保持字段、数组顺序和JSON键序，不产生新业务事件或不受控引用仓库。
- 保留现有公共事件/HTTP/SSE及UI投影，不减少流式事件持久化，不扩大上下游访问、工具权限或执行范围。
- 新格式改变宿主持久数据表示，历史SQL迁移正文、SQLite schema8和公开协议17不因本轮改变；产品与APP_VERSION按发布规范同步为0.10.0。

### Acceptance Criteria

- AC1：新JSONL外层只有version、records、checksum，旧版批次、错归属、断序和内容损坏明确拒绝。
- AC2：私有数据、请求消息、冻结队列绑定在日志中是JSON对象/数组，没有双重字符串编码；完整供应商消息和思考签名可恢复。
- AC3：同批相同工具正文只存一份；不相同或更丰富的展示结果无损保留；新请求只追加变化的消息与必要正文，日志重放后得到原完整请求。
- AC4：重启后继续追加、分支切换、队列、Skill继承、工具结果未知、断线展示与下载保留现有行为；引用损坏失败，不静默补默认值。
- AC5：相关源码、静态、构建产物与浏览器链路实际验证，记录结构精简收益及未验证项；实际结果同步权威文档和verify。

## UseCase

- UC1：新会话生成回复与多次工具调用，日志仅保存一次canonical正文及上下文变化，下载仍是原始已提交JSONL字节。
- UC2：关闭后从新格式日志重建消息、工具和工作状态，继续提问时模型收到完整历史，授权与能力版本保持正确。
- UC3：重复请求消息、分支交替和动态工具加载后重放，快照引用可还原同一组内容与顺序；无效引用、错误checksum和未知格式拒绝启动。
- UC4：工具完成、取消或结果未知时公开状态与模型结果仍同批落盘；截断末行不会恢复半个操作或重跑副作用。

## Issues

原私有数据通过JSON.stringify保存时会清除SDK模型中的undefined可选字段；改成对象后不能直接把这些字段交给持久化JSON校验。统一snapshotPrivateData生成脱离SDK引用的JSON快照，继续清除不可序列化的可省略字段，保留原有JSON边界和错误处理。

首轮静态检查拒绝新journal-codec测试的非空断言和JSON.parse隐式any；改为显式存在性检查和schema校验后通过。runtime定向测试曾在并行宿主负载下触发已有5秒观察期限，隔离及4worker全包均通过，未修改时限；最终全仓源码测试通过。

扩大的工具链浏览器回归发现旧M2用例依赖历史默认审批模式，而产品已按用户要求默认完全访问。测试显式选择请求批准后，原工具链和受限执行断言全部通过；不回退产品默认或放宽断言。
