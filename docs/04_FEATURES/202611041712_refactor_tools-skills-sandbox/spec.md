# 工具、Skill、插件与沙箱分层重构

## Spec

状态：原分层重构、单工具文件整理及2026-11-06收口的配套源码组织对齐均已完成实现与本机工程验证。独立tools与sandbox package、27个独立工具文件、办公Skill与独立领域注册已落地；工具配套实现归lib、utils及根装配文件，不保留documents、ports、registry源码目录。实际验证和未验证的平台、依赖范围见[验证记录](verify.md)，不据代码迁移关闭既有验收缺口。详细分层见[设计](design.md)，实施顺序见[任务](tasks.md)。

### Roadmap Alignment

属于M0架构治理及既有M2执行、M3上下文与交互、M4插件/办公、M5子任务能力维护，承接已完成的工具目录与按需加载、子Agent模块整理。M6长期记忆与搜索按用户要求暂缓；未来memory、computer-use只约定接入方式，不提前建空包或宣称实现。M2.3 Windows、M4账号/Office视觉、后续平台与正式安装验收缺口保持原归属。

### Intent

让工具有完整注册单元、Skill有可版本化的指令与资源、插件有明确的分发单位，Agent只组合获准能力。按长期职责设计依赖，而非把各领域实现集中进一个大包。办公工作流通过Skill、通用工具和本地脚本完成，独立sandbox承载共享的受监管进程与宿主访问机制。

### 已确定的设计方向

- 新增@my-pi-harness/tools；包内使用tools/、skills/、plugins/，不使用builtin目录名。
- 新增@my-pi-harness/sandbox；工具操作与进程/文件/网络访问机制分开。旧execution的职责完整迁移后删除，不保留重导出兼容壳。
- 采用完整ToolRegistration和能力端口；工具定义、加载元数据、参数相关策略和执行入口形成同一注册项，移除集中按名字维护的工具族派发。
- Office迁为Documents、PDF、Spreadsheets、Presentations四个插件Skill及其资源脚本；移除office\_\*专用模型工具和旧stdin JSON runner。通用正文/图像/PDF页图读取继续存在。
- 自主编写实现和Skill内容，采用已确认的工程范式；不复制参考仓库业务代码、内部指令或历史文档。

### Constraints

- tools不能依赖agent-runtime、storage或daemon；sandbox不能依赖tools、integrations、Pi、数据库或业务协议。领域服务通过窄端口接入工具，不传整个Runtime/Coordinator。
- 工具注册项的执行函数只在内存；日志保存实际模型可见定义、来源、指纹与授权版本。主子Run分别绑定执行器，不能继承父Run闭包。
- 保留原始模型参数校验、只读角色、审批、动态加载持久屏障、未知副作用分类、停止与资源租约。不以注册成功、Skill加载或插件安装代替执行授权。
- 保留当前用户选择：新对话UI默认完全访问，API省略权限默认ask；审批与隔离在内部独立表达，已有选项映射保持明确。首轮不隐含新增网络放行、宿主重跑或平台支持。
- 本地Shell/stdio受限模式继续默认断网；Web、MCP/OAuth各自的公网/精确目标规则不因本地full-access关闭。能力范围见设计，不把文件守卫或解析Worker称为OS隔离。
- Skill资源必须来自已接受且仍有效的精确版本。受限及角色只读执行用OS只读目录提供，不因加载Skill开放profile或安装根；full-access保持原有宿主语义，版本/撤销检查不能约束任意宿主Shell访问。撤权与进程回收前保持租约。
- 进程总生存期与工具等待时间分开；后台running不等于成功。不恢复重启前命令，不增加LLM累计Token或工具总次数限制。
- 产物通过通用宿主入口注册，下载依赖真实归属和内容hash，不能信任脚本stdout或模型自报。Office业务临时目录由业务流程拥有。
- 保留现有高级格式能力及拒绝行为；结构通过、真实重算、视觉检查分别记录。包重构不能直接改变现有产品、API和平台完成状态。
- 本轮依照后续用户授权实施并使用隔离测试数据验收；不读取应用凭据、不清理用户数据、不自动提交或升版。协议及schema随实际变更同步，不创建旧格式兼容分支。

### Acceptance Criteria

- AC-01：所有现有工具经统一注册接口接入；参数、来源、加载方式、需求、动态效果策略和执行入口可从一项注册定位，不存在第二套按工具名/族派发清单。
- AC-02：工具不导入具体Run/Work/Subagent类；已有会话控制和子任务由原领域拥有，主子执行器正确重新绑定，独立领域可贡献注册项而无反向依赖。
- AC-03：默认与按需声明、工具搜索及Skill加载的模型可见状态可从日志还原；未提交能力不进入下一模型请求，撤销的能力不能继续派发。
- AC-04：tools、sandbox、integrations依赖单向；execution源码、依赖、exports、路径别名和打包残留全部删除，源码及真实构建产物均通过。
- AC-05：Shell、长期命令与stdio MCP共用受监管字节进程；取消、超时、限额、leader先退出、管道关闭和重复关闭均保持事实准确，daemon异常退出无静默遗留所属命令。
- AC-06：run_command/wait_command/stop_command能表达在途和终态，保留有界部分输出、退出码和截断信息；跨会话/任务访问及未经批准启动均拒绝。
- AC-07：Skill正文、资源版本及代次校验继续有效；只读资源命令可运行；受限及角色只读命令的资源写入/profile访问拒绝，所有模式的未加载/已撤销资源新派发拒绝。full-access不宣称有OS路径保护，进程结束前不回收仍在使用的资源。
- AC-08：四个办公Skill完成普通创作与现有高级操作；模型不再发现office\_\*或旧pdf_read_pages，通用读取、视觉工具和文档附件读取继续可用。
- AC-09：宿主注册通用产物，主子任务均能下载注册时的精确字节；伪造输出、越界、符号链接、注册中变化、存储快照损坏和未授权下载明确拒绝；源文件注册后修改不改变下载字节。
- AC-10：审批与隔离分别可解释；full-access不绕过角色、专用文件/网络或插件撤销限制，隔离初始化失败不自动转宿主执行。
- AC-11：源码及独立桌面产物能找到工具包、沙箱资源和插件脚本；缺Python/转换器明确诊断，依赖安装走显式授权命令，未内置运行时不宣称开箱即用。
- AC-12：权限/生命周期/存储与M1–M5回归、关键办公结构及真实视觉样例分别给出证据；Windows及其他未运行项继续标记Not verified。
- AC-13：旧工具schema、名字特例、Office分发runner、重复helper、无消费者的依赖和资源完整删除；不留下新旧双套执行栈或仅转发的目录。
- AC-14：2026-11-05用户追加的工具文件整理覆盖全部27个原生工具：tools目录按工具名平铺，一个文件拥有一个工具的参数、描述、加载和权限元数据及执行入口；共享文件操作、网络传输和领域服务各有明确拥有者。移除多工具注册数组、数组下标关联和按名字区分不同文件操作的执行函数；所有调用方、公开出口、测试和受影响文档同步更新。
- AC-15：用户确认继续对齐配套源码组织：删除documents、ports、registry目录。正文解析归utils/document-text.ts，注册契约归lib/tool-registry.ts，原生装配归根workspace-tool-registry.ts，检索归utils/tool-search.ts；公共执行上下文归lib/tool-context.ts，工具专属输入和回调归对应工具文件。包出口、源码/测试别名、部署探针及文档全部同步，不保留旧出口兼容壳或旧构建残留；解析Worker、主子绑定、加载和授权语义保持。

## UseCase

- UC-01（AC-01/02/04）：实现一个独立领域的样例注册工厂，经端口装配进入目录并运行；不修改中央family switch、不创建该领域的空产品包，重复名和来源冲突被拒绝。
- UC-02（AC-02/03/10）：父Run激活工具后派生只读子任务，候选和实际执行范围正确收窄；子调用操作自己的任务状态，不读写父Run闭包。
- UC-03（AC-03/07）：加载一个含脚本的Skill，下一请求在持久屏障后使用精确资源版本；篡改/停用/重装后新启动被拒绝，活动资源按撤销流程收束。
- UC-04（AC-05/06）：长命令超出短等待时间返回running，之后wait取输出并获真实终态；取消、超时、停止、daemon关闭/异常退出均回收所属资源，不自动重执行。
- UC-05（AC-08/09/11/12）：四个办公Skill从输入检查、生成、重新打开、重算/渲染与图片检查到注册最终产物，主子会话下载与原hash一致；缺依赖和视觉未完成明确可见。
- UC-06（AC-05/10）：MCP持久连接复用通用进程且保留自己的协议和租约；单次调用取消不误杀其他租约，撤权及最后租约释放完成关闭。
- UC-07（AC-04/11/13）：在无旧execution dist的干净构建和隔离桌面目录中加载新包与Skill资源，旧名称不再可搜索，历史事实不靠新执行器重跑。
- UC-08（AC-14）：维护一个工具时从同名文件定位其完整声明和专属行为；命令、Skill及子任务继续通过领域端口绑定，工具目录不改变模型参数、默认/按需加载、审批或主子Run执行语义。
