# M2 最终检查与提交

## Spec

状态：M2审查、补漏、文档与0.2.0最终产物验证已完成，见[验证记录](verify.md)。按用户授权准备本地提交，由正常钩子完成最后静态与源码检查；提交结果以Git记录为准。提交后再进入M3，不在本轮提前开发M3，不推送。

### Roadmap Alignment

属于[roadmap](../../00_OVERVIEW/roadmap.md)的M2收尾。复核工作区、七种工具、审批、Diff、持久化恢复、目录桥与交互；Windows Shell和浏览器新增目录按用户已确认的决定保留暂缓，不迁移到M3或标完成。真实供应商/账号与目标平台实机仍须独立证据。

### Intent

形成进入M3前可复查的本地提交，补齐已发现的交互与检查入口遗漏，准确同步版本、发布记录和剩余事项。

### Constraints

- 当前Git上次提交为M0；本次包含本对话累计实现且尚未提交的M1、M1.6、M2及相关规范、文档、测试，不掩盖为单纯M2小改。逐项检查暂存范围，不加入缓存、产物、真实profile或凭据。
- 使用产品0.2.0记录M0之后的新功能；内部私有包版本保持0.0.0。工具快照增加明确assistant锚点，wire升5；SQLite仍为迁移4，事件信封与私有codec代际不变。
- 初开弹窗聚焦图标按钮时，仅显示按钮自身焦点；名称输入框聚焦时才高亮组合边框。保留Radix初始焦点、键盘访问与关闭恢复，不取消焦点管理。
- M2定向浏览器检查包含新工作区交互，不因后续小迭代遗漏已有检查入口。
- 同一assistant的工具展示按已持久化tool.requested事件seq排列，不能用不透明ID或毫秒时间排序；状态更新、分支继承和重启不得改变请求先后。
- 工具快照从已有投影列提供afterMessageId，时间线按消息与所属工具锚点组合；同毫秒最终回答不能跑到工具之前。不改写原工具事件或工具JSON，仅区分已存工具记录与公开快照。
- 按风险运行最终工程/产物/浏览器/桌面检查，提交钩子负责其配置的静态与源码测试；同一内容已通过的检查不为提交机械重复。检查失败先修，不绕过hook。
- 历史verify保留原环境与证据；当前Spec、API、指南、roadmap和本轮verify说明现状，不能把原始历史记录写成最新结果。

### Acceptance Criteria

- AC-01：M2剩余项明确区分本轮已解决、用户暂缓和外部环境未验证，没有未解释的正常macOS流程缺陷。
- AC-02：工作区初始图标焦点、输入框焦点、Popover关闭恢复及紧凑布局可用，M2用例入口覆盖当前交互。
- AC-02b：同一assistant、同createdAt且ID字典顺序相反的多工具，快照、分支和重开后仍按请求事件顺序展示。
- AC-03：最终检查按实际命令记录，构建和本机应用版本为0.2.0；未执行平台/账号检查不写通过。
- AC-04：按八步流程形成正确暂存、本地commit及Release Note，提交后工作区干净且没有推送。
