# 子Agent模块与通用执行接口整理

## Spec

状态：2026-11-03用户确认结构设计后完成实现、源码/API回归、构建与M5隔离浏览器验证，见[验证记录](verify.md)。保留一个agent-runtime package，以职责和依赖方向评估拆分，不按草图逐项创建文件。用户后续授权与循环策略调整一起整理为[0.17.0](../../06_RELEASES/0.17.0.md)本地提交。

### Roadmap Alignment

属于M0工程治理与既有M5委派能力维护，承接工具目录治理后的模块审查。M1–M5开发与验收状态保持，M6继续仅规划；工具分类维度、权限行为调整属于后续讨论，不并入本轮。

### Intent

将agents明确为subagents领域模块，让通用Run通过自己拥有的执行接口接入委派能力。分开任务协调、角色与工具约束、通信、模型工具适配及Run适配，保留任务树和资源生命周期的单一拥有者，避免复制状态或增加只转发的服务。

### Constraints

- 实现阶段仅授权实现与验证，不自动提交、推送、升版或启动收费模型；后续提交按用户明确指令执行。模块重构阶段不清理数据；后续用户另行授权处理上轮工具治理阻塞启动的旧会话，按原专题记录该数据清理，不改变本轮消息或存储实现。
- 保留Pi core/ai、现有消息类型与落盘粒度、公开HTTP/IPC/SSE、任务事件、存储schema和权限语义。原开发日志问题沿用工具治理记录，本轮不兼容或处理旧数据。
- 主子Run仍共用RunExecution，子任务独立上下文、角色限制、审批继承、写入拥有权、并发、通信幂等及停止/续作行为保持。
- runs拥有执行扩展接口，禁止反向导入subagents；模型工具声明可由目录引用，通用工具选择与审批不持有子任务调度器状态。
- 不新增workspace package、插件框架、通用事件总线或多后端执行框架；不为可能的未来消费者添加未使用端口。不保留旧目录或废弃名称兼容转发。
- 协调器继续唯一拥有活动节点索引及树级资源；紧耦合的停止和收束可保留在协调器，不为了草图中的lifecycle.ts拆散生命周期。
- 源码按类型、常量/schema、实现分区；文档同步当前权威位置，历史迭代文档不机械改写。

### Acceptance Criteria

- AC-01：生产源码不再使用agents内部目录及泛指整个Agent运行时的AgentRuntime名称；子任务协调器命名和公开导出匹配职责，所有消费者同步。
- AC-02：runs不导入subagents领域模块，扩展接口由runs拥有；子任务适配器实现它，通用输入投递不承担任务通信的领域校验。
- AC-03：五个委派工具的schema、名称、参数和错误行为保持；模型工具路由不混入模型流调度实现。
- AC-04：角色权限、限额及附件范围校验与工具候选过滤各有明确拥有者；默认/按需集合、父子隔离和已有审批策略保持。
- AC-05：任务通信幂等、范围限制、续作、队列消费事实与消息同批提交保持，停止/取消/持久化失败后不遗留任务或请求槽。
- AC-06：单一协调器拥有活动节点和生命周期，不引入重复Map或状态副本；文件拆分有真实消费者，没有空模块、单纯转发和旧路径别名。
- AC-07：受影响源码测试、编译、静态检查和构建通过，必要任务API与浏览器回归以隔离profile执行，不使用用户服务或凭据。

## UseCase

1. UC-01（AC-01–04）：主任务spawn后等待并收集结果；嵌套子任务遵守角色、深度、工具集合和请求调度，主子上下文不混合。
2. UC-02（AC-02、03、05）：主子通信、子任务完成后续作、重复请求及非法目标；注入消息只有实际消费时与对应任务事实同批落盘。
3. UC-03（AC-04、05）：只读父任务创建写角色被拒；完全访问审批继承、写入拥有者、MCP只读与动态工具发现行为保持。
4. UC-04（AC-05、06）：等待中取消、停止后续问、父收束、在途持久化失败和关闭；实际请求、工具与子树由原拥有者等待并释放。
5. UC-05（AC-01、02、06、07）：核对目录和导入图，执行相关编译面与构建，验证任务API和看板仍消费相同协议。

## Issues

- 当前AgentRunHooks由agents/ports拥有，而runs消费该类型；agents/launch又创建RunExecution，存在可消除的反向领域认识。
- 当前run-hooks同时包含模型工具路由、等待、模型流并发、通信消费和执行收束，按两个适配职责拆分。
- 当前AgentRuntime持有树级索引、计时器和取消资源，生命周期拆出前须证明拥有权仍唯一；不为缩短文件而扩散可写状态。
- 最终保留协调器的生命周期实现，没有新增lifecycle服务。SubagentMessaging借只读索引和续作回调工作，不维护第二份节点Map；工具访问规则通过allows传给通用选择器。
- runs不依赖subagents模块；prepare仍使用共享协议AgentMessage组装续作输入，运行中通信校验和消费事实由适配器提供。不为移除共享DTO认识增加额外通用消息层。
- 模块验证完成后，用户实际启动暴露上轮工具治理已记录的旧接受快照问题；获明确清理授权后已恢复实际profile及daemon启动，处理范围和证据见[工具治理验证](../202611021658_refactor_tool-catalog-loading/verify.md#后续旧开发会话清理2026-11-03)，不增加兼容逻辑。
