# Agent执行职责拆分与去重

## Spec

状态：2026-11-01已完成实现、定向回归和独立审查，验证见[verify](verify.md)。用户重新限定只清理Agent执行层重复功能并按职责拆文件；此前包含消息治理的未提交改动已全部回退，本轮从干净基线a7b87f2开始，开发验证版本0.14.1、协议22、SQLite9。用户随后明确授权本地提交，按提交规范将产品与APP_VERSION同步至[0.14.2](../../06_RELEASES/0.14.2.md)，协议、存储及消息语义保持。

### Roadmap Alignment

属于M0工程组织及M1/M3/M4/M5既有执行链路维护。M6继续仅规划；M7未选能力、既有Office/外部网络/Windows缺口不由本轮关闭。后续用户明确授权本地提交及规范要求的版本同步，不包括推送、构建或发布。

### Intent

让单Run生命周期、Pi装配/请求钩子、输入消费、工具族执行、审批与派发结果各有明确拥有者；主子Run共用相同公共准备，消除重复与校验漂移。职责清晰时拆为独立文件，不以文件数量或行数为完成指标，不保留被新实现替代的旧分支、重复实现或无意义转发。

### Constraints

- 消息部分保持现状：不改Pi消息类型、protocol.AgentMessage命名、MessageView/LiveMessageDelta结构、公开消息投影次序、codec、JSONL/SQLite格式、前端及SSE协议；不加parts，不迁移消息，不清理用户数据。
- execution.ts中的现有消息事件代码可作为执行器内部独立职责原样封装；只改变拥有者和调用关系，不改字段、默认值、消息顺序、持久粒度、异常partial保留与回放语义。
- 不迁移或重写EventInput及持久事件schema。本轮去重限执行准备、工具公共流程及被Agent规则加载重复实现的有界字节读取。
- 主子Run仍复用同一执行器；保留队列消费与消息同批、接受先于模型请求、冻结能力/租约/角色/审批、MCP派发屏障、unknown无重试、取消/失败与后代收束。
- 主子Run公共模型检查同时要求文本能力与推理强度；共享准备不抹掉分支/任务、根输入选择与子角色继承的实际差异。
- 工具族处理器独立于公共策略、审批及持久结果记录；SDK拒绝、从未派发及正常工具结果复用同一canonical结果组装，仍保持原状态和审计关系。
- execution/filesystem拥有稳定有界字节读取；context保留AGENTS路径选择、优先级、UTF-8、总预算及领域错误映射。只提取已存在原语，不扩大文件/工具权限。
- 不运行收费模型，不操作用户服务/账户；测试只使用独立临时资源。公共协议与存储版本不变；必要文档随最终职责同步，验证结束后再创建verify。

### Acceptance Criteria

- AC-01：RunExecution只编排生命周期；Agent装配、消息事件记录、输入投递及工具终态由清晰独立模块拥有，原实现删除。
- AC-02：主子Run共用模型检查及history/work/user/system/接受批次准备；分支、角色、公开消息字段和数据记录顺序保持。
- AC-03：34种内置定义和默认可见选择不变；工具族路由、只读/原始JSON拒绝、人工/AI/完全访问审批、MCP派发/unknown/取消及持久失败有定向回归。
- AC-04：规则与文件工具复用同一字节读取；超限、增长、变化、取消及资源关闭回归通过，领域文案与限制保留。
- AC-05：消息、前端、协议、存储格式相关文件保持基线；已有消息/队列/通信/流式/失败/恢复测试证明仅职责调整，无数据迁移或兼容层。
- AC-06：静态/类型/行为检查及独立代码审查覆盖改动，文档与最终职责一致；未执行的平台/模型验证明确标注。

## UseCase

1. 普通主Run与带模型覆盖子Run启动，文本与推理能力一致检查；合法执行和异常路径都释放模型资源，接受事实不重复。
2. 多轮工具、队列修订、Agent通信、运行停止及SDK空final：公开消息字段/次序/原始意图、partial保留及日志批次与原语义相同。
3. 工具未知路由、审批拒绝、只读、取消、断连unknown与持久化失败：不得派发错误执行器、重复落盘或伪称完成。
4. AGENTS及普通文件读取发生增长/变化/取消：共享安全原语实际失败并关闭句柄，各自领域错误保持。
