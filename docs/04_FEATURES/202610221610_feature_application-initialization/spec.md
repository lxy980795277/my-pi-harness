# 应用初始化与统一加载

## Spec

### Roadmap Alignment

属于M0应用启动体验及M4界面收尾，不增加M5范围，不改变登录、工作区或扩展能力的服务协议。用户已确认统一首次加载策略，并要求加载组件带有色彩和动效；本轮连续实现与验证，不自动提交。

### Intent

首次进入页面时，登录校验、服务协议检查和必要工作台数据共用一个稳定的全屏加载界面。必要数据就绪后一次展示侧栏和输入框，避免左右区域分别加载造成的布局变化。

### Constraints

- 保留现有本机信任、应用登录、撤销和协议校验。未登录不请求私有数据，失败仍可配对、登录或重试；不通过固定延迟、假进度或跳过校验改善视觉。
- 登录及健康检查通过后，并行读取工作区、会话列表、Provider配置及默认设置。仅当前默认或已选模型必要的能力按需读取；设置专用Provider目录、MCP和Skill目录不阻塞启动。
- 查询定义与缓存由TanStack Query拥有，启动Hook只汇总必要状态，不复制到Zustand。入口与业务组件共享查询定义及短期新鲜度，避免主界面挂载后立即重复首批请求。
- 初次无数据的必需查询阻止进入工作台；空列表及未配置默认模型属于合法完成。首次失败在统一入口显示具体错误并允许重试；后台刷新保留已有界面及草稿，失败由原区域提示，不重新覆盖整页。
- 加载组件在登录、服务与工作台准备阶段保持同一实例、相同尺寸，只更新简短阶段文案。上方为蓝/紫/青色空间光环，下方为阶段文字及纵向居中的三点跳动动效，不放Logo或卡片。光环图形保持固定方向，只保留沿线流动的光迹与柔和光晕。动效采用transform/opacity，适配浅深主题和prefers-reduced-motion，使用status语义，不伪报百分比。
- 注销、登录失效与身份切换继续取消私有请求并清空旧缓存。未来新增必要前置数据必须明确纳入准备Hook；不遍历全局所有pending查询形成通用遮罩。

### Acceptance Criteria

- AC-01：延迟登录响应时只出现统一加载；未登录进入登录页，不发送工作区等私有请求。
- AC-02：登录及协议校验成功后，四类必要数据并行请求；任一延迟时侧栏与输入框均不提前挂载，完成后同时出现，不展示原左右加载文案。
- AC-03：空数据可进入工作台；请求失败可重试恢复，协议不兼容仍阻止进入。
- AC-04：后台轮询、失效重取和设置更新不遮挡工作台、不丢草稿；退出或撤销时旧私有结果不会重新进入页面。
- AC-05：实际浏览器观察彩色动效、浅深主题和减少动态效果；各阶段加载图形不重挂载，文案不改变容器布局。

## UseCase

- UC-01：已有登录进入，分别延迟auth、health和工作区/设置响应；始终是同一个加载组件，主界面直到必要数据齐备才展示。
- UC-02：无登录进入登录页；完成登录后共用准备流程；注销或授权失效中止私有准备。
- UC-03：必需接口失败后重试，合法空工作区/无默认模型正常进入；协议失败沿用明确的服务诊断与重连。
- UC-04：已进入工作台后刷新会话或工作区，保留输入草稿与页面；在浅/深/减少动态效果下检查加载组件。

## Issues

当前App在登录与ServiceGate通过后立即挂载侧栏及SessionsPage，后者再分别获取工作区/会话和Provider配置，输入框挂载后才读取默认设置。首次请求分散在组件树不同层，导致重复加载界面与不稳定的首屏布局。

实现复核补充两条协议约束：健康检查失败后重连不能用仍保留的旧成功data放行；注销或授权恢复时，公开诊断可保留，但旧健康请求须取消并标记失效，重新确认协议后才能请求私有工作台数据。普通健康后台刷新和已有私有数据刷新不重新遮罩。

实际验证及修正见[验证记录](verify.md)。

加载动效已由用户确认，临时常驻预览开关及其入口分支已移除。开发和生产均按真实登录校验、服务检查及工作台数据准备状态展示加载界面，就绪后进入页面。
