# M4实施任务与模块归属

日期：2026-10-19。实施基线为0.5.0提交 `6b96c78`，M3复核及登录前置工程已完成。本文是任务规划，所有实现项仍待开发；功能范围和约束由[总Spec](spec.md)拥有，标杆核对见[baseline](baseline.md)。

## 顺序与交付规则

先完成M4.1本地MCP完整链路，再进入M4.2目录与按需加载；两者完成后可以并行推进M4.3远程MCP和M4.4 Skills运行时。M4.5依赖M4.4，M4.6依赖M4.2–M4.5；M4.6完成后，M4.7外部服务与M4.8本地办公工作流可并行，云端办公另依赖M4.7。最后由M4.9验证组合场景。

每个模块按Spec细化、协议/数据、宿主与运行时、可用UI、异常路径验证、verify顺序交付。界面随模块一起完成，M4.9只负责跨模块联调，不承接之前未做的所有界面。进入某个模块时才冻结具体接口和依赖，不提前创建空包或将规划勾为已实现。

## 模块归属

| 所有者                         | M4职责                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------- |
| `packages/protocol`            | 公开配置、状态、选择、调用来源与事件schema；不暴露秘密或宿主对象                  |
| `packages/storage`             | SQLite配置、信任、安装及连接记录；系统凭据引用；JSONL事实与投影                   |
| `packages/execution`           | 持久进程/管道、受控文件与网络、隔离和完整回收                                     |
| 拟新增 `packages/integrations` | MCP SDK适配、Skills目录、插件装配与外部连接能力，内部按领域组织；仅随实际实现创建 |
| `packages/agent-runtime`       | Run工具集、模型可见定义、策略与审批、Skills激活、预算/压缩和会话事实              |
| `apps/daemon`                  | 装配上述能力，拥有管理API、授权流程及生命周期，不将HTTP对象传入运行时             |
| `apps/web`                     | 设置与输入框入口、状态、授权/审批和结果呈现；仅消费公开DTO                        |
| `apps/desktop`                 | 按实际需要扩展选目录、打开资源和系统浏览器等有限桥；不承接Agent业务               |

## M4.1 本地MCP闭环

依赖M1–M3及应用登录。先做有限目录、用户明确选择的本地工具链路；完整目录管理与Run内动态加载归M4.2。

| 顺序   | 工作包               | 所有者与完成门槛                                                                                                                                                      |
| ------ | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M4.1.1 | 协议与统一RunToolset | protocol、runtime、storage：统一接受审计/模型声明/预算/执行路由；定义稳定来源、配置revision、指纹及可见版本，补调用结果未知的持久事实，未知结果不能成为Todo成功依据   |
| M4.1.2 | 受监管持久stdio      | execution、integrations：SDK适配双向管道，明确cwd/环境/隔离、输出限制、发现与调用取消、连接租约和有界关闭；不直接复用一次性Shell输出收集器                            |
| M4.1.3 | 配置、启动信任与凭据 | storage、daemon、Web：Server CRUD/revision、启停、秘密单独保存、启动范围确认和诊断；固定编辑/禁用/撤销对在途调用的处理，配置改变后旧信任不能复用                      |
| M4.1.4 | 实际调用与最小选择UI | runtime、integrations、Web：设置增加MCP页，解禁输入框MCP选择，有限工具在Run接受时冻结；参数校验、审批、混合结果投影与JSONL使用同一来源，不以call_tool代理绕过模型定义 |
| M4.1.5 | 本地链路验收         | 真实SDK fixture与Pi请求、配置重启、批准/拒绝/停止/超时/撤销/关闭，两个Run共享连接时互不误关；观察所属进程与管道实际结束，并验证Web/Electron入口                       |

- [ ] 完成M4.1.1详细Spec与依赖核对，更新全部协议消费者。
- [ ] 实现M4.1.1–M4.1.3的真实定义、进程与配置能力，不以空接口计完成。
- [ ] 完成M4.1.4前后端调用闭环。
- [ ] 通过M4.1.5并记录平台边界。

模块完成标志：用户添加并明确信任本机Server，选用工具后Agent真实发现、声明、审批调用并保存结果；拒绝无调用，停止与退出无所属进程遗留。

## M4.2 工具目录与按需加载

主要归属integrations/mcp、runtime/context、protocol/storage及daemon/Web，依赖M4.1。

- [ ] 目录分页、缓存、刷新/失效、稳定别名、schema方言/大小/深度校验，以及资源/Prompts目录展示。
- [ ] 实现tool_search和Run内显式加载，分离冻结候选目录与当前可见集合；下一模型请求、预算、日志和执行按同一active revision读取，旧system投影不丢新增定义。
- [ ] 工具开关、可信只读和可撤销授权，绑定定义/参数/配置/身份；加入表单/JSON编辑、批量导入预览、冲突处理、脱敏导出和诊断。

完成门槛：大目录不全量进入prompt，加载后真实下一请求包含准确schema；同名、失效定义、旧Run、超预算及撤销均不能错路由。Resources/Prompts仍只发现与展示，不扩张读取或订阅能力。

## M4.3 远程MCP与OAuth

主要归属integrations/mcp、execution、daemon授权装配与Web，依赖M4.1–M4.2。

- [ ] Streamable HTTP及SSE传输，受控网络/重定向、静态认证头和连接状态。
- [ ] OAuth发现、state/PKCE/issuer、回调归属、刷新去重、失效、重授权和断开。
- [ ] 完成授权界面、无工作区调用、取消/断线/超时与结果未知处理。

完成门槛：两种传输分别通过真实SDK fixture；凭据只由宿主持有，断线后不自动重做副作用。应用登录、模型OAuth与MCP连接授权分别管理。

## M4.4 Skills运行时

主要归属integrations/skills、runtime/context、protocol/storage及Web，依赖M3、M4.1–M4.2。

- [ ] 固定系统/插件、项目、用户作用域、兼容目录、同名优先级和无工作区行为，发现/校验SKILL.md元数据。
- [ ] 查询、详情、渐进加载正文与有界资源读取，完成来源/内容hash冻结和压缩后指令保留。
- [ ] 解禁输入框Skill选择，贯通发送、steer/follow-up、队列编辑、重发和分支；实现显式Run级工具授权申请、撤销与失效。

完成门槛：实际加载指令进入模型并可由会话重建；旧Run不读取新磁盘版本，资源越界拒绝，加载Skill不自动提升执行权限。

## M4.5 Skills创建与管理

主要归属integrations/skills、execution、daemon/storage、Web及必要桌面桥，依赖M4.4。

- [ ] 设置列表/详情、资源、作用域、启停与打开注册目录。
- [ ] 受控创建和GitHub来源安装，暂存/校验/原子启用，禁止同名覆盖与不受信生命周期脚本。
- [ ] 取消、失败清理、卸载和活动Run资源所有权；系统/插件资源由其所有者管理。

完成门槛：成功项可选用，重启保留状态；坏来源、取消和同名不产生假安装，不删除工作区其他文件或活动Run仍使用的资源。

## M4.6 插件市场与装配

主要归属integrations/plugins及独立资源、daemon/storage和Web，依赖M4.2–M4.5。

- [ ] 九个范围内内置插件manifest、分类/详情及独立资源：Vercel、GitHub、Google、Notion、Supabase和四类办公插件。
- [ ] 安装后装配Skills与MCP apps，提供整体/逐项启停、连接状态与管理入口。
- [ ] 明确插件/App/连接/凭据共享归属，卸载只清所属关联，不误删手动Server或其他插件资源。

完成门槛：无真实第三方账户也能验证装配和管理；安装不自动授权账号或工具，不提供未实现的远程市场、任意JS包或升级按钮。

## M4.7 外部服务连接

主要归属integrations/connections、daemon授权/gateway、storage、runtime和Web，依赖M4.3、M4.6。

- [ ] Plugin OAuth与账户连接/刷新/断开，明确与MCP app共享凭据的引用和所有权。
- [ ] 受限REST gateway绑定有效Run、激活Skill、账户、路径/参数/权限和期限；宿主附加秘密，子请求事实关联父工具并遵守Plan/审批。
- [ ] 按GitHub、Google、Vercel、Notion、Supabase建立MCP与gateway两通路矩阵；Google覆盖Drive、Docs、Sheets、Slides、Calendar。

完成门槛：越权路径、失效Run/Skill、账户错配及撤销均拒绝；不将应用GitHub登录Token当工具凭据，真实账号结果逐服务登记，fixture不代替供应商验收。

主要归属execution、integrations/plugins独立资源、runtime及Web受保护预览，依赖M4.4–M4.6；云服务另依赖M4.7。

- [ ] 复用M3文档正文提取，新增有界PDF指定页图读取；检测外部依赖，缺失时明确不可用。
- [ ] 独立实现DOCX与PDF的创建、约定修改、结构/内容检查及必要页面渲染。
- [ ] 独立实现XLSX与PPTX的创建、约定修改、公式/表格/图表及布局检查。
- [ ] 完成受监管脚本、取消/超限/失败清理、工作区文件交付和可查看结果。

完成门槛：逐项覆盖总Spec的办公能力矩阵，每种格式有创建和受控修改的实际产物；保存成功不等于验收成功，必需结构/视觉检查不能省略，不新增Office编辑器或通用产物平台。
