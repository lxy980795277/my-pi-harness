# 前端状态职责整理

### Intent

将过宽的Workspace Store按应用导航、会话草稿、设置界面拆分，让状态的所有者与存活时间清晰。Query继续缓存daemon事实，组件局部交互继续由Hook拥有；跨虚拟列表卸载需要保留的工具展开选择进入独立会话展示Store。

### Constraints

- 应用导航拥有页面、当前会话与工作区；会话草稿拥有新建代际、选择、输入草稿、未确认请求与创建attempt；设置拥有Dialog、当前分区、Provider/模型及授权流程UI状态。删除旧混合Store并更新所有消费者，不保留兼容转发。
- Store只同步修改本域状态，不互读互写其他Store，不直接请求HTTP/SSE。跨域新对话、创建成功和注销由所属Hook组合明确动作；保留代际、幂等请求ID及旧响应不能改写新草稿的语义。
- 消息、Run、工具结果、配置和登录状态继续以daemon事实及Query为准，不复制到Zustand。附件草稿保持现有独立Store，秘密输入保持局部，客户端草稿和展示选择仍为内存状态，不新增浏览器持久化。
- 工具展开选择按sessionId/toolId隔离，滚出虚拟列表或切换会话后返回仍保留；待审批详情强制可见。注销/授权失效统一清理导航、草稿、设置、附件与展示状态。普通表单编辑、菜单开关和请求控制器不机械提升为全局状态。
- 保留已授权的UI修改，验证现有创建、发送重试、队列、导航、设置和退出行为；不操作用户服务、真实账号或开发数据。

### Acceptance Criteria

- AC-01：旧混合Workspace Store没有消费者或兼容别名，导航、草稿与设置各有明确所有者，源码和所有消费者类型检查通过。
- AC-02：切换会话保留输入/附件草稿，未确认提交复用原requestId，新建代际拒绝旧结果；已有恢复用例继续通过。
- AC-03：跨虚拟列表卸载后工具展开选择保留，按会话隔离，待审批入口不被折叠，注销及撤销后客户端私有状态清空。
- AC-04：Query仍是服务端缓存入口，设置和会话主流程浏览器回归通过；实际证据单列，未验证平台不标完成。

## UseCase

- UC-01：在会话A输入未发送内容并添加附件，切换B再返回，草稿仍在；发送结果未知时重试仍用同一requestId，旧创建响应不影响后来新建的输入。
- UC-02：打开工具详情，滚出可见范围再返回或切换会话后返回，保持展开；其他会话同类工具不跟随，待审批详情持续可见。
- UC-03：从用户菜单进入设置并打开Provider/模型编辑，再切换设置分区或退出，弹窗与选择状态正确；注销或授权撤销清理所有客户端私有状态。
