# Agent循环终止与子任务结果回收

## Spec

状态：工程实现及本机自动化验证完成，证据见[验证记录](verify.md)；真实供应商与平台边界继续保留。

### Roadmap Alignment

属于M0工程维护及既有M1/M5执行链路修复，承接子Agent模块整理；M6保持仅规划，不扩大真实账户、Office或平台验收范围。

### Intent

移除主、子Run按模型请求或工具总数硬截断的策略，避免正常调研被固定16/32轮或64次工具次数切断。针对相同工具与完整参数的连续重复注入提示，保留异常前已产生的子任务文字，由父任务同时看到状态与部分成果。

### Constraints

- 任务数、嵌套深度、请求并发、现有树/任务时限、单次输出和上下文容量继续由原拥有者控制；不引入累计token预算、强制收尾请求或自动重试。
- 删除maxTurns配置、工具参数、内部计数、设置和看板展示及重复判断；不保留兼容字段或迁移旧格式分支，不清理用户现有数据。
- 重复检测按每个Run隔离，规范化JSON对象键序，保留数组次序；不同工具或参数重置连续计数。第3、5、8次提醒，仅建议调整方法，不改参数、不跳过调用、不改变审批或成功状态。原结果已占满落盘内容块容量时跳过提醒，不挤占、合并或截断原结果。
- 提醒必须随现有工具上下文持久化后进入模型请求，复用现有事实链路，不伪造用户提问或复制参考项目代码/提示词。
- 子任务结果只选当前目标Run，成功回答和部分输出显式区分；失败、取消和未知结果不能转为成功，不泄漏旧续作文字。
- 保留已授权的subagents模块重构；实现阶段不自动commit或push，用户后续授权一起整理为[0.17.0](../../06_RELEASES/0.17.0.md)本地提交。

### Acceptance Criteria

- AC-01：根Run超过32次请求、子Run超过16次请求、工具超过64次仍可自然完成；原权限、停止及超时行为有效。
- AC-02：设置和spawn不再接受maxTurns，读写、持久快照、设置表单和任务详情共用精简后的限制定义。
- AC-03：相同调用在3/5/8次收到有界提示，不同参数/工具、不同Run及动态工具集重建不会串扰；提示在模型上下文和临时日志回放中一致；满容量结果保持成功且不追加越界内容块。
- AC-04：子任务失败或取消返回已产生文字及真实错误/状态；无输出明确为空；成功保留完整回答，重试/续作不能回退到其他Run。
- AC-05：清理旧计数、无效测试及当前态文档，完成相关源码、协议/存储/API、类型与构建回归。

## UseCase

- UC-01：长调研执行多轮不同查询后正常汇总，不因累计轮数停止。
- UC-02：模型反复调用同一工具与参数，收到提醒后仍可选择继续或调整方案；审批拒绝仍按原政策执行。
- UC-03：子任务产出文字后模型失败、用户停止或超时，父任务读取部分成果并能识别未完成；新Run无文字时不返回旧结果。
- UC-04：设置和任务看板不再显示轮数限制；非法旧参数在新写入口明确拒绝。

## Issues

- 原实现存在finishTurn和调度适配器两份轮数限制，ToolRuntime另有64次总调用限制；本轮同时移除。工具声明集合的64项容量限制属于请求大小策略，继续保留。
- 原结果选择只接受stop/length且要求complete，导致失败Run已有的文字无法被父任务读取；本轮回收已有正文并明确partial，模型length仍沿用现有Run终态但标记输出不完整。
- 检查发现工具指纹与重复判断使用相同的JSON规范化，已归并到tools/identity；模型收据测试只解析首个数据文本块，不把独立提醒拼入JSON。
