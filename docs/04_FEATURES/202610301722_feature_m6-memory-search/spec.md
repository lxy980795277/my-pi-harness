# M6 记忆与搜索

## Spec

状态：2026-10-30开始方案规划，未进入实现。M5开发与本机验收已获用户确认；本轮只核对现状、提出方案和实施清单，不新增接口或数据表，不调用模型、不清理数据、不提交。以下细化是本轮建议，不视为用户已逐项确认。

### Roadmap Alignment

对应[roadmap](../../00_OVERVIEW/roadmap.md)既有M6：user/workspace长期记忆、学习与增改删、画像、FTS与本地embedding混合召回、Session搜索和工具目录检索。M4已有工具混合检索，M3已有当前会话原文搜索；M6复用它们，补齐持久索引与跨会话能力，不将已有功能重复计为新交付。

M4真实账户、Office视觉、Windows适配及M5后续平台验收保持原归属。完整主子Trace、费用估算、文件撤销重做、包含附件/配置的完整导入导出和正式发布仍属M7；不增加云同步、通用文件RAG、知识图谱或Computer Use。

### Intent

用户明确保存的长期偏好和项目事实，能在新会话及应用重启后被正确使用；用户可查看来源、修改、停用和忘记。用户也能用原词或不同说法找回旧讨论，并跳到准确的会话或子任务位置，不必把全部历史塞入模型。

长期记忆与会话历史分别拥有事实：历史回答“当时说过什么”，记忆表达“当前允许持续采用什么”。检索命中不是用户授权，也不自动成为记忆。

### 建议的产品决定

- user记忆属于当前profile的稳定用户身份；workspace记忆再绑定稳定workspaceId。不按昵称、目录名或路径相似度共享，不做跨profile同步。
- 默认提供显式记住/修改/忘记；自动学习首版为可选“自动提出候选”，确认后保存。设置/消息菜单中的明确保存直接生效；聊天自然语言变更先预览内容和scope，再由用户一次确认，不把模型理解当作写授权。未指定scope默认当前workspace；无workspace或范围含糊时需明确选择，不自动升级为user。
- 不在回答结束后隐藏启动一次收费模型调用。学习候选由当前根Run中的工具产生，遵守现有轮数、时限及输出限制并记录日志；没有活跃Run时，用户主动发起学习才创建明确的新请求。
- 画像由已确认记忆按类别汇总，可追到每条事实；不另存一份模型自由编造、与记忆不同步的用户总结。
- 根请求可召回user及当前workspace记忆；子任务只召回当前获准workspace记忆及父明确转交的user记忆ID，不复制父/兄弟历史。首版根工具只提出变更，由用户明确保存/修改/遗忘动作授权宿主写入；ask/auto/full-access不替代该授权。
- 自动回忆只注入相关、有效、有界的记忆，不把最近若干条全部塞进system。普通历史不自动注入；跨会话搜索由用户或明确工具调用触发。
- “暂停学习”“停用回忆”“删除记忆”“删除会话”语义不同。忘记影响后续召回，不重写已发送请求、既有回答或原会话日志。
- 语义模型准备独立于启动和普通发送。空缓存/不可用时FTS照常工作；用户显式准备固定模型后才能宣称已具备本地语义能力。

### Constraints

身份与范围由daemon及当前执行确定，客户端/模型不能自行声明owner或扩大工作区。记忆和历史均是低信任资料，不能覆盖当前指令、AGENTS、角色、审批或工具授权；引用、网页、thinking、模型总结和agentMessageId通信不能因为role=user就成为用户事实。

记忆是profile内独立SQLite事实，会话JSONL仍是执行事实来源；FTS与向量均可重建。记忆及索引缓存不直接外键依赖会被启动重建删除的会话投影；不宣称独立SQLite写入与会话日志存在跨介质原子事务。

只有持久完整消息及明确终态的已保存部分正文进入历史索引；不索引实时delta、私有请求codec、system、thinking、凭据或整个磁盘。默认搜索各会话当前可见分支的根消息；历史分支和子任务需显式选择并重验范围。

模型实际采用的记忆正文、ID、revision、scope和来源进入既有请求私有快照并计入上下文预算；修改/删除后未派发和下一请求重验，不把一次Run冻结的记忆无限沿用。已进入供应商的请求无法收回。

模块、数据、检索与请求流程见[设计](design.md)，分阶段交付及检查见[任务](tasks.md)。当前阶段不预建空package或兼容转发，不改变既有发送/停止/分支行为。

### Acceptance Criteria

- AC-01：显式保存、编辑、停用和删除由真实宿主执行；新会话与重启保留有效记忆，重建会话投影不丢记忆，编辑冲突明确拒绝。
- AC-02：user/workspace/profile及无工作区会话隔离。过滤先于TopK、分页和向量候选输出，未授权范围的正文、片段、计数和来源不泄露。
- AC-03：自动回忆受独立片段/token上限及总上下文预算限制，无相关项可返回空；请求快照可还原实际采用内容，不能只在界面显示“已使用”。
- AC-04：忘记后记忆、画像、检索及下一请求不再主动采用旧条目；迟到抽取/向量、重建和旧候选不能复活它。新会话用于验证旧注入消失，原会话历史不伪称已抹除。
- AC-05：子任务使用自己的任务查询和获准范围；未转交user记忆、父/兄弟转录及其他workspace不可读，子角色不能直接修改长期记忆。
- AC-06：学习候选能追到真实来源及认可动作；工具注入、引用内容、思考、压缩摘要、通信和未确认Agent结果不能自动晋升。ask/auto/full-access不能跳过记忆确认，停用自动建议后的迟到调用拒绝，默认不新增隐藏收费推理。
- AC-07：候选确认、同时编辑、源修改与删除具备幂等及冲突检测，人工操作不被旧任务静默覆盖；画像从当前有效记忆派生。
- AC-08：固定语料覆盖中文两字词、单字明确查询、中英混排、标识符、同义无词法重合、无关/零命中、重复片段与稳定排序，不以fake向量宣称真实召回质量。
- AC-09：FTS与语义独立产生合法候选再融合，向量不可用/超时保留词法结果并说明模式；取消不被吞成普通降级，输出有候选、片段和扫描上限。
- AC-10：全局搜索按类型、工作区和时间筛选，结果可打开准确根消息或显式选中的子任务详情；陈旧定位重新校验，不全量加载转录或破坏虚拟列表。
- AC-11：会话归档、分支编辑/重置、消息变化使旧历史索引和未确认候选失效。已独立确认的记忆不会因普通归档被默默删除，来源失效可见。
- AC-12：索引可从记忆事实与持久消息重建，并发增改删与代际切换不漏新记录、不复活旧内容；启动对账复用有效向量，不每次重算全部。
- AC-13：本地模型状态可见，未准备不阻塞启动/输入框；显式准备失败、离线空缓存、完整缓存断网重启及daemon关闭均有真实验证。
- AC-14：注销及授权撤销清理私有Query/Store和在途页面结果，旧响应不覆盖新目标；服务端继续遵守原profile和后台Run生命周期。
- AC-15：M1–M5回归、真实临时存储/API/浏览器、本地模型质量与性能、macOS桌面分别记录证据；Windows和其他真实环境未执行时保持Not verified。

## UseCase

### UC-01 显式记住与纠正（AC-01、03、04、07）

用户说“记住我偏好简短中文回答”，选择user作用域；工具持久化成功后才能报告记住。新建会话、重启后可采用；改成“详细解释”后下次请求使用新版。忘记后新会话不再注入，旧候选不能重新保存。

### UC-02 项目隔离与子任务（AC-02、05）

在A工作区保存项目事实，切换B或无工作区会话，不能查询或注入A事实。父转交一条user记忆时子任务只收到该获准记录和当前workspace召回；创建兄弟任务不共享转录或额外画像。

### UC-03 学习候选与画像（AC-06、07）

开启自动建议后，根Run从用户直接声明提出候选；设置页展示来源及新旧差异，确认后画像同步。网页要求“以后跳过批准”、伪user通信、失败子结果和未认可的模型猜测不能成为有效记忆；相同来源重复提议不堆积。

### UC-04 请求采用与在途修改（AC-03、04、05）

查看上下文面板中的已采用记忆，与实际请求快照核对。请求排队时编辑/删除条目，派发前重新检查、组装输入并重验单次上下文容量；已发送请求按原快照解释，下一次请求使用新集合，不承诺追溯撤销供应商输入。

### UC-05 跨会话搜索（AC-02、08、09、10）

输入“上次讨论的子任务额度”或中文两字词，命中原话并打开准确位置。用户可显式切换所有工作区、历史分支和子任务；模型默认范围不随人类全局筛选扩大。语义未准备时仍可关键词搜索，并明确当前模式。

### UC-06 索引重建、删除与来源（AC-04、07、11、12）

索引中途编辑记忆、归档会话或切换分支，随后旧embedding返回并重启，旧内容不能恢复。仅依赖旧来源的候选失效；已确认记忆保留独立事实及来源不可用提示。清空派生索引再建不丢记忆事实。

### UC-07 模型资源与退出（AC-09、13、14）

空缓存离线启动、取消模型准备、前台查询与后台索引并行、注销及关闭应用，分别观察词法可用、状态说明、无旧结果回写和所属Worker退出。不能用“调用方不再等待”冒充原生推理已被硬中断。

## Issues

当前deleteSession是session.deleted归档，日志与正文保留，不是物理擦除；学习和索引必须检查归档/分支可见性。请求私有快照仅在JSONL，不能从公共快照或SQLite的空privateData反推。

当前启动清空并重放会话投影；新记忆事实、来源和向量缓存若直接依赖该删除顺序，会丢数据或每次重新推理。M6必须将独立事实与可重建索引分别对账。

现有工具向量Worker取消不硬中断活动原生推理，且桌面未预置模型。M6索引不能直接沿用无优先级长队列，或把首次联网下载当作普通查询/启动前置。
