# M6 实施顺序与完成门槛

本页拆分[Spec](spec.md)的实施范围，机制见[设计](design.md)。2026-11-11按0.19.1重新规划；用户已授权顺序开发，M6.1–M6.6原方案实现及本机验证已完成；2026-11-12按用户授权替换M6.4保存策略，以下直接保存新链路已完成重新验收，证据见verify。规划完成、已有M4工具向量检索和旧平台证据都不代表M6完成。

## 阶段依赖与交付

| 阶段                      | 可交付结果                               | 依赖与主要风险                                           |
| ------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| M6.1 固定记忆闭环         | 人工保存、自动采用、管理、重启及遗忘生效 | 先确立独立事实与请求最终化；请求调度改造风险最高         |
| M6.2 持久检索与本地资源   | 有权限过滤的词法/语义检索，资源显式准备  | 依赖M6.1的数据与来源；索引恢复、Worker真实取消和短词质量 |
| M6.3 相关回忆与主子范围   | 每次请求按当前输入召回，解释实际采用     | 依赖M6.1/2；阈值、上下文分配及跨任务隔离                 |
| M6.4 直接保存、学习与画像 | 对话直接保存、默认学习、有效条目画像     | 复用M6.1的写入和来源；不依赖完整跨会话搜索界面           |
| M6.5 历史搜索与精确定位   | 找到旧讨论、只读打开原位置、引用与工具   | 依赖M6.2；有界源窗口、历史Task及虚拟定位工作量较大       |
| M6.6 综合验收与收口       | 权限、质量、性能、恢复和桌面证据         | 各阶段同步测试，最后汇总；不留到结尾才测检索质量         |

推荐按表顺序交付独立可用阶段。M6.4和M6.5在前置能力完成后可按拥有者并行，但不能同时修改同一来源解析或请求入口。公共来源查询由storage持有、认证解析由daemon持有；首个实际消费者接入时完成，不预建万能来源框架。

不按文件数估算工作量，也不在缺少测量时承诺工期。先完成M6.1的真实闭环，再根据调度和质量结果调整后续任务；不从全量历史自动抽取或大规模向量化开始。

## M6.1 固定记忆与请求最终化

- [x] 新增有实际消费者的memory领域包，接入workspace/exports、源码边界、类型、lint、测试及生产部署；SQL、工具定义、Worker仍由各自现有模块拥有。
- [x] 明确profile owner/user/workspace及无工作区范围，实现记忆、设置、最小来源、revision和写入receipt；独立事实不进入会话投影重建删除清单、不级联依赖投影表。
- [x] 实现认证、有界管理API和revision/幂等事务；设置页及消息菜单可编辑正文、scope和固定采用，保存结果区分有效事实与失败。
- [x] 实现「允许Agent使用记忆」与明确默认值；固定项按获准范围自动采用，首版无需输入框picker、提案工具或embedding。
- [x] 拆开请求准备草稿与最终提交；压缩在获取名额之前，获名额后复核当前授权/全部合法固定项及设置，失效先释放再重组。限制本地重组次数，不自动重发已交出请求。
- [x] 将最终usage和context.prepared同批提交，记忆正文只出现于prompt中的一个有界JSON块；私有记录引用整块范围，同步schema、codec、恢复及拒绝非法范围的测试。
- [x] 以memory类别计算上下文，固定内容超限明确诊断，不静默漏项；子任务首版仅自动采用当前获准workspace固定项。
- [x] 从prepared建立最近每Run/Task的采用投影，接入上下文面板；显示当时正文、scope、来源和当前变化，不用现库回填旧请求。
- [x] 用临时SQLite/JSONL、HTTP和浏览器证明保存→新会话采用→重启→纠正/停用/忘记；证明投影重建保留事实、重复写入不复活被忘记条目。
- [x] 用可控Provider/调度名额验证等待期间新增/修改/删除/关闭、并发为1时必要摘要、持久失败、取消及实际流settled；覆盖根请求与子任务，不能只测领域函数。

门槛（AC-01–06、09）：有效固定记忆能自动影响实际请求，并能解释当时采用；遗忘对尚未交接Provider的请求生效。完整用户闭环完成后才进入相关召回，不以CRUD或回答「记住了」代替。

## M6.2 持久检索与本地资源

- [x] 新增有界持久正文/成员关系查询及来源校验，排除live delta、thinking、system、私有codec与原始工具大结果；稳定消息正文按ID/hash切块一次，共享分支以成员关系表达。
- [x] 在现有profile数据库实现来源/分块、普通FTS5、向量及索引签名；明确中文单字/双字、标识符、长查询、MATCH语法构造与原文验证。
- [x] 先过滤合法来源再做词法/独立语义候选、融合、去重和分页；记录降级与覆盖率，不用词法候选重排冒充独立语义搜索。
- [x] 将daemon/search推理收紧为真实多消费者服务；宿主队列持有待派工作，一次派发一个有界批次，前台优先、后台小批且有公平性。
- [x] 显式准备固定模型、状态与本地专用加载；当前工具检索也接入同一资源拥有者，避免旧入口仍在首次查询下载。
- [x] 排队取消即移除，活动取消仍等待真实settled再复用容量；禁止迟到回写，关闭终止并await Worker。取消不得被吞为普通词法降级。
- [x] 实现增量幂等、事实/成员关系复核、向量CAS、新代际重建/变化补偿和启动对账，重启复用有效向量。
- [x] 从此阶段起测真实模型的短词/混合/同义/负例质量；覆盖空缓存离线、准备取消/失败、缓存断网重启、签名变化、并发重建和资源退出。

门槛（AC-02、09–12）：持久混合检索独立于工具目录可用；未准备资源时词法可用且不下载，索引滞后/重建不泄漏失效正文，不每次重启重算全库。

- [x] 按本次实际消费输入召回；follow-up/steer更新查询，通信与Task目标保持各自来源，不永久用Run首问。

- [x] 采用面板区分固定、相关、截短/未采用原因；验证当前输入、新增相关条目、负例、父关闭采用、遗忘及主子/兄弟隔离。

## M6.4 对话直接保存、自动学习与画像

- [x] 工具按职责独立定义save_memory/learn_memory/update_memory/delete_memory，根Run绑定窄handler；保存/学习/纠正直接执行，删除使用原审批策略。
- [x] 直接写入保持真实人类来源与toolCallId绑定、scope隔离、revision冲突、去重、幂等和无正文遗忘抑制；子任务不能写入，低信任引用不触发自动学习。
- [x] 删除pending提案、确认/拒绝、单消息学习动作、TTL/grant、队列冻结字段和无消费者的动态能力移除逻辑；schema16清除旧提案表并迁移设置。
- [x] Web移除审阅与学习菜单，仅管理已保存条目；工具用统一折叠行呈现，真实成功事件刷新记忆事实。
- [x] 验证默认学习、关闭/执行交错、明确保存/纠正、普通/完全访问删除、冲突/重试/遗忘、根子隔离和来源先后。

- [x] 新增只读source resolve、目标周围有限窗口及分页，验证精确消息/hash和分支/Task锚点；读取不写branch.selected、不依赖整分支snapshot。
- [x] 当前时间线按稳定entry退出follow、展开过程、scrollToIndex及测高校准；不查找未挂载DOM或改为全量渲染。
- [x] 非当前分支/归档目标用只读历史阅读，任务目标从准确Task及around-message页打开；不从cursor0遍历，也不依赖当前分支任务列表。

## M6.6 联调、质量与交付

检索样本作为本功能测试fixture，不另建评测平台；质量基线从M6.2开始采集。

- [x] 按差异运行protocol/memory/storage/runtime/tools/daemon/Web源码测试、类型及静态检查，覆盖M1–M5相关回归，新增package和资源进入生产部署smoke。
- [x] 至少60条中/英/混合标注查询，含中文单字/两字、精确标识符、同义零词法重合、冲突事实及无关项；分开校准集与持出集，记忆/历史结果分项报告。
- [x] 比较词法/语义/融合Recall@5、MRR及scope正确性；融合Recall@5至少0.85、无关查询自动采用率不高于5%是初始目标。自动采用另要求校准/持出记忆正例各至少50%被正确采用，避免以全部拒绝掩盖不可用；不允许额外错误采用。唯一精确原文定位和权限负例单列全通过，不能用平均分掩盖。
- [x] 记录设备、数据量、冷/暖缓存及后台索引并发；一万片段、数百记忆时稳态词法P95不高于300ms、暖混合P95不高于1.5秒，实际83.35/1135.74ms；后台重建结果单列记录，未达标先定位，不随机截断语料掩盖。
- [x] 真实固定本地模型验证质量/资源；假向量只证算法。临时daemon/Pi/HTTP/SSE/浏览器覆盖保存、采用、遗忘、建议、定位、重建与取消交错。
- [x] 分别记录macOS Electron真实窗口和部署资源、真实供应商联调及其他平台结果；不能以旧M5证据或源码测试替代M6真实链路。
- [x] 清理重复规则、无消费者字段和旧入口，更新架构/协议/技术专题/用户指南及roadmap；实际验证后才创建verify，保留未验平台/账户与M7范围。

门槛（AC-01–15）：实现、权限、持久恢复、本地真实检索及界面链路都有对应证据；性能和质量阈值如需调整，记录设备、数据及依据，不能静默降低验收。
