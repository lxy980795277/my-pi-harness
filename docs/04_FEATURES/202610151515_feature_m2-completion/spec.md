# M2 剩余功能与执行收尾

## Spec

状态：M2.1/M2.2实现与macOS本机验收完成，待用户统一体验验收；真实供应商未验证。Windows环境与M2.3由用户明确暂缓，尚未实现，不计为完成。不提交或推送。[验证记录](verify.md)列出本轮证据与限制。

### Roadmap Alignment

所属里程碑为[roadmap的M2工作区与执行](../../00_OVERVIEW/roadmap.md)。本次只补齐工作区、文件工具、Shell、审批、工具持久化与恢复。AGENTS上下文、附件/引用、预算压缩和Plan/Todos仍属于M3，不纳入本次。既有M2实现与证据见[基线Spec](../202610150930_feature_workspace-execution/spec.md)。

### Intent

以现有功能为基础补齐实际路径和生命周期缺陷，形成可重复执行的M2验收链，严格区分已实现、可本机验证和需要外部环境的部分。

### Constraints

- 不移动已发布事件、迁移或私有codec代际；公开工具ID不透明，新增记录可更换派生规则，旧记录按已存ID读取。
- 工作区根校验由execution拥有，注册允许目录别名并存realpath，执行仍检查根身份不变。明确拒绝敏感目录，API返回安全4xx，不能把无效目录报成存储500。
- 默认显示名适配协议长度，完整根路径不截断；显式输入继续严格校验。
- 模型工具路径使用相对正斜杠；宿主内部相对路径先规范化，不让Windows分隔符误触发输入拒绝。拒绝ADS、设备名和尾点/尾空格等有歧义的名称，具体策略在execution说明。
- 同一Run不同assistant轮次可复用SDK toolCallId；公开工具记录ID包含assistant消息锚点，SDK私有配对ID保持原样。
- Shell在leader退出后有界收集/关闭输出并回收所属进程组，不能为了等待继承管道的后代无限挂起；保留取消、超时及输出限额。
- 真实Provider仅使用显式 `MY_PI_HARNESS_TEST_API_KEY`、`MY_PI_HARNESS_TEST_BASE_URL` 和 `MY_PI_HARNESS_TEST_MODEL` 专用配置；不读取用户现有Keychain、不输出秘密、不把合成模型证明写为真实供应商验收。
- 本轮只收尾macOS，Windows环境准备与M2.3按用户要求暂缓。通用Windows路径规则可在本机验证，不能据此声明Windows工具、Shell隔离或实机验收完成。
- Windows原生隔离不能通过模拟process.platform或使用taskkill替代；不得未经明确授权在宿主配置全局管理员用户、WFP或ACL。没有平台证据就保留未完成项，不改roadmap消除缺口。

### Acceptance Criteria

- AC-01：合法长目录省略name可注册，显示名符合协议；敏感根在注册时拒绝，注册与执行策略一致，已有合法别名仍可使用。
- AC-02：嵌套文件读写/列表/搜索的内部路径可跨平台表示；歧义或危险Windows名称在进入文件操作前明确拒绝。
- AC-03：同一Run连续两轮复用SDK调用ID仍产生独立记录、正确模型上下文与分支历史，不停用会话、不混淆审批。
- AC-04：Shell普通退出保留尾输出；leader提前退出、超时与取消均有界回收，不产生新的悬挂。
- AC-05：执行已配置环境下的M2边界验收，并分别记录桌面目录桥、真实模型和Windows缺口，不能用skip代替通过。
- AC-06：M2.3只有真实Windows隔离、文件/网络拒绝、所属进程回收及实机检查通过后才能标完成。

## UseCase

- UC-01 注册长名目录或目录别名，读取其文件；注册敏感根或被替换根时明确拒绝，不写入不可用登记。
- UC-02 在嵌套中文/空格路径创建、读取、搜索；不接受Windows路径歧义或设备目标。
- UC-03 兼容模型连续两轮使用call_0，分别批准两个调用，恢复/新分支重放保留正确的结果与审批所属关系。
- UC-04 Shell写大量尾输出后退出，或leader提前退出留下管道持有者；前者结果完整，后者在总时限内回收并按事实返回。
- UC-05 使用隔离profile走通macOS目录桥、模型调用、文件修改/审批/Diff/停止/重启；缺少专用模型凭据时记录Not verified，Windows/M2.3记录用户暂缓且不执行。

## Issues

已修复：默认basename超过120字符会触发存储INVALID_RECORD；注册允许execution必拒绝的敏感根；Windows内部relative产生反斜杠后被外部输入规则拒绝；Shell在exit而非管道收束后构造输出；工具公开ID只按Run+SDK ID派生，跨assistant轮次冲突会被误判持久化故障。相应源码、实际文件/进程与浏览器链路已验证。

保留缺口：本机没有Windows运行器，按用户要求暂缓M2.3；专用真实Provider环境变量均未设置，合成模型验收不能替代真实供应商验证。
