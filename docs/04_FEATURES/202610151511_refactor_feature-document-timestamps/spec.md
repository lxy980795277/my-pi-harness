# 功能文档分钟目录迁移

## Spec

状态：目录时间戳迁移及2026-11-01功能索引补齐均已完成，见[验证记录](verify.md)。本专题只调整文档目录、索引、引用与命名检查，不更改业务行为；本次索引维护按用户授权本地提交，不推送。

### Intent

功能文档按北京时间精确到分钟命名，使同一天的多次功能、修复和重构按顺序排列。迁移现有目录并保留全部已写内容，后续 Spec 使用同一规则。

### Roadmap Alignment

属于M0文档组织维护。2026-11-01按用户要求补齐功能索引，沿用本专题；不变更任何里程碑状态、目录时间、功能正文或验收结论。

### Constraints

- 目录格式为 `YYYYMMDDHHmm_category_name/`，日期与小时分钟之间不加分隔符，时间使用 `Asia/Shanghai`，category 为 feature、fix 或 refactor，name 使用 kebab-case。目录表示文档建立顺序；同一功能的后续小修更新其 Spec，不为每次修改重命名。
- 缺少真实开始分钟的历史目录使用排序估计，不将估计时间写成已核实的开发开始时间。10月13日按工程底座、规范审计、模型会话分别补09:00、10:00、11:00；10月14日模型设置补09:00。
- 10月15日按 Provider 导航09:00、工作区执行09:30、设置加载与滚动修复13:00、工作区导航14:00排序。已有验证日期、结论和正文保留，只替换路径引用。
- 先建立本 Spec，再移动现有目录和更新全仓文本引用。文档检查拒绝旧格式、非法日期/分钟和缺少 Spec 的功能目录，验证记录仍仅在实际验证后生成。

### Acceptance Criteria

| ID    | 可观察结果                                                                     |
| ----- | ------------------------------------------------------------------------------ |
| AC-01 | 所有功能目录采用含分钟的新格式，原有 Spec/verify 正文和证据完整保留            |
| AC-02 | 仓库文档与源码的路径引用更新，文档链接检查通过                                 |
| AC-03 | 功能入口、AGENTS、工作流和路线图明确同一命名及历史估时政策                     |
| AC-04 | 实际命名检查接受合法目录，拒绝旧格式、非法日历/时间和缺少 Spec                 |
| AC-05 | 功能入口按目录时间倒序覆盖全部既有专题及Markdown，链接存在且不补造缺失验证记录 |

## Issues

旧目录只含日期，同日多项功能无法按创建顺序排序。历史分钟没有统一事实来源，因此仅补排序估计，不重写历史验证时间。

2026-11-01索引盘点发现，38个Spec均有入口，但新专题前插、旧专题尾部追加造成时间顺序混杂；专题内99份Markdown仅直接列出69份，漏列30份验证或补充设计。补齐入口并统一倒序，M4分项文档单列，保留初版记录的标识。
