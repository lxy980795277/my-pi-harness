# 自动初始化本机客户端

## Spec

### Roadmap Alignment

属于M0启动体验及M1应用登录维护；取消浏览器手工配对，不改变M6记忆能力或扩展M7验收范围。用户已确认自动连接方案，保留应用登录与来源校验。

### Intent

Web首次打开时自动建立低权限客户端，直接进入应用登录；已有有效应用会话恢复工作台。删除配对码页面、导航入口、终端输出、挑战状态、公开接口和专属协议。桌面继续使用所属main进程的私有启动secret自动建立客户端。

### Constraints

- GET `/api/auth/status`保持只读；POST `/api/auth/client`只接受空对象，经Host和严格Origin校验后建立或复用客户端，返回Cookie与AuthStatus。
- 客户端仅关联OAuth流程、CSRF与应用会话，不证明操作者拥有本机；初始化不授予业务API访问，不自动登录或跨Web/桌面共享登录。
- AuthStatus使用`clientInitialized`表达客户端状态；有效客户端复用，保留原CSRF与应用会话，不延长绝对有效期。
- 保留回环监听、Host/Origin、CSRF、GitHub应用登录、profile归属、会话撤销与SSE清理。桌面启动secret不进入Renderer。
- 不清理真实数据库、日志、凭据或工作区，不处理无关M6改动，不自动提交。

### Acceptance Criteria

1. 首次Web打开无配对页面或配对入口，自动初始化后展示应用登录；连接失败显示可重试错误。
2. 初始化后的未登录客户端无法读取业务数据；重复初始化不改变有效应用会话、客户端和CSRF。
3. 缺Origin、错误Origin/Host、未知初始化字段被拒绝；状态GET不签发Cookie；旧配对接口移除。
4. Web和桌面既有登录、恢复、撤销、跨客户端隔离及profile归属继续有效。
5. 专属配对实现、DTO及当前文档清理完整，相关静态检查、HTTP回归和真实页面流程通过；未执行平台验证明确记录。

## UseCase

| 用例           | 操作                                            | 预期结果                                        |
| -------------- | ----------------------------------------------- | ----------------------------------------------- |
| UC1 首次Web    | 打开自有本机页面                                | GET状态后同源POST初始化，显示应用登录，无手工码 |
| UC2 恢复       | 有效登录Cookie下刷新或重复初始化                | 身份、会话、客户端及CSRF保留，进入工作台        |
| UC3 失效与退出 | 客户端过期或应用退出                            | 自动准备所需客户端并显示应用登录；私有状态收回  |
| UC4 非法请求   | 跨站/无Origin初始化、未知字段或仅客户端访问业务 | 拒绝请求，不授予业务权限                        |
| UC5 桌面       | main私有bootstrap后加载Renderer                 | 自动客户端与应用登录保持原流程，secret不公开    |
