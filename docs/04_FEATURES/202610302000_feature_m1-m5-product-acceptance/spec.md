# M1–M5真实任务与可用性验收

## Spec

状态：2026-10-30已完成八项主任务及停止、排队、压缩、恢复专项的实际执行与证据复核，结论为部分通过，详见[验收记录](verify.md)。基线为产品0.14.0、公开协议22、SQLite schema9、提交524d59b；本轮修复已以0.14.0重包复测；2026-11-01按用户要求整理为0.14.1本地提交，版本元数据与实际验收包分别记录。任务完成表示已执行，不表示全部AC通过。

### Roadmap Alignment

本轮属于[roadmap](../../00_OVERVIEW/roadmap.md)中M7既有能力的统一产品验收，实际覆盖M1–M5。发现的修复仍归对应M1–M5维护；不开发M6，不提前完成M7的Trace、撤销重做、完整导入导出、正式安装器或全平台发布。M5已完成的开发和既有验收事实保留，本轮给出新版本与所选任务的实用性证据。

### Intent

按用户已确认的八项任务，从简单对话逐步增加文件、执行、附件、联网、插件、办公产物和多Agent协作，观察应用能否完成真实工作。完成标准包括答案与产物正确、交互连续、失败可解释、停止恢复可靠和证据可追溯，不能只看模型说“完成了”。

### Constraints

- 通过实际macOS Electron界面与已配置真实模型执行主任务；API、SQLite/JSONL及校验脚本只承担准备、观测、故障注入和独立核验，不替Agent计算答案、修复工程或生成应由产品交付的办公产物。界面点击/输入/上传/下载/刷新/退出走CUA。
- 主验收使用独立profile、Keychain namespace、合成应用登录、动态端口和专用工作区；只读复用被选模型配置及其凭据，不改原Provider或导出秘密。实际模型与合成登录分别记录，不能据此宣称真实GitHub应用登录已通过。
- GitHub插件不克隆或改写凭据owner、epoch、安装代。优先在已有有效授权的应用服务内建立专用验收会话及工作区，沿用原授权只读访问；该服务不参与重启/故障注入。若版本、授权或网络不足，登记外部阻塞并继续独立任务，不伪造授权成功。
- 数据、输入材料、控制器和原始证据分别位于忽略的output/m1-m5-acceptance-20261030及.cache；独立oracle不置于模型可读工作区。不会删除用户会话、数据库、工作区或停止原4311/5174服务。外部操作只读，不提交PR/Issue、邮件或其他服务写入。
- 保留现有任务数、深度、并发、轮数、超时、单请求输出、上下文和权限限制；不添加累计token额度。真实模型调用按已授权任务进行，不为冲高用量反复请求；记录实际时长与已报告用量，缺Usage保留缺失，不估作精确账单。
- 只读子角色不能Shell或写文件，即使full-access也不能提升；计算和产物由主任务或单一写角色承担。task通信、问题、计划、审批及停止均核对原Run/Task，等待不占模型并发名额。
- 办公文件逐个下载、重新打开并校验；结构正确、数值正确、PDF页图以及Office/LibreOffice实际渲染分别记录。缺渲染环境保留Not verified，不以ZIP/XML替代版式验收。
- 每项使用已固定输入和可观察断言；发生阻塞保留首败证据，按证据定位产品、模型、材料或外部服务原因。产品缺陷在授权维护范围内修复并定向复测，不弱化断言或隐藏失败。
- 本轮不自动commit、push、发布或操作正式签名；先前提交授权已由524d59b完成。用户后续要求提交时另走既有流程。

### Acceptance Criteria

- AC-01：保存基线版本、模型能力/推理、审批、依赖、输入hash及环境；独立profile与原服务归属明确，结束清理所属PID、端口及临时凭据，不泄露秘密。
- AC-02：T1真实流式、多轮追问、编辑分支、刷新、复制/统计及原始日志下载可用；完整历史和分支内容可由持久事实核对。
- AC-03：T2正确理解小工程、执行AGENTS约束、定位预埋问题并引用真实文件位置；原文件内容不被修改。
- AC-04：T3由Agent修复预埋错误并执行测试，独立oracle验证数值和受控修改范围；命令失败可见且能继续处理，不以模型自述代替实际退出结果。
- AC-05：T4正确提取CSV/PDF/说明，主动完成指定提问与计划审核，澄清后继续同一执行；附件来源、差异和核算可验证，刷新与多轮仍保持引用。检查点恢复工作状态时不宣称回滚磁盘。
- AC-06：T5按给定官方URL读取并产出有日期/单位/来源的事实表；逐项与原文核对，不能把不可访问或缺失字段编成成功。有限替换来源和停止无效探索，不无限猜URL。
- AC-07：T6真实GitHub连接的账户/仓库查询与Skill/工具发现有服务端和界面证据；受控MCP的发现、调用、拒绝、断连另行验证。两者不得互相代替验收结果。
- AC-08：T7交付并修改XLSX、DOCX、PDF、PPTX实际文件，公式/数值/页数和修改一致；下载文件与落盘hash可核对，必要渲染与视觉检查明确结果。
- AC-09：T8有并行调查、一次嵌套核对、任务详情/看板、通信或人工确认、独立结果与主汇总；三城市同年GDP/人口口径、来源和产物可核对，子任务无未授权Shell/写入，父终态后无活动后代。
- AC-10：排队输入、编辑重选、单停及整树停止、拒绝审批、命令失败和MCP断连各有实际操作及终态证据；副作用不因刷新、重试或恢复重复执行，结果未知不伪称成功。
- AC-11：实际触发一次上下文压缩并证明关键事实保留；刷新和隔离宿主重启保留已完成历史/分支/任务，等待中的执行中断且无自动重放。隔离检查按真实scope和显式可见关系判断，不将同profile普通历史搜索误称为跨工作区泄露。
- AC-12：八项及横向检查均给出Pass、Failed-product、Failed-model、Blocked-external或Not verified和证据；分开报告完成率、结果质量、交互问题、耗时及计量完整性，不将部分任务通过宣称为M1–M5全部能力或全平台通过。
