# 源码运行与插件资源归并

## Spec

### Roadmap Alignment

属于M0构建/部署治理及既有M2–M5工具能力维护，承接已提交的tools与sandbox分层。M6继续仅规划；Windows、本地隔离、真实账号及办公质量缺口不随本轮关闭。

### Intent

后端私有包直接导出TypeScript源码，开发与生产统一由独立Node和tsx加载。Web、Electron main及preload继续构建。将插件代码、manifest、App声明、Skill与专属脚本归入tools/src/plugins；共用支持按实际消费者归属，消除工具体系中确证无用的字段、接口和重复读取。

### Constraints

- 先提交既有改动：已完成基线8b62195、产品0.18.0。后续改动在用户再次明确要求后按0.18.1提交，不推送。
- 用户已暂缓导入后缀修改；后端相对导入继续保留.js，Web继续无后缀。源码运行不要求更改这一约定。
- 对齐已确认的源码执行与资源共置范式，保留Electron宿主、安全策略及本项目独立实现；不复制参考项目业务代码、提示词或Skill内容。
- daemon必须独立存在并由Electron监督；生产运行不依赖源码仓库、用户Node/pnpm、开发别名或遗留dist。
- 保留真实路径、资源hash与不可变快照、命令租约、权限撤销、取消和进程回收；不以资源移动为由放宽安全规则。
- 不改模型消息、工具声明/顺序、协议24、SQLite10或用户数据；不读取真实.env或凭据。

### Acceptance Criteria

- AC-1：后端所有私有运行包的exports和files指向实际源码，删除无人消费的后端构建配置、dist入口和源码覆盖别名。
- AC-2：daemon生产依赖包含tsx；开发、CLI、浏览器测试及桌面产物都从源码启动。Electron main/preload包含必要协议代码，保持JS/CJS产物。
- AC-3：tools不再有包根resources目录。专属脚本归各Skill，真正共享依赖保留单一实现、精确hash与来源白名单；PDF页图支持由文档读取所有者持有。
- AC-4：移除已确认无生产消费者的工具上下文字段及插件接口，同份App声明只读取一次；保留职责完整的现有模块，不机械减少文件。
- AC-5：无后端dist前提下通过类型、静态和相关行为检查；隔离生产deploy能读取PDF、运行四个物化Skill，CLI启动/退出/恢复及桌面应用目录smoke提供实际证据。
- AC-6：同步架构、运行/测试规范与当前入口文档；历史验证记录保留真实已执行命令。未验证平台/账号/正式安装事项单列。

## UseCase

- UC-1：清理后端dist后启动daemon并查询健康状态；取消、退出及重启恢复保持既有行为，缺少生产依赖明确失败。
- UC-2：从独立生产deploy启动，不用源码别名；插件manifest、隐藏.app.json、Skill及共享依赖完整，PDF读取和四个办公CLI执行成功，物化租约回收。
- UC-3：从实际Electron应用目录启动；main/preload不尝试由普通Electron加载裸TS，daemon用随包Node/tsx加载随包源码，桥与退出检查通过。
- UC-4：插件目录、加载/撤销与资源hash回归保持；畸形清单、越界来源和hash不符仍拒绝，真实权限判断不因移除无消费者字段而变化。
