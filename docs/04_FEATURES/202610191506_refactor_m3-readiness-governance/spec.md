# M3复核与M4前代码治理

## Spec

状态：M3复核、治理修复与macOS自动化验证完成，详见[验证记录](verify.md)。本轮不提交、不推送，不开始M4功能开发。

### Roadmap Alignment

对照现有roadmap复核M3.1–M3.8及其JSONL前置重构，在新增应用登录后的当前工作区执行验收；按docs/10_GOVERNANCE覆盖Renderer、daemon、Agent/存储、Electron与工程入口。M4前置登录沿用原Spec，MCP/Skill等M4功能保持未实现；用户暂缓的Windows Shell、浏览器新增目录与真实供应商验证不转移到M3。

### Intent

确认M3是否仍满足已约定的功能范围，清理可证实的缺陷、规则违规与过时代码，给出进入M4.1前的明确结论和验证边界。

### Constraints

- 保留当前未提交的登录与界面改动，不回退工作区；不读取真实凭据，不删除开发数据、工作区文件或其他项目文件。
- 按治理入口的高/中/低定义记录位置、触发条件、证据、修复与验证；没有实际问题不编造收益，不机械展开简单空值默认或删除动态入口。
- 遵守领域类型、弃用API、可读性、状态所有者、进程与订阅回收、JSONL事实和SQLite投影、依赖实际消费方等现有规范；不借治理扩张功能或新建无职责抽象。
- 根静态检查覆盖工程规则；产品行为验证采用M3定向源码/HTTP/存储/浏览器及受影响的登录、桌面回归。已有未变平台证据可复用，真实账号、Windows与签名安装不冒充自动化通过。

### Acceptance Criteria

- AC-01：M3每个子模块能对应当前实现与有效测试，区分功能缺失、用户移除入口和后续里程碑范围。
- AC-02：完成治理各领域扫描，可证实的高/中问题修复并有相应行为或静态证据；低风险建议明确是否实施及理由。
- AC-03：命名/业务联合/弃用/空值可读性/死代码与依赖检查考虑真实消费者，不产生未使用的新层次或删除动态测试/发布资源。
- AC-04：当前源码与构建产物通过必要检查，M3关键流程在登录门禁后仍可使用；未验证平台、用户体验与真实供应商单独列出。
- AC-05：更新实际受影响文档、roadmap状态与最终验证记录，给出是否可进入M4.1的结论，不将未实现M4能力标为完成。
