# M5实现后的代码治理

## Spec

### Roadmap Alignment

2026-10-30按用户要求执行[代码治理](../../10_GOVERNANCE/overview.md)，维护M0工程规范及M1–M5已实现能力，不开始M6。保留本次工作区中M5、会话持久粒度、回答错误展示及子任务审批修复的有效实现；真实供应商、Electron、Windows与发布验收仍按原里程碑记录。

### Intent

检查apps、能力包、脚本、测试及相关文档的职责、状态所有权、生命周期和实际死代码，重点消除未提交迭代中的失效实现、重复逻辑及遗漏的调用方。发现有证据的问题直接修复，不为治理增加新功能或机械重写风格。

### Constraints

- 按docs/10_GOVERNANCE的code、server、web、desktop逐类审查，分清已确认缺陷、规则违反和可选改进。
- 所有删除先核对源码、测试、schema、动态注册、构建与发布入口，不删除仍有效的M5功能、明确规划资产或无关用户改动。
- 不复制其他仓库业务代码、提示词或历史文档；依赖以当前安装版本和实际消费者判断，不为静态误报添加依赖或豁免。
- 不改变权限策略、自动重试、模型预算或既有数据，不操作用户凭据、真实模型、开发端口及会话文件。修复功能缺陷仍保留原所属Spec和验收边界。
- 用户未要求提交，本轮只交付工作区改动及证据；不自动commit、push或改写历史。

### Acceptance Criteria

- AC-01：覆盖Renderer、daemon/能力包/存储、Electron、脚本/依赖/文档四类范围，输出有位置、触发条件及证据的结论；未验收平台明确标记。
- AC-02：确认的职责混放、重复事实源、无效调用方、冗余逻辑及生命周期缺陷已清理或明确说明未处理原因，不删除有效功能。
- AC-03：按实际改动运行相关源码/类型、构建及必要真实浏览器/产物检查；不重复无新改动的通过检查，不用静态通过代替实机验收。
- AC-04：完成治理记录和相关权威文档同步，保留原M5平台及真实供应商缺口，无伪造修复收益或验证结果。

- UC-02：清理失效导出或重复逻辑时，同步真实消费者及文档；动态注册、CSS、schema和发布资源的入口仍有效。

## Issues

本轮审查与修复已完成，实际范围及检查结果见[治理验证](verify.md)；子任务审批继承及动态工具集指纹修复属于[M5 Spec](../202610281702_feature_m5-subagents-board/spec.md)的AC-12范围，其验证与问题记录继续由原功能文档拥有。

- [中，已修复] packages/storage/src/sessions/agent-tasks.ts的detail先读取完整Task快照，再第二次读取全部消息并在JavaScript中分页；工具和用量查询还解析整个Session的转录。长任务及兄弟任务增多时，500ms详情刷新不能保持页面级读取成本。改为SQL按ordinal和limit取页、按Task及本页锚点/待审批状态查工具，用量只读取目标子树的计量字段；保留完整snapshot供真实运行时消费者使用。
- [中，已修复] AgentTaskDetail.messagesQueue仅有schema、生产者及fixture，无界面或服务消费者，却每次传回全部通信正文。删除这一公开冗余字段及生产查询，同步消费者及协议版本；保留内部通信事实和listAgentMessages，不迁移或改写历史日志、数据库。
- [中，已修复] Web README仍描述已移除的执行/Plan输入模式；Runtime README与系统架构设计仍将实时delta描述为持久提交、或仅按snapshotSeq比较。按当前源码及权威协议修正这些过期事实，历史Spec/verify保留原记录。
- [中，已修复] use-task-detail的发送尝试只保留文本和旧Run，服务接受续作但响应丢失后，SSE推进latestRunId会让重试生成新requestId并重算continue，可能重复排队。冻结完整发送输入直至确认或明确拒绝，保留结果未知的重试身份，覆盖接受后断线及任务状态变化。
- [中，已修复] use-session把Work失效交给忙时丢弃的点击事件桥，较旧读取在途时最后一次持久变化可能被丢掉；Run结束又停止轮询，页面可持续显示旧工作状态。由订阅拥有合并失效与排空，关闭/切换后停止旧刷新，不修改通用点击桥的互斥语义。
- [中，已修复] Agent启动异常处理仅根据AbortSignal是否中止判定取消，导致子任务准备阶段的真实超时或树级故障被记为cancelled。由拥有者区分主动取消和故障，保留最先确定的原因，并覆盖准备阶段超时与主动停止。
- [中，已修复] Office产物下载只在根对话快照中查工具，子任务详情却复用相同下载入口，造成子worker成功生成产物后无法下载。改为按会话、工具ID及当前可见分支精确查询持久工具，支持可见子任务；保持来源、路径、摘要和跨会话拒绝，不将全子转录并入主快照。
- [中，已修复] journal-codec在任意run.finished时清除整个Session的请求基线，子Run结束会使活跃父/兄弟的后续请求重复落盘完整历史。只释放已结束Run的基线，保持其他Run独立；用交错编解码验证引用恢复及落盘粒度，不修改历史记录。
- [低，已清理] AgentBudget的RequestWaiter.signal只有初始化、没有读取；取消处理直接使用所属闭包的signal。移除这一冗余字段和赋值，保留监听清理与准入行为。
- [中，已修复] 全仓类型感知ESLint在默认约4GiB堆上限退出134，CI同样通过pnpm check调用该入口。lint脚本仅为ESLint进程显式设置8GiB上限，保留全部规则、范围及后续gate，不要求用户或CI手工设置全局NODE_OPTIONS。
