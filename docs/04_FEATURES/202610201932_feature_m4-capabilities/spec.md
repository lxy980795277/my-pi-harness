# M4 MCP、Skills与插件

## Spec

状态：M4.1–M4.9模块边界保持已确认范围。M4.1本地stdio已实现配置、秘密、启动信任、发现、有限工具选择及真实调用；SDK 2.3.1已锁定，Pi/JSONL与浏览器链路已通过定向验证，整体验收记录见[本地MCP验证](verify.md)。2026-10-22已完成M4.2–M4.9的工程实现与macOS本机自动化联调，见[本轮整体验证](m4-completion-verify.md)。Office必要视觉检查、真实供应商与Windows适配/验收仍未完成，整个M4尚待统一验收；各子Spec保留具体边界。真实账号、第三方Server及平台证据独立记录，不以本地fixture代替。

### Roadmap Alignment

本轮完整覆盖既有M4：MCP stdio/HTTP/SSE、信任/凭据/OAuth、工具发现加载、Skills创建安装管理、插件市场、外部服务连接与办公文档工作流。拆为M4.1–M4.9是实施顺序，不改变所属里程碑，也不把其中一条最小链路当作M4整体完成。

M5子Agent、M6跨会话记忆/搜索和全局工具检索、M7完整Trace/导入导出/磁盘撤销不进入本轮。M4.2仅检索已启用、已信任的MCP目录，不做跨市场或embedding检索。Computer Use仍按用户决定排除；Windows Shell与浏览器新增工作区继续保留M2暂缓状态，不能据此把M4的Windows适配标为已验证。各模块工作包、依赖与完成门槛由[实施任务](tasks.md)维护，本Spec拥有功能范围、约束及UC/AC。

标杆当前实际功能与未实现边界见[能力核对](baseline.md)。这里只参考功能，不复制标杆业务代码、内部提示词、Skill正文、脚本或历史Spec。

### Intent

让用户能在设置中安装、连接和管理扩展能力，在输入框显式选择或由Agent按需发现使用；所有外部工具继续经过同一套审批、上下文预算、日志与取消管理。先完成一条真实本地MCP链路，再逐步组合远程服务、Skills、插件和办公任务。

### Constraints

#### 架构与依赖

- 保留Electron/Web/daemon/Pi与存储分工。计划新增一个有真实实现的packages/integrations，内部按mcp、skills、plugins、connections组织适配能力；不提前建立空包、通用插件框架或动态执行任意JS的插件系统。
- integrations不依赖React、Electron、Fastify、SQLite或运行时私有源码；daemon装配配置/凭据端口，agent-runtime拥有Run选择、工具适配、审批和模型可见内容，execution拥有进程/文件/网络执行机制。
- MCP采用官方TypeScript Client SDK；2026-10-20核对的版本与Node要求见[SDK核对](local-mcp.md#sdk核对)。已通过实际TypeScript/Pi兼容验证并在catalog/lockfile锁定client/server 2.3.1，不自写JSON-RPC或传输协议。[官方SDK](https://github.com/modelcontextprotocol/typescript-sdk)
- 远程HTTP指Streamable HTTP，SSE为显式兼容传输；不将MCP与当前页面HTTP/SSE协议混用，不提供对外MCP Server。Resources/Prompts先对齐目录发现、诊断和展示，未发现消费入口的能力不冒充标杆已实现。

#### 工具集、模型与持久化

- 现有会话/工作区工具已由接受时选定的RunToolset统一模型定义、预算、审计及运行时路由，来源/指纹单独保存在私有审计；底层execution和会话执行器对固定目录的参数复核继续生效。MCP的候选身份、配置版本、路由、定义指纹和授权绑定按Run固定，未发送选择不影响已接受Run；模型可见集合的动态管理仍归M4.2。连接按实际发现/执行请求取得租约并独立释放，不为整个Run预先持有所有Server连接。
- M4.2通过tool_search从已解析的候选目录显式加载完整定义，接入Pi公开prepareNextTurnWithContext等扩展点，不修改Pi loop。不是静态call_tool代理；新定义实际进入模型请求前先持久化，预算、Pi、审计与执行使用同一份可见工具集；每轮从当前active revision读取定义，不能继续使用RunExecution构造时捕获的初始列表。未进入该轮可见集合的候选工具不得提前调用。
- list_changed、配置编辑和Skill内容修改不在旧Run中无声替换定义；发现远端已无法兑现冻结版本则明确拒绝。禁用/撤销信任明确使相关活动调用失效，不能仅隐藏设置项。具体忙时重配语义在M4.1协议设计中确定并验证。
- 外部工具使用稳定短别名，保留serverId、原工具名、配置revision和定义指纹，不能靠人类可改名称拼接路由。动态schema在宿主校验方言、大小、深度和引用策略，不解析网络引用，不断言成TypeBox类型后跳过校验。
- MCP文本/图片、structuredContent和资源结果有明确有界投影。Pi不能直接使用的媒体给出可读说明或受保护资源引用；不把音频、资源链接或嵌入资源强转为文本/图片。需要模型推理的结构化值必须进入实际content，不仅保存在details里。
- SQLite拥有MCP/插件/连接配置与安装清单，JSONL保存会话选择、工具定义加载、Skill激活内容、调用及结果事实；私有模型/原始结果与公开摘要区分。秘密继续进入系统凭据库，不写入普通配置、JSONL、prompt或公开DTO。
- 沿用replay:never。已发送调用后断线/超时的结果未知必须单独表达，不能自动重试、报为安全失败或成为Todo成功证据；恢复不连接Server、不安装插件、不重新执行工具。

#### 信任、审批与生命周期

- stdio连接本身会启动本机代码，因此Server启动信任与逐次工具审批分开。command/args/cwd/环境变量来源、受管程序版本或远端endpoint/授权范围配置改变需重新确认，不能靠callTool审批补救未授权启动。
- 本地连接按Server配置、工作根和隔离策略隔离，远端按账户/授权范围隔离；full-access进程不能被ask/auto或Plan复用。模型请求中不冻结Token字节，刷新按凭据引用串行执行。
- ask/auto沿用macOS隔离与明确Server资源/网络规则，隔离不可用明确拒绝，不自动切换宿主执行。持久双向stdio不能直接套用当前一次性Shell输出收集器；实现时提取实际需要的进程拥有者，确认所属组与管道结束后才完成回收。
- MCP默认不因readOnly等外部注解自动获批；Plan/内部只读模式、用户审批、独立AI复核和full-access仍分别判断。经用户确认的只读策略及授权绑定定义/参数/配置/身份，变化后旧授权失效。[工具注解约束](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)
- 没有工作区不影响不依赖文件的远端MCP与Skill目录读取；本地执行明确要求注册工作区或经用户授权的受管cwd，不默认使用仓库、HOME或profile。Skill文本与图片资源经专用读取并检查模型能力，脚本及插件资源采用受管的只读版本/临时资源映射，不开放整个秘密目录。
- OAuth校验state、PKCE、issuer、回调归属和重放；清楚区分模型OAuth、MCP OAuth和Plugin OAuth。全局MCP配置不等于共享所有工作区的调用授权，应用账户与连接来源必须一致。
- 关闭覆盖启动、发现、请求、授权、安装、凭据刷新及所属进程；单个Run释放租约不能误关其他Run。远程取消不保证上游副作用撤销，明确保留未知结果。

#### Skills、插件与办公边界

- Skills按系统/插件、项目、用户作用域管理，解析标准SKILL.md及资源；兼容目录、同名优先级和无工作区行为在M4.4固定为明确规则，不能只沿文件系统偶然顺序覆盖。[格式规范](https://agentskills.io/specification)
- 目录元数据、完整指令、资源按需分别加载；显式选择记录稳定ID而非仅替换文本，贯通普通发送、steer/follow-up、队列编辑、编辑重发及分支恢复；同Run队列只能使用已冻结候选版本。真正加载内容/hash进入会话，压缩保留已激活指令，不从最新磁盘重建旧内容。allowed-tools或Skill正文不自动提升权限；Agent可显式申请、由用户批准后仅授权当前Run匹配的工具，内容/定义变化、撤销或Run结束后失效，路径/Plan/隔离限制继续生效。冻结旧指令不能延长已撤销授权。[渐进加载](https://agentskills.io/client-implementation/adding-skills-support)
- 创建/安装只操作明确选定作用域，使用受管暂存、来源/版本/内容校验与原子启用；GitHub安装不执行不受信的生命周期脚本。同名默认拒绝覆盖，系统/插件Skill不能被普通卸载路径误删；活动Run引用的资源不能被直接删除。
- 插件市场先对齐标杆内置目录及manifest装配，不新增远程市场、任意插件包、版本升级或依赖求解。覆盖Vercel、GitHub、Google、Notion、Supabase与四类办公插件；Computer Use不进入本轮。插件安装不自动授予工具或第三方账号权限。配置层记录插件/App/连接/凭据的所属与共享引用，卸载仅删除所属关联，不能按名称猜测或删除其他插件、手动Server及有效执行仍引用的凭据。
- 外部服务包含MCP app与Plugin OAuth/REST gateway两条通路，不能用“支持MCP”代替连接器。网关只开放明确上游、方法/路径/参数，宿主附加凭据，Skill和Shell不拿真实Token；网关调用还须绑定有效Run、已激活Skill、账户、有限权限与期限，执行同样的Plan/审批规则；只读POST按应用确认的业务语义判断。当前网关是宿主端口，已激活Skill经有限服务工具调用，不向任意Shell暴露HTTP网关或注入Token；未来脚本入口仍必须绑定同等Run/Skill/连接/操作grant，且不能复用浏览器Cookie/Token或取得上游Token；Run结束、撤销或断开后失效。子请求及成功/失败/未知结果关联父工具并写入会话事实，不能仅记录访问日志或把一次Shell批准当成全账户授权。具体服务地址/Scopes在M4.7按官方资料复核。
- 办公工作流以文件及可核验结果交付，不建Office编辑器或通用产物平台。已有M3文档提取直接复用；新增PDF页图及四类办公任务的脚本、提示词与资源全部独立编写。外部运行依赖先检测，不将插件启用当成依赖已经安装。
- 所有管理UI收敛到用户卡片中的设置Dialog；输入框“+”保留上传文件、MCP、Skill，随能力完成解禁。继续shadcn、紧凑布局、无路径赘述/聚焦光圈与现有Hook/TSX规范。
- 浏览器与Electron共用业务API，原生选目录、打开受信资源及授权跳转只走有限桥。macOS本机、Windows stdio生命周期、远程网络和真实第三方账号分别给证据，缺环境不写成跨平台通过。

### Acceptance Criteria

每个子模块分别提供Spec细化、协议、实现与验证；以下为整体必须覆盖的用户结果，M4.1证据见本目录verify，其余模块按各子Spec实现与定向验证，整体验收另记。

- AC-01 / M4.1：可配置、信任并启动真实受控stdio Server，发现和调用工具；批准/拒绝/取消/超时/关闭有实际进程与日志证据，配置和秘密分别保存。
- AC-02 / M4.2：重名/长名工具不串路由，无效schema拒绝；tool_search后下一次模型请求含完整定义，历史可重建该输入，预算与执行使用同一active revision，旧system投影不能丢失新增定义；定义/身份/参数变化使旧授权失效，旧Run不会热换版本；表单/JSON编辑、批量导入预览/冲突与脱敏导出可验证，env/headers秘密分流到凭据入口，不随配置导出。
- AC-03 / M4.3：Streamable HTTP与SSE均用真实SDK fixture走通；静态认证及OAuth成功/失败/取消/刷新/登出正确；越权目标和重定向拒绝，结果未知不重试。
- AC-04 / M4.4：目录发现、显式选用和Agent渐进加载均可用；资源越界拒绝，来源/hash可追溯，文本/图片资源和压缩后指令有效；显式工具授权只对本Run及匹配指纹生效，撤销或内容变更后失效，加载不自动授权脚本执行。
- AC-05 / M4.5：创建、GitHub安装、启停和卸载均有可用界面；详情显示资源清单，桌面可打开注册Skill目录；重复名称、取消、坏来源及失败回滚不会破坏现有Skill或工作区，重启可恢复安装状态。

- AC-07 / M4.7：五个服务族的账户连接与App清单明确；MCP凭据共享、引用归属及受限REST路径均有独立用例，网关校验Run/Skill/权限并记录子请求，不绕过Plan/审批；真实账户未配置时分别标记Not verified，不用fixture冒充供应商验收。

## UseCase

### UC-01 本地MCP端到端

前置：已注册工作区并准备受控stdio程序。操作：设置创建Server、检查启动范围并信任，诊断发现，在对话中批准一次工具调用。预期：收到结果并持久化来源/参数/审批；拒绝时不执行，停止或关闭回收所属进程。异常：坏配置、隔离失败、取消和坏JSON-RPC均有明确状态。

### UC-02 大目录按需使用

前置：多个已信任Server暴露重名与大量工具。操作：Agent搜索后加载少量工具再调用；另一客户端修改配置或撤销信任。预期：下次请求与日志含准确schema和来源，旧Run不换路由；撤销使相关执行失效。异常：非法schema、超预算和过期授权被拒绝。

### UC-03 远程服务与认证

前置：受控HTTP/SSE及OAuth服务。操作：静态头或浏览器授权后调用，触发Token过期/刷新，再断开账户。预期：秘密始终由宿主持有，账户范围一致且连接状态同步。异常：回调重放、issuer不符、跨源重定向、断线与未知结果不会静默成功或重复执行。

### UC-04 Skill选择与压缩

前置：安装有效Skill并有同名多作用域项。操作：输入框显式选择或由Agent查询/加载正文与资源，触发压缩；随后修改原Skill。预期：优先级明确，旧Run继续使用已冻结内容，下一Run才读取新版本；发送/队列/编辑/分支保留准确选择，未暴露或已撤销能力不能借队列激活。异常：资源越界/链接逃逸和未经批准的工具请求被拒绝。

### UC-05 Skill生命周期

前置：可写的项目或用户作用域。操作：创建Skill、从GitHub安装、禁用、取消一次安装、卸载。预期：成功项能使用，失败不留假状态，系统/插件项按所有者管理。异常：重名、坏包、解压越界和活动资源删除被拒绝或有界等待。

### UC-06 插件组合能力

前置：内置插件目录。操作：安装含Skill和MCP App的插件，逐项启停，再卸载。预期：设置和输入选择同步，清理所属配置/凭据，其他插件不受影响；当前Run不会读取被无声替换的资源。

### UC-07 外部服务两条通路

前置：配置相应服务OAuth应用；自动化使用受控替身。操作：连接账户，经MCP App和Skill REST gateway分别发出范围内查询，再断开。预期：账户/Scopes/凭据来源可辨识，未授权方法、路径或账户不能借网关访问；结果与来源进入会话。

### UC-08 办公文件交付

前置：工作区、已启用办公插件及明确依赖。操作：生成并修改DOCX/XLSX/PPTX/PDF样例，读取回验，必要时渲染或读取指定PDF页。预期：交付可打开的工作区文件及验证结果。异常：缺依赖、超限、损坏输入与取消明确失败，不删除源文件或承诺磁盘回滚。

### UC-09 重启、撤销与平台

前置：存在已加载Skill、已发现工具和在途外部调用。操作：重启、重建查询投影、撤销授权、卸载插件并切换客户端。预期：历史和不确定结果保留，原等待中断，不重连重跑外部动作；平台未验证项仍明确列出。

## Issues

本地MCP初期异常窗口见[本地验证](verify.md)。后续实现已处理以下问题，实际回归与剩余验收由本轮整体验证记录拥有：

- 协议15包含Skill选择、动态能力版本、连接来源、远程MCP草稿连接测试及插件只读详情预览；SQLite schema 6保存扩展与账户配置。所有消费者和宿主codec同步更新，不建立旧格式兼容层。
- WorkContext按当前可见版本重建工具声明和预算，真实Pi请求及context.prepared保持同源；私有候选定义、授权和加载事实在日志提交前校验，防止伪造定义或授权后派发。
- 在异步授权检查后、实际模型派发前再次同步核实授权；动态Skill加载被撤销时停止Run，只有真实持久化失败才冻结Session。
- 第三方OAuth client、系统浏览器回调及Office依赖有明确诊断。缺配置、Windows执行适配和必要视觉检查未完成时保留真实状态，不以fixture或文件保存代替验收。
- 开发桌面首次启动遇到既有v1会话日志，而本轮严格要求批次v2；这与开发期不兼容约定一致，但临时profile回归未覆盖用户的旧开发数据。先备份并隔离已确认不兼容的日志，再在独占profile下清理会话投影，保留Provider、工作区、应用登录及其他配置；不修改旧日志版本或在启动时自动丢弃数据。
