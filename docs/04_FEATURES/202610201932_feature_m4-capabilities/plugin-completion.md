## Intent

用户在服务插件详情中点击单一「授权」按钮，由独立弹窗请求授权地址并进入供应商页面，完成后显示账号并可断开。每个插件拥有一份凭据，所属共享授权App直接读取它，不再创建或关联通用账户。普通用户不填写Client ID/Secret、不添加或选择账户。App通过自身开关显式开启，Skill通过只读网关访问API。服务Skills提供可操作的任务工作流；Documents/PDF能够生成有排版控制、可核验的本地文件。

## Constraints 与设计

- 插件凭据使用0600的profile文件，与应用登录、模型凭据和高级多账户分别管理；保留统一审批、Run定义/Skill版本冻结与撤销。独立编写Skills与资源，不复制参考项目提示词、脚本或业务实现。
- 插件详情只显示授权状态与授权/断开按钮，关窗停止等待，不提供取消/重新打开、账户表单、选择器或手动关联。高级多账户与手动Token配置保留在独立连接管理入口。OAuth客户端由daemon专用SKILL配置提供，不回退到应用登录客户端，秘密不进入公开DTO、模型或日志。
- 插件声明拥有OAuth端点、scope、账号读取及只读网关规则；state/PKCE有效期10分钟，提前60秒按插件单飞刷新。回调和凭据发布复核profile身份、插件安装代及当前流程，卸载、断开或重新授权不能被迟到结果覆盖。
- GitHub/Google App共享所属插件Token，授权不自动开启App；其他App通过元数据声明独立MCP OAuth。App开关显式开启并信任所属固定配置；Token只允许用于精确所属App和官方endpoint。缺少客户端配置时明确报错，页面不恢复表单。
- Agent只读访问声明的HTTP网关，写操作使用明确开启的MCP App。公开gatewayUrl进入冻结Skill和会话事实，私有能力头仅由宿主web_fetch附加，不对模型公开。删除固定REST操作目录及逐Run服务grant入口；Google的Skill只读授权与各MCP App开关分别管理。
- GitHub提供基础路由、审查意见、Actions排障及提交发布工作流；Google提供路由及Drive/Docs/Sheets/Slides/Calendar独立工作流。资源按需读取，实际使用当前Run发现并获准的工具，不承诺不存在的REST operation或伪造MCP名称。
- 启动时自动对账随包受管Skills和App声明，保留精确引用及已有组件偏好；详情读取实际安装版本，旧Run保留冻结正文与资源；不作为任意远端市场升级器。插件开关控制Skill目录与所属App；内置办公工具继续独立受工作区策略控制，界面说明这一语义。
- DOCX在固定JSON工具中增加页面布局、字体/段落/富文本、页眉页脚/页码与受控工作区图片；补充有界格式修改和精确文本修订。复杂关系合并继续明确拒绝。
- PDF新增基于ReportLab Platypus的flow内容与自动分页、跨页表格、页面布局及页码，保留原固定页模式；补充受支持的choice字段及结果复核。视觉覆盖继续明确不是安全脱敏。
- 不添加任意源码执行器，不静默安装系统软件，不对真实账户创建授权或读取既有秘密。依赖不足时保留明确未验证结果；DOCX视觉质量只有实际渲染检查后才能宣称通过。

## UseCase 与验收

1. 安装GitHub，详情中没有添加账户、Client字段、账户选择器和手动关联；点击授权同步打开中转窗，由弹窗自行POST并跳转GitHub，完成后显示账号。Google五个App共享该插件Token且仍保持关闭；断开不误改其他手动账户、供应商或应用登录。
2. 关闭弹窗停止主窗轮询；卸载后的迟到回调进入错误结果页，不交换或恢复Token。重新授权、异步写入及刷新与撤销交错时，不能覆盖新凭据；过期、重放、跨目标或身份改变的桌面ticket被拒绝。
3. 开启一个共享App，只允许其精确归属和官方endpoint读取插件Token；关闭该MCP组件不继续派发其工具。Skill网关只允许声明的只读路径，禁止重定向；普通浏览器、应用Cookie或其他回环URL不能代替宿主私有能力。
4. 新Skills可预览、安装、按名称发现和渐进加载；已安装旧受管资源在启动时自动对账，保留原授权、App引用及组件偏好。参考资源能从冻结版本读取，停用/同步后旧授权不复活。
5. 创建含样式、布局、页眉页脚及受控图片的DOCX，结构及引用可核查；修改输出独立于source。生成多页长文PDF及跨页表格，重新打开、提取文字并查看页图，字段写入后复核结果。
6. 缺依赖、非法布局/路径/图片、超限、取消或解析失败保持明确结果，不覆盖源文件、不公开凭据。真实供应商及Office桌面版式验收单列实际证据。

### GitHub回调发行者修正（2026-10-27）

用户重新发起授权且过程中没有重启，新的安全提示将失败限定到授权响应校验。本机用假code/state/iss复现：正确GitHub发行者`https://github.com/login/oauth`在任何换码请求前被拒绝，而域名origin`https://github.com`反而通过。原因是插件适配器从授权端点取origin作为issuer；[GitHub官方声明](https://docs.github.com/en/apps/github-authentication-discovery-endpoints)的发行者保留`/login/oauth`路径。此前合成回调只有code/state，未覆盖iss。

插件manifest显式声明issuer，与授权端点分别拥有；校验使用声明值，不能从回调自报值或端点origin推断，也不跳过issuer/state校验。错误issuer使用固定提示，未知外部值不进入日志或页面。没有iss的回调保持原有支持，带iss时必须精确匹配；既有应用登录和高级账户声明不改动。

### 高级账户授权窗口

高级账户管理使用独立的父窗口请求流程；插件授权使用上方独立启动页，两者分别管理凭据和窗口所有权。

Web点击连接账户时，在首次异步请求前同步打开同源`/connection-oauth/launch?service=<供应商>`，立即切断新窗口的opener；原页面继续以现有登录、CSRF、账户revision/epoch请求授权地址，校验后控制已打开窗口跳转。中转页只有动画、受控供应商名称和关闭按钮，不挂载工作台、不发起授权/登录/工作区请求，不接受自定义跳转目标，不在URL中传递账户、Token或CSRF。StrictMode不会重复创建授权。

弹窗被阻止时不创建服务端流程；接口失败或发起请求期间卸载时关闭所属中转窗并保留原页错误。用户关闭或供应商COOP使句柄分离，不当成撤销授权；已创建的流程继续支持轮询、重新打开与明确取消。Electron保留`desktop.openExternal`，避免把桌面登录会话交给系统浏览器中的本地页面；权限校验及回调机制保持原有所有者。

UseCase：延迟授权接口时先看见中转页，响应后同一窗口进入GitHub；一次点击仅一次POST，原工作台保持不跳转；阻止弹窗不产生POST；服务端失败清理中转窗并显示错误；中转页直接打开不读取工作区或开始授权；重新打开复用原授权URL且不发新POST。使用合成服务与拦截的供应商页面验证，不进行真实用户授权。
