# 0.10.0

日期：2026-10-27。本次为M5前会话数据精简的本地提交，不推送或对外发布。

## 会话存储

- JSONL批次升级为v3，仅保留version、records、checksum，删除batchId、previousBatchId及可从事件推导的外层sessionId、firstSeq；保持事务分组、连续事件序号、归属校验、内容校验和、fsync与末行修复。
- privateData、模型codec、冻结队列绑定和请求messages使用原生对象/数组，清除多层JSON字符串编码；保留SDK消息、供应商签名及权限冻结事实。
- 同Run、同分支的请求历史复用上一快照消息索引，提示词可引用首system消息。相同工具展示正文复用同批canonical结果；不同、被截断或更丰富的展示结果仍完整保存。
- 读取先校验原始行再无损还原逻辑记录，Run结束释放请求基线，失败写入不推进基线。下载保持已提交原始文件字节；SQLite不再额外重复保存整份请求审计。

## 运行时与验证

运行时统一使用脱离SDK引用的JSON对象快照，保持原有可选字段规范化、消息回放、队列、分支、审批、派发屏障与结果未知语义；公开HTTP/SSE和对话展示继续使用现有协议。旧工具链E2E显式选择请求批准，不依赖产品默认完全访问模式。

在macOS arm64、Node24.20.0、pnpm10.34.6下，lint、类型、格式、8项实际构建任务通过；源码1589项通过、2项跳过，产物6项及15个不同浏览器场景通过。合成OAuth/模型与真实Office Python Worker覆盖续聊、队列、附件、计划、快照、插件跨重启和产物下载。完整命令、失败修复与限制见[验证](../04_FEATURES/202610271953_refactor_session-journal-compaction/verify.md)。

用户提供样例的只读内存重编码由4,793,736降至1,534,383字节，减少67.99%；1180个事件完整保留，逐批恢复后内容及键顺序一致。该测算不代表所有会话的压缩比例或输出性能提升。

## 版本与开发数据

产品与APP_VERSION为0.10.0，内部私有包保持0.0.0；公开协议17、SQLite schema8和公开事件envelope1不变，历史SQL迁移正文不变。JSONL批次由2升至3，旧日志和旧字符串codec不再读取，不提供自动迁移或兼容分支。

用户已明确授权并完成本项目两个profile的旧会话清理：停止占用进程，删除3份旧JSONL并清空13张会话相关表，保留模型、工作区、插件、登录配置及独立凭据；新存储重新打开后会话为空。其他开发环境升级前也需要明确处理旧会话数据，不能只删除日志而留下SQLite会话索引。

业务构建和浏览器验证使用产品0.9.1完成，本次提交另外同步0.10.0元数据并执行版本检查。没有生成新的Electron应用目录或安装器，没有新增真实账号、Windows、安装、签名或公证验收。M4剩余账号/视觉/平台项保持原状态，M5尚未开始。
