# 0.19.0

日期：2026-11-08。属于M0及既有M1–M5共享数据职责治理，按用户授权本地提交，不推送或对外发布。M6继续仅规划。

## 共享协议

配对、登录、模型认证挑战与Provider操作请求使用protocol中的同一schema/type。高级账户、MCP与Skill OAuth保留各自启动响应，Skill目录响应由daemon、Web和Desktop共用；原生路径检查仍属于桌面主进程。HTTP错误统一为code/message，保留领域错误映射、非JSON或畸形响应兜底及401授权失效通知。

公开ProviderConfig不再包含credentialRef；宿主使用protocol/internal的ProviderRecord保存既有记录，由Gateway明确选择公开字段。ToolContent统一执行、MCP投影与持久结果的文本/图像块，保留原限制和各自外层语义；移除仅用于类型推导的已解析会话输入schema及重复定义。工具参数、UI状态、领域接口及合理的纯共享工厂保持原归属。

## 默认Agent与存储

默认子Agent角色、指令和限制归agent-runtime，由daemon向storage显式注入，存储不依赖运行时实现。ProfileStoreOptions归profile模块。默认读取不写库；无配置且未注入时明确失败；完整配置首次保存只依赖数据库revision，保持0到1的递增与冲突检查。

## 兼容性与验证范围

根产品版本与APP_VERSION同步为0.19.0，公开协议由24升至25。Web、daemon与Desktop须同步更新；旧客户端不能继续依赖Provider响应中的credentialRef，宿主消费者使用internal入口。SQLite10、Provider持久JSON布局及Session JSONL格式不变，不需要数据迁移或清理。

[验证记录](../04_FEATURES/202611070332_refactor_protocol-contracts/verify.md)包含2108项源码测试通过、2项按原条件跳过、7项隔离生产部署及全仓格式、lint、类型和Web/Electron构建。源码全量使用2个worker并在命令期间临时防止闲置休眠，仓库默认worker、超时和断言未调整；记录保留首次超时及主机休眠的复核证据。

上述行为与构建验证基于0.18.4候选实现，本次同步提交版本与发布记录，不重新生成桌面应用目录。真实外部OAuth/Provider、Browser/Electron视觉、正式安装器、签名、公证及Windows/Linux未据此验收，既有Office质量与平台缺口继续保留。
