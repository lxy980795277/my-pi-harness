# 协作规范

分支和集成策略由用户授权及实际仓库状态决定，不自动假设主分支名为master。需要独立功能分支时可使用feat/、fix/、refactor/、chore/前缀；未经指令不创建或改写分支。

## 多执行者

明确每个执行者的文件或模块所有权，避免同时编辑同一文件。共享协议先协调再调整，所有实际消费者一起更新。其他执行者的修改立即可见，不能通过覆盖或reset清理不认识的内容。

## Review

检查目标行为、依赖方向、类型与外部输入、安全和资源清理、持久化与迁移、异常状态、检查证据及文档同步。PR说明面向未参与对话的读者，写问题、结果、验证和实际限制，不保留聊天历史。

## 冲突

先理解两边事实与意图，再合并有效内容。代码冲突以完整行为与约束为依据；文档冲突合并有效事实，避免重复和相互矛盾。历史改写或丢弃改动需要明确授权。

## 交付

报告实际修改、通过的检查和未验证路径；不能将同事的未完成内容标记为自己的完成证据。提交操作独立遵循八步流程。
