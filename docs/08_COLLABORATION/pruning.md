# 代码裁剪

裁剪用于移除已确认无职责的实现、重复状态与失效文档。先理解调用与发布用途，再在授权范围内改动；文件体积、静态未引用或长时间未使用只是调查信号，不能单独证明可以删除。

## 触发信号

- 同一能力存在两套实现或多个可写事实源。
- 文件持续增长并混合路由、状态、存储、平台或界面职责。
- 兼容分支没有实际消费者、版本或删除条件。
- 注释实现、backup/unused/deprecated副本和空package替代真实规划。
- 依赖没有源码、配置、样式、测试或发布资源使用者。

源码行数与职责审查见 [前端](../05_CONSTRAINTS/frontend.md) 和 [后端](../05_CONSTRAINTS/backend.md)，依赖误报检查见 [代码治理](../10_GOVERNANCE/code.md)。不以多建转发文件规避职责判断。

## 实施步骤

1. 搜索静态引用，核对插件注册、入口、构建、测试、样式、schema、动态加载与打包资源。
2. 确认消费者、兼容需求和用户数据影响；实际范围变化或未授权数据删除先对齐。
3. 删除或合并实现，更新所有消费者与相关依赖，不保留注释副本。
4. 更新架构、API、约束和当前功能说明；保留真实历史验证记录，注明后继变化，不删除证据假装旧行为从未存在。
5. 运行覆盖行为与产物的检查，交付范围和风险。只有用户明确要求提交时进入八步流程。

删除持久化字段、数据库、公开API或用户数据先定义迁移与兼容；已有用户授权的目标按Spec完成，不重复确认。未知消费者不能被假定不存在；需要继续保留的入口记录所有者、适用版本与退出条件。
