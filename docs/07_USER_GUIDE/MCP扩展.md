# MCP目录与远程服务

设置中的MCP支持本地stdio、Streamable HTTP和显式兼容SSE。远程服务不需要工作区，本地程序的添加方式见[本地MCP](本地MCP.md)。

## 连接远端服务

1. 打开“设置 → MCP → 添加 MCP 服务器”。默认“表单配置”填写MCP ID、连接方式和服务器地址；也可切换“JSON 配置”，使用单个`mcpServers`条目。连接方式仅Streamable HTTP和SSE，地址要求HTTPS公网。
2. 在“自定义 Headers”逐行填写请求头名称和值，例如Authorization与`Bearer …`。值只保存到系统凭据库，编辑时留空可保留已存值；地址或传输变化后需重新填写。JSON的headers用于新值，secretHeaders只引用当前配置已有的值，不会回显秘密。
3. 点“远端授权”，确认具体地址、传输和认证范围。授权不连接上游，也不代替工具审批。
4. 独立MCP OAuth点“连接 OAuth”，在新页面完成授权，再返回点刷新。如果需要预注册App，在`oauthClient`填写公开Client ID、issuer、scope等，Client Secret仍从秘密表单保存。应用登录的GitHub App配置不会自动用于这里。
5. 已在“连接”中授权的官方服务，也可以在远程编辑器的认证来源下拉中选账号；只显示与当前地址匹配的已连接账号。保存后再次确认远端范围。
6. 点“发现目录”，确认工具、资源和提示词条目。资源与提示词目前只展示目录，不自动读取正文或执行。

重新配置地址、传输或认证会使旧授权失效。Vercel可能要求审核客户端，Google等需要自己注册OAuth App；服务要求或权限不足会明确报错，不能用切换传输自动绕过。

编辑器中的“测试连接”执行真实MCP握手与目录读取，显示工具数量和耗时，不保存草稿或调用业务工具。测试提交的秘密Header值会清空，保存前请重新填写。已授权配置也可在列表中测试；OAuth需要先完成账户授权，测试不会自动开启登录。

## 工具目录与只读授权

目录中可以逐项停用工具。停用后再启用不恢复旧Run或旧队列授权；需要明确重新选择。Agent也可以搜索本次Run接受时冻结的可信目录，再按需加载定义，避免把大量schema一次放进上下文。

“可信只读参数”表示你确认某个工具以某组精确JSON参数调用时只有读取行为。它绑定当前身份、Server版本、工具定义及参数；修改或撤销后失效。外部工具写着readOnly并不能保证没有副作用，不会自行跳过审批。内部只读审批模式只放行当前仍有效的精确授权。

“高级配置”中的“导出脱敏配置”下载公开配置JSON；“导入JSON配置”先预览，再确认批量创建。导入项保持停用，秘密和信任需要重新配置，名称冲突不会覆盖已有Server。

出现“结果未知”时，操作可能已经生效。先核验目标系统，再以新的明确输入决定下一步；应用不会重启旧调用来猜测结果。
