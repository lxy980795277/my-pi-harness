# 子 Agent 与任务看板

主Agent可以通过工具把独立任务交给子Agent。子Agent使用自己的上下文，收到明确转交的任务和附件；它的完整消息不会直接插入主聊天，主Agent可以等待结果后汇总。

## 角色与限制

在用户菜单的设置Dialog打开“子 Agent”，可启停委派、选择角色模型及推理强度、调整角色说明和限制。调查与审查角色只读，执行角色可在继承权限内修改文件或调用写工具；角色不能扩大当前工作区或MCP/Skill权限。

子任务继承主对话本次运行的审批方式。选择“完全访问权限”后，只读调查任务获取网页等允许操作无需额外批准；选择“请求批准”或“帮我批准”则分别沿用人工或AI复核。只读角色仍不能发送网页POST、修改文件或执行Shell，批准策略不会扩大角色能力；明确的Skill工具授权仍需单独确认。

未指定模型时继承父执行。配置修改作用于新任务，不替换已经开始的任务；关闭委派不会擅自重启或更换活动Task。根树上限保持接受时的配置，新任务还受父任务剩余预算和权限约束。

默认限制为整树16个子任务、3层嵌套、4个并发模型请求、委派后每次Run最多16轮请求、10分钟树时限、200000 token预算及单请求4096输出token。尚未委派的普通主对话保持原模型输出与32轮限制；请求消耗仍计入后续树预算。token预算包含请求前估算和供应商返回的实际计量，不能用来承诺精确费用。

## 查看与操作

- 会话header的任务入口打开当前分支任务树，选择节点查看角色、模型、限制、输入、结果和工具。
- 左侧“任务看板”查看跨会话任务，可按工作区和状态筛选。等待回答、计划审核及工具批准显示为待处理；等待后代与等待模型名额分别标明。
- 任务详情可以补充消息。运行中消息在安全输入边界交给原执行；显式续作会创建新Run并继续该Task自己的历史，不会重新执行旧Run。
- 详情中的停止只停止该任务及后代；输入框的停止结束当前根执行及其整棵子树。按钮等待真实资源结算，不只改变本地状态。
- 提问、计划审核和工具审批始终显示原任务来源。关闭详情会保留未提交选择和文字，重新打开可继续；注销清除这些本地草稿。

子Agent之间的通信在详情标为“任务通信”，不会显示成用户提问或增加对话次数。只有直接父执行仍接受命令时才能续作；父执行结束后，原任务作为历史保留，需要重新委派新的任务。

补充消息或续作的发送结果未确认时，详情保留原文及重试入口，关闭后重新打开也可继续确认；重试仍确认原来那一次发送，任务状态变化不会变成新消息。明确拒绝后可以修改，成功后清空草稿；这些待确认输入不跨整页刷新持久保存。

## 状态与恢复

任务可处于待开始、执行、等待或已结束；结束保留成功、失败、停止和中断的区别。没有明确任务分母时不展示猜测的完成百分比。

刷新页面从服务读取已有事实；关闭详情不会停止后台执行。daemon重启会把在途执行和人工等待标为中断，保留已完成结果，不自动调用模型或重新执行工具。未被消费的通信会明确结算为未送达。

同一任务树同时只有一个写入拥有者，子任务获准写入期间其他任务只读。该协调不隔离其他应用，也不自动撤销文件、Shell或第三方服务的操作。

正式模型供应商、Electron和各平台的验收范围见[M5功能记录](../04_FEATURES/202610281702_feature_m5-subagents-board/spec.md)，当前接口见[任务协议](../03_API/agents.md)。

## 快速体验

更新代码后完整重启应用，在设置的“子 Agent”确认委派启用，使用支持工具调用的已配置模型。新对话可发送：

> 请使用spawn_agent创建两个researcher子任务：一个分析Zustand适合管理哪些状态，另一个分析TanStack Query适合管理哪些状态。不要自己直接完成。使用wait_agents等待两个任务完成，再汇总它们的结论。

标题栏应出现任务数量；打开任务树或左侧任务看板，可以分别查看两个任务的输入、独立消息和结果。主聊天只保留主Agent过程及汇总。运行结束后刷新，任务历史仍应可读。

人工等待可用以下请求验证：

> 请创建一个researcher子任务，让它先使用ask_user询问我更关注性能还是代码可维护性，收到回答后再给建议。主Agent使用wait_agents等待它完成。

从任务的待处理入口填写答案，关闭详情后重新打开，确认选择与文字仍在；提交后原任务继续。另一次可在等待时点击详情的停止，确认只取消该子树，主Agent收到实际取消结果。输入框的停止则结束根执行和整棵子树。
