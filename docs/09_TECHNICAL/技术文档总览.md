# 核心技术设计

本目录面向理解和维护系统的开发者，只记录值得长期解释的核心设计：系统要解决什么问题，状态由谁拥有，关键流程如何执行，失败如何恢复，以及当前取舍和边界。文档随实现更新，不作为开发流水、依赖版本审计或通用经验汇编。

| [Agent运行时](Agent-Runtime.md)         | Pi分工、Session/Run、模型与工具循环、队列、停止、提问与计划审核   | 谁拥有一个任务？等待用户后怎样继续同一个Run？       |
| [上下文管理](上下文管理设计.md)         | 规则/附件冻结、请求投影、预算、裁剪、摘要与原文检索               | 长任务如何持续执行？模型实际看到了哪些内容？        |

建议先读系统架构，再按工作方向进入其余专题。调查数据恢复优先看会话存储；调查模型请求质量优先看上下文管理。专题按职责相互链接，不另建同一主题的简版或历史版。

## 收录与维护

- 文档按主题清晰命名，优先使用中文名称，入口统一为技术文档总览.md；重命名同步所有引用，不保留别名副本。
- 新增主题应具有独立状态所有者、跨模块关键流程或需要长期解释的失败/恢复机制；普通表单、控件、CRUD与基本配置不单独成文，优先更新已有专题。
- 开头写日期、模块、实现锚点与真实状态；正文按问题、核心思路、架构/时序、状态来源、关键机制、模块、边界和验收要点展开。按复杂度取舍，不靠增加代码摘录和检查清单凑篇幅。
- 图、伪码和数据示例必须对应当前实现，伪码显式标注；引用实际源码和验证入口。已实现、自动化验证、人工体验和后续规划分别描述，不将参考项目能力写成本项目现状。
- 机制变化直接更新所属专题及受影响的图和链接；迭代经过、问题修复和实际执行证据留在功能Spec/verify，不在本目录累积历史日志。
