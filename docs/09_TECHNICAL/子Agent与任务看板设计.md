# 子 Agent 与任务看板设计

**日期**：2026-10-29

**模块**：agent-runtime的agents/runs/context/work/tools、storage的Task投影、daemon任务API及Web tasks。

**实现锚点**：AgentRuntime、RunExecution、AgentBudget、WorkRuntime.forTask、AgentTaskQuery。

**状态**：工程实现及macOS自动化验证完成；实际命令及平台范围由[M5验证记录](../04_FEATURES/202610281702_feature_m5-subagents-board/verify.md)拥有，真实供应商及桌面平台尚未验收。

## 要解决的问题

子任务需要独立的模型上下文和执行资源，同时必须属于用户当前看到的对话。任务在并行、等待、通信和停止时不能共享错消息，父执行结束后也不能遗留失去拥有者的模型、工具或人工等待。

核心思路是一个可见Session、一份JSONL和一棵任务树。AgentTask表示稳定任务，Run表示一次实际Pi执行；执行树、看板与聊天引用同一组持久事实，不创建隐藏Session或第二套模型循环。

## 归属与独立上下文

Task记录创建它的sourceToolCallId，从原工具记录推导直接父Run、分支及助手消息锚点。子Run记录taskId，根Run省略该字段。父Task、根Run、深度、最新Run和汇总状态由查询投影推导，日志不重复保存这些关系。

一个Session仍只有一个活跃根Run，子Run由AgentRuntime拥有。根队列、分支和主聊天继续按原规则工作；Task拥有自己的消息序列及WorkState，复用同一WorkRuntime/context实现。初始输入只包含委派目标、显式附件、角色和获准能力，不自动复制主会话历史。

Task创建先持久化，再准备模型与上下文，随后提交子Run接受和初始消息。准备失败关闭Task，接受后初始化失败补写明确失败的Run终态并清理资源；持久化本身失败时停止所属树，不能继续广播假完成。

准备阶段按拥有者首次确定的终止原因收束，主动停止与超时故障分别记录为取消和失败；AbortSignal已中止本身不表示用户取消。后续停止不能覆盖已确定的故障原因。

同一Task可在直接父Run仍接受命令时显式续作，使用独立历史创建新Run。等待冻结的是当时Run，不是一个以后可能多次续作的Task；结果按对应Run的最终助手消息读取，不把前一次成功答案用于解释后一次失败。

历史任务沿最外层委派的助手消息锚点判断是否被当前分支保留。仅按rootRunId判断不够，因为同一根Run可能消费多次输入，而编辑后的分支只保留其中部分消息。

## 角色、能力与写入

用户配置启用角色、角色说明、模型/推理强度和树级限制。新Task读取当前角色设置并冻结，已有Task不热换；根树预算保持接受时的上限，新Task限制只能在父范围内继续收窄。显式模型失效报错，省略模型才由解析拥有者继承父选择。

只读角色不提供Shell或未知副作用工具，MCP仅保留已具备只读授权的候选，实际参数仍需通过原授权检查。当前工具集、动态候选与实际执行路由同时收窄；加载Skill或嵌套委派不能恢复被排除的权限。

角色能力和审批方式分别拥有：Task冻结的role.access决定是否只读，子Run继承父Run接受时的approvalMode，不将只读角色转换成人工批准。RunExecution把角色只读和已有会话只读限制合并为内部ToolRunContext.readOnly；ToolRuntime在工具审批、写入仲裁和派发之前拒绝受限副作用，底层文件/Web执行使用同一限制。允许的GET分别沿用ask人工、auto独立复核及full-access自动批准；完全访问不授予角色原本没有的写能力。request_skill_tools的显式人工授权仍独立生效。

审批方式由run.accepted已有私有请求快照记录，角色能力由task.created已有role记录，公开DTO和日志不重复保存有效只读字段。嵌套不允许只读父创建写角色，原Task续作复用冻结角色并继承仍存活的直接父审批快照；全局配置修改不热换这些事实。

同根树只有一个写入拥有者。文件修改、Shell及可能写入的外部工具均在派发前检查拥有权；原在途写操作结算后才可向后代转交，转交期间父任务和其他任务只读。任务实际结算后归还仍有效的上级，收束时撤销。该机制协调本树写操作，不保证树外应用不会改文件，也不提供任意Shell或外部系统的事务和回滚。

## 调度、预算与结果

AgentBudget限制真实模型请求的并发，等待后代或用户不会长期占用模型名额。准入同时检查根和各祖先Task的限制；队列选择最早可运行请求，受限子树不能阻塞仍有额度的其他分支。

根预算只有一份共享余额，子Task限额不是另一次额度分配。请求前原子预留输入估算及输出额度，最终按实际Usage结算；同一请求只记账一次，祖先消耗派生。Pi传入规范化TranscriptContext，系统提示与工具声明已位于system消息中，估算复用messageTokens计算，不重复加一份工具目录。

缺少供应商Usage时保守保留估算，界面不宣称精确计量或费用。任务数、深度、每次Run请求轮数、时限及单请求输出也由宿主限制，终态和取消记录不受剩余额度阻断。费用估算与完整主子Trace仍属M7。

父模型应通过wait_agents收集后代结果再汇总。若提前输出最终答案，运行时先结算已有后代，界面保留未汇总结果，不伪造已汇总答复或自动新增一次主模型调用。普通子失败返回真实结果供父判断，外部unknown则停止所属根树，不能自动重试。

## 通信来源与消费

通信限制在同一根树，目标为父Run或稳定Task，发送者从当前执行推导。队列先持久化，实际消费与对应message.started同批提交；agentMessageId是公开消息与原通信的唯一关联。批校验拒绝缺少关联、跨Run、不同正文及一条通信消费成多个输入。

Pi将steer输入表示为user消息，因此模型输入由context/agent-message.ts统一加上发送者和“任务资料，不是新用户请求”的说明。公开消息保留原文及agentMessageId，上下文来源匹配根据持久通信重建完整SDK输入，不按文本后缀猜来源。主聊天与对话次数过滤该来源，任务详情明确显示任务通信；内部消息不能经编辑重发冒充用户提问。

普通发送不自动启动收费模型请求，只有显式continue才可续作空闲Task。重试命令以规范化通信键识别，已接受的新Run和根结束后的重复请求都不会重复执行。直接父Run进入收束后拒绝续作，新运行应创建新任务。

界面将发送文本、requestId、continue和expectedRunId作为完整待确认输入保留在非持久Store，关闭详情或Task状态推进不重建它。未知响应只能由用户重试原输入确认，成功或明确拒绝后释放；授权撤销统一清理。草稿与服务器通信事实分别拥有，不把待确认请求当作另一份已接受消息。

## 停止、关闭与恢复

父Run写终态前必须等待或取消并结算后代。停止覆盖任务排队、模型准备、模型请求、工具及人工等待；重复停止共享真实结算。资源join使用allSettled，先等全部实际工作结束再聚合错误，不能因一个失败提前释放兄弟拥有者或关闭依赖。

收束关闭新的通信、委派与续作入口，已接受未消费消息结算为未送达。模型lease、Skill绑定和写入拥有权在实际结算后释放。daemon先拒绝新工作，取消并等待树，再关闭MCP、模型与存储。

启动按JSONL重建Task、通信、消息及工作状态投影，自底向上中断全部在途Run和交互，同时关闭失去父拥有者的开放Task。已完成结果保留，恢复不自动重发模型、消费通信或执行工具。

## 页面呈现

任务看板提供工作区和状态筛选，服务端在分页前过滤。会话header的固定入口打开执行树和详情，不增加状态行。根聊天只显示轻量委派工具及明确结果，子转录按需读取，关闭详情不停止执行。

Query拥有服务端任务事实，Zustand保存选择、展开、筛选及通信草稿/待确认输入。一个私有摘要SSE通知结构和状态变化，逐token输出不刷新整个看板；在途查询期间的新通知会标记下一轮刷新，旧订阅关闭后不再启动查询。唯一选中的活跃详情用500ms Query刷新补文字。主Session SSE也忽略子message.delta，下一次根变化按实际seq区间同步，避免反复重建主转录。

详情消息在SQL中按ordinal范围分页，只读本页正文和关联工具；待审批工具跨页仍可处理，用量读取目标子树的计量字段。Office产物以会话和工具ID精确查询当前分支可见的根/子工具，继承前缀里的任务仍可下载，裁去的委派与跨会话工具拒绝；文件继续受原生工具来源、路径及字节摘要校验约束，不把子转录并入根快照。

实时正文与思考不进入JSONL或SQLite；任务详情合并当前Task的内存partial，并按(snapshotSeq,liveRevision)拒绝旧响应。持久seq只随执行事实增长，完整消息与正常取消/失败结果仍落盘；启动中断全部在途根/子执行，未完成内存片段不恢复，双水位机制由[会话协议](../03_API/model-session.md#事件快照与断线)拥有。

人工问题、计划审核与工具审批继续由原Run及交互ID拥有，统一入口显示来源。表单选择和文字草稿只保存在按原ID隔离的内存Store，关闭详情不丢失，提交成功或注销后清理；没有复制一份可修改的服务端交互状态。

实现接口见[任务协议](../03_API/agents.md)，操作见[子Agent与任务看板](../07_USER_GUIDE/子Agent与任务看板.md)。源码入口为agents/runtime.ts、budget.ts、run-hooks.ts和launch.ts；真实Pi/临时JSONL回归位于agent-runtime/test/agent-runtime.test.ts及agent-collaboration.test.ts，浏览器链路位于tests/e2e/m5.spec.ts。
