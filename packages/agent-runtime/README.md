# Agent Runtime

Node端的模型接入与持久会话运行层，使用固定的Pi core/ai 1.1.0公开接口。HTTP、SQLite、OS凭据和页面由宿主提供；本包不导入Fastify、Electron、React或SQL驱动。源码测试通过paths消费protocol/storage，生产仅导出dist。

`ModelGateway`装配账户实例、模型清单、连接探测与认证。OpenAI（Codex）、Anthropic、Google、DeepSeek、MiniMax、Kimi六个内置Provider按公开factory固定为单例入口，名称、端点和模型目录只读；自定义Provider允许空模型列表，模型Dialog草稿一次提交整个Provider，保留未提交的同ID模型headers/compat，切换协议同步已有模型API。自定义Provider使用Pi的Chat Completions、Responses或Anthropic lazy API。请求HTTP与模型SSE解析由Pi负责。OpenAI兼容Base URL通常含`/v1`；Anthropic SDK会追加`/v1/messages`，通常配置不含`/v1`的服务根地址。HTTPS及显式回环HTTP可用，地址不得含用户信息、query或fragment。

公开providerKind、配置实例ID与credentialRef分别表示协议/厂商、账户配置和秘密存储引用。不同实例使用独立Pi注册ID与凭据；生产默认AuthContext不读取供应商环境变量或其他应用认证文件。requiresApiKey=false跳过保存及环境凭据，通过Pi公开fetch注入剥除SDK认证头；恢复Key要求可继续使用原保存凭据。模型定义显式指定真实modelId、能力、上下文和compat，保存配置不证明远端可用。`testConnection`发起有超时的真实请求，可能产生供应商用量；它返回脱敏结果。

`resolve()`返回Model、绑定的streamFn及必须调用的`release()`。该lease从认证检查前开始，阻止运行期间修改Provider和凭据；调用者在失败或SDK真正结算后释放。本包的SessionRuntime与连接探测负责这些释放，外部调用者须遵守相同规则。

宿主须在独占daemon启动时清理OpenAI/Anthropic SDK的环境认证、租户、Base URL、custom headers和console日志覆盖项；本包不在每个Gateway或请求内修改进程全局环境。Pi的AuthContext隔离不能代替底层SDK的环境策略。keyless最终fetch另外移除认证与OpenAI租户头，显式非秘密模型headers继续传递。应用启动清理的确切变量由daemon的model-environment模块拥有。

认证通过真正的`Models.login/logout`执行。AuthFlow暴露URL、device code、secret/code/select prompt及终态，输入只交给当前prompt，不存入公开DTO。宿主提供稳定profile deviceId。凭据适配将版本化Pi认证对象保存在宿主SecretStore，整段异步refresh在串行modify内进行；已开始的OAuth刷新在调用者取消后仍保存旋转Token。Gateway关闭会中止连接探测与登录，并等待在途凭据操作，不提前宣布退出。

`resolveSessionInput`解析显式选择或持久化全局默认，创建前检查模型、思考等级、启用与认证；失效默认不会改用其他模型。已有会话仍保留自己的选择。

`SessionRuntime`序列化单会话命令；每个Session只有一个活跃Run，不同Session可独立运行。输入、Run配置与模型上下文版本先原子提交，再创建真实Agent请求。SDK事件立即映射为独立公开字段，delta先提交后广播；订阅者不等待SDK idle，真正结算由Run所有者等待。绑定工作区的会话通过`ToolRuntime`提供受策略与单次审批约束的工具循环；没有工作区不自动获得本机目录权限，deferred不会被误报为完整成功。

`RunToolset`在接受Run前由实际`ToolRuntime`能力与工作区选择一次，深拷贝并冻结定义，同时保留TypeBox元数据。接受审计的`tools`、Pi声明、上下文预算及运行时路由共用该集合；来源与稳定定义指纹单独保存为私有`toolSources`，不进入模型工具schema。`ToolRuntime`仅在已接受集合内查找来源和定义，重名与未接受的路由明确拒绝；底层execution及会话执行器对固定内置目录的参数复核继续生效。MCP来源从宿主ExternalTools端口获得有界、可执行的冻结定义与非秘密授权，Run接受审计同时保存工具选择及授权绑定。配置、信任、凭据和SDK连接由daemon/integrations拥有，runtime不直接访问SDK或SQL。

`ToolRuntime`按接受Run时冻结的approvalMode执行：ask逐次询问，auto调用`ModelApprovalReviewer`，full-access自动批准并显式选择macOS无沙箱Shell；旧read-only继续阻止变更。Plan限制在审批前检查，文件工具仍以工作区为根。独立复核使用当前Run的Provider/model、用户请求与冻结规则，没有执行工具、共享主会话或多轮重试；只接受allow/deny/ask结构化结果，模型/认证失败、超预算、无效结果或30秒超时均转人工。停止中止复核并等待SDK结算后释放模型lease。审计请求和决定先持久化，存储失败直接传播，不当成模型失败转人工；公开事件只有工具/模型ID及决定/理由，完整复核请求仅保存在privateData。工具卡最终来源区分user/ai/full-access，先前AI转人工记录仍保留在事件历史。

运行中的follow-up/steer输入先进入持久队列，再交Pi对应队列消费；文本更新与删除重建其内存投影。每个Run只投递当次允许的输入集合，普通发送与编辑不会激活旧暂停队列。取消、失败与重启保留未消费输入，恢复收费请求需显式resume，且原始分支必须与所选分支相符；同一恢复Run只激活相同Provider/model、MCP工具选择和授权绑定的输入。排队时即冻结定义与原始授权，编辑保留接受请求ID；恢复先校验原始授权并重建TypeBox元数据，撤销后重新信任不会复活旧输入。编辑用户消息追加分支与新输入，保留旧分支并排除其后续回复。session.deleted归档会话，保留事件，不是彻底删除私人数据。

输入接受后若Agent初始化或首次队列读取失败，运行层清理订阅与临时所有权、释放模型lease并停用Session；不会遗留可继续工作的假Agent，也不补写假完成。下一次启动将已接受但未结算的事实恢复为interrupted。

RuntimeStore拥有会话日志与投影。公开MessageView与宿主模型codec分离，成功消息保留Provider签名、responseId、system工具声明及工具结果；普通模型消息使用version1 codec；工具结果使用protocol拥有的中立StoredToolResult，runtime再组装Pi消息。不兼容旧开发格式。工具结果按assistant消息锚点进入分支前缀；工具终态和中立结果同批写入，SDK回调不产生第二份结果。已持久完整assistant中未进入执行的call结算为宿主interrupted。MCP调用首次写入前先持久化may_have_started屏障；无法确认结果记unknown、停止Run并保留队列，不自动重试或继续模型请求。恢复只配对日志，不重新连接或执行；未知结果在模型/本地摘要中保留可能已生效的阻塞，不能成为Todo成功证据。工具记录ID按Run、assistant消息ID与SDK调用ID派生，允许网关在不同assistant轮次复用调用ID。持久化失败中止并停用Session，不广播假完成或继续使用未提交状态。

主对话每个助手模型步骤在完成事实中保留供应商token用量与宿主完成时间，字段与缺失语义见[会话协议](../../docs/03_API/model-session.md#事件快照与断线)。工具轮与最终正文使用同一记录入口，独立审批复核和上下文压缩请求不并入这组主对话用量；不从正文估算或从私有codec补造历史统计。

JSONL批记录是会话执行事实来源，完整批次fsync后才更新SQLite投影和发布事件；SQLite继续保存产品配置及可重建查询投影。宿主私有模型输入与公开事件分开保存，HTTP/SSE不暴露privateData。附件内容由宿主独立冻结保存，日志引用不等于附件文件备份。记录格式、回放及索引修复由[storage](../storage/README.md)拥有。

`context`模块在每次Run开始时读取工作区根`AGENTS.md`及显式引用文件祖先目录中的规则，按目录深度及路径确定顺序，不扫描其他目录。已冻结的引用不依赖源文件继续存在；仍存在的祖先目录继续检查，缺失目录不提供规则。规则保存工作区相对来源、原始字节SHA-256与文本；下次Run重新读取，旧快照保持原样。最多16个文件、合计64 KiB，非UTF-8、符号/硬链接、敏感路径、越界及取消均拒绝；读取复用execution的真实路径和受检文件句柄，父目录并发改名仍受底层文件策略与OS隔离限制。项目规则只影响所属目录，不能覆盖应用策略或扩大工具权限。Plan、Todos和历史摘要按明确标识的工作数据加入模型上下文。

`WorkContext`在每次模型请求前重建当前工作状态与冻结规则对应的system内容。估算覆盖system、规则、工具定义、消息、附件、摘要和工作状态；ASCII/Unicode UTF-8启发式及每张图片4096 token均是估算。前次实际请求与后续assistant的input/cacheRead/cacheWrite共同校准下一次总量；摘要或上下文起点改变时基线失效，类别拆分始终保持估算。模型输出空间完整预留，最终仍超限则拒绝请求。

投影仅缩短模型可见副本：长工具结果保留首尾，旧附件正文有界，早先图片转换为附件保留提示；原始消息、完整结果和附件不被改写。达到输入预算80%时，按完整assistant/tool组选择旧前缀，保留约16%的近期内容，支持同一Run内多次自动压缩。当前任务从有效消息中移除后会加入system以保证连续性，已批准计划和任务状态每次请求重新加入。工具调用和结果必须成组，不能把孤立结果交模型。

摘要模型无工具、输出有界、总等待90秒。结构摘要记录目标、约束、决策、观察与完成、待办、阻塞及下一步；模型错误、无效JSON或自身超时使用保守本地摘要，调用方取消和持久化失败继续传播。全部结构字段合计受JSON序列化24000字符和渲染30000字符的预算限制，连续降级不会因局部数组累计变长而中断持久化。每个摘要版本保存父版本、覆盖消息、触发原因、策略及同口径前后token估算。手动压缩由WorkRuntime按持久消息锚点保留最近两轮用户对话；自动压缩由WorkContext按完整工具组保留近期内容，可以在单个长任务中多次进行。两者共用结构化摘要生成与持久化入口。最终真正请求的system和消息先保存为context.prepared。

`WorkInteractions`让ask_user和update_plan工具等待所属Run的用户响应，最长24小时；停止Run会结束等待。ask_user支持多题、选项说明、单选/多选和显式自由输入，答案逐题验证；取消提问返回工具错误，模型可以继续。update_plan提交带唯一ID的结构化步骤并进入只读规划模式；新计划必须保留现有任务关联的步骤，否则在保存与等待审核前拒绝，模型可先更新或清理任务关联。feedback结果返回原Run修订，approve切换执行模式并继续原Run，工具审批仍独立生效。update_plan_steps只修改已批准计划的步骤进度，不修改正文或授予批准。

update_todos保存稳定ID、计划步骤关联和五种任务状态。完成任务需要本Run成功工具的已核验记录ID，或纯文本分析的明确completionNote；伪造、失败或为新增完成项引用其他Run证据被拒绝；既有完成项的未变证据在后续Run和继承分支中保留有效，校验以当前分支可见工具为准。最多一项任务处于进行中。用户手动完成同样需要依据或完成结论。reset_working_state/reset-tasks只清Plan/Todos；reset-context保留模式与Plan/Todos，清规则快照、用量、摘要、问题和未消费队列，并重置有效历史起点，旧历史仍可读。

自动摘要版本是“上下文检查点”：选择旧版本保留当前Session及所有历史，但仅旧摘要和选择后新消息进入模型。restore_context_checkpoint支持指定版本或回退1至10个父版本。search_session_history有界检索当前分支原始消息、工具结果及可见消息绑定的文本附件，包括被模型投影缩短的附件尾部；最多检查10000条消息、2000条工具和128个附件，总扫描100万字符，最多返回20个各2000字符的片段，不跨Session，不代替M6长期记忆。手动checkpoints是“会话快照”：冻结消息前缀和工作状态，恢复时创建新分支，保留旧分支。两者都不回滚文件、命令或外部请求。

本包测试使用真实临时SQLite、真实Pi Agent与受控faux Provider、动态端口HTTP/SSE和显式内存凭据适配器。它们不调用真实供应商账号或用户keyring，不能替代真实API、系统凭据和macOS/Windows发布验收。

```sh
pnpm --filter @my-pi-harness/agent-runtime typecheck
pnpm --filter @my-pi-harness/agent-runtime lint
pnpm --filter @my-pi-harness/agent-runtime test
```

## M4渐进能力

`InputCapabilityResolver`冻结显式MCP、候选目录、发现诊断和Skill正文/授权，排队保留原requestId与授权epoch。`RunCapabilities`将搜索目录与当前可调用集合分开：`tool_search`以服务显示名、原始工具名、说明和参数索引执行BM25检索，可由宿主注入本地向量推理并融合排名；完整工具名优先，语义失败或18秒期限回退词法，Run取消继续传播。搜索默认加载8项、每次最多10项，跳过已加载或已暂存名称，总工具数（含内置）最多64项；现有工具在Run内保持可用。搜索自动暂存命中，`load_tools`仍支持显式名称；两者与`load_skill`都先提交`run.tools_loaded`再更新下一次Pi声明、预算和路由，旧assistant不能调用未曾提供的工具。未命中时返回冻结发现状态，不能据此推断OAuth失效；新发现工具在后续Run进入候选，不在搜索时扩权。

每次Run把启用且未被遮蔽的Skill摘要目录和MCP服务发现状态加入已记录的system上下文，模型按用户意图选择并调用`load_skill`，摘要本身不激活正文。目录与激活正文贯穿每次请求及压缩后的重建；未装配WorkContext时也在实际system消息中提供激活正文。Skill正文每次从冻结记录重建，不被压缩摘要或新磁盘版本替换；目录禁用、插件重装和授权撤销不能复活旧绑定。

用户文字中的独立`$skill-name`明确调用会冻结并激活相应启用Skill，未安装、禁用及被遮蔽的名称不激活。文字调用与picker显式选择分别保存，合并后仍受16项和同一内容/授权版本限制；队列私有`mentionedSkillBindings`保存当次正文，恢复不会改读磁盘新版本，撤销则拒绝恢复并保留队列。活跃Run后续输入中的新调用先随队列接受事实持久化，再通过每次模型请求前的`prepareRequest`屏障提交`run.tools_loaded`，包括直接续接的follow-up；它不创建工具授权或本地目录权限。

后续Run从当前分支有效消息所对应的已提交接受/加载事实继承最近16个Skill冻结正文，自动压缩不清除该来源；编辑分支、上下文重置和检查点选择只使用保留范围。正文不会因picker空选择、模型历史裁剪或磁盘更新而丢失或换成新版。继承前逐项重验当前启停、版本及插件授权；失效项排除，并在已记录system上下文的`unavailablePreviousSkills`中说明，普通聊天继续，显式新选择仍严格校验。队列私有`inheritedSkillBindings`保留原版本，恢复可排除已失效的继承；不会继承`request_skill_tools`授权或MCP可执行集合。动态激活Skill同时暂存其声明且属于冻结工作区目录的Office工具，下一请求经过相同持久屏障获得schema；没有工作区不提供Office文件工具，任意MCP名字不随Skill声明加载。

`request_skill_tools`始终要求明确用户批准。服务插件通过冻结Skill中的`gatewayUrl`提供只读HTTP入口，模型使用会话级`web_fetch`访问允许的路径，不要求工作区或授予文件/Shell能力；公网与网关访问继续执行现有网络校验、Plan与只读限制和单次审批。网关地址随接受输入与`context.prepared`保存，私有访问能力只在宿主执行请求时添加，不进入模型或会话日志。当前工具集合不提供固定服务操作目录、账户选择或Run级服务grant。MCP写操作继续使用实际加载的工具、独立信任与当前审批策略。接口与事实见[运行时能力协议](../../docs/03_API/capability-runtime.md)。
