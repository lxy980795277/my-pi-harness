# DOCX 渲染与验收

`office_inspect` 的 ZIP/XML 与关系检查只证明可读结构，不证明页数、分页和文字排版。先检查产物返回的 `validation` 与 `notVerified`，再执行所需的页面验证。

1. 调用 `office_render`，例如 `{"source":"report.docx","output":"report-preview.pdf"}`。输出必须是新 PDF，已有文件不覆盖。该转换依赖部署者已安装的 LibreOffice；缺少依赖必须报告未渲染。
2. 用 `office_inspect` 读取预览 PDF 的总页数。再分批调用 `pdf_read_pages`，每次指定 1–4 页。对新建文档检查所有页；对局部编辑至少检查受影响页和前后衔接页，明确实际覆盖范围。
3. 查看页图中的中文与特殊符号、标题层次、页眉页脚、页码、表格跨页、图片比例、留白、空白页、孤立标题和截断。若采用模板，对照源文件的渲染页图核对用户要求保留的布局。
4. 发现问题后调整明确的版式参数，生成新的 DOCX/PDF 并重新检查。不能用旧预览证明新文件已经通过。
5. 再读最终 DOCX，核对实际正文及原生审阅对象。更新目录、引用和页码可能需要用户在 Office 中执行字段更新；没有执行时应写明。

交付说明只包含已观察到的检查结果：例如“已检查 XML 关系及第 1–3 页图”。缺少 LibreOffice、模型不支持图像或未检查全部页时，保留相应未验证项。下载按钮提供的是实际生成的文件，不代替 Word/LibreOffice 视觉验收。
